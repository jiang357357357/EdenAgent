# Eden Agent TypeScript 宿主与 pi 实现方案

日期：2026-09-09。状态：实施中，阶段证据以《Eden Agent TS 迁移实施跟踪》为准。用户最新修订：先完成全部计划功能实现，再集中逐步测试与修正；本方案各阶段描述保留目标与最终验收标准，不再要求每个小实现步骤停下来测试。

## 1. 决策与目标

生产宿主改为独立 Node.js / TypeScript 服务，通过 pi 公共 SDK 复用 Agent 循环、模型接入、会话和扩展机制。停止维护独立 Rust AgentCore；Eden 拥有业务编排、权限、数据恢复和插件生命周期。

核心产品目标：智能体能发现能力缺口，在自身世界内创建插件草稿、编写 TS、运行验证、修复失败、请求必要权限、启用固定版本、调用并维护插件。已授权范围内的动作可以自动完成；代码生成能力不授予修改宿主授权规则的能力。

继续保留：双世界独立进程与状态、React/Vite 客户端、Electron 桌面壳、流式对话、角色与记忆、自唤醒、语音、工作区、审批、作业、子智能体、Mon 集成、MCP 与官方连接器。

不以迁移名义删除现有业务。MVP 只是实施顺序；全部能力迁移和验收完成前，不称为完整替代。

## 2. 已完成归档与当前断点

旧代码位于 `Archive/2026-09-09-rust-runtime/{AgentCore,Server}`。Server 保持原 Git 子模块，旧实现不再占用根 `Server/`。

尚未修复的入口包括根 Cargo workspace、`generate:rpc`、`typecheck`、connector 构建脚本、CI、Electron 的 Rust Server 监管器及部分资源路径。归档后这些入口不能代表可运行产品。`Data/` 未修改，不允许新代码原地升级旧数据库。

归档说明及提交基线见 `Archive/2026-09-09-rust-runtime/README.md`。前端现有自唤醒修改须保留，迁移时对最终工作树做适配，不恢复旧版本覆盖它们。

## 3. pi 选型和依赖边界

本地研究基线：`文档/参考/pi` 提交 `7df73a00c6cf85c000bf1ce1594c9284067a92f0`，相关包版本标为 `0.82.0`。这是源码基线，不代表已核实同版本 npm 制品包含完全相同接口。

优先使用 `@earendil-works/pi-coding-agent` 的公共 SDK 创建会话，并使用配套 `pi-agent-core` / `pi-ai`。不启动 pi CLI，不采用实验性的 `pi-server` 作为 Eden Server，不导入 pi 私有源码路径。参考目录仅供阅读，不作为生产运行时依赖。

第一阶段必须验证：模型自定义路由、Mon 会话/角色模型绑定、自定义 ResourceLoader、关闭默认工具与资源发现、扩展绑定/重载、会话重建、流式取消、事件监听等待语义和压缩持久化。

如果高层 SDK 的公共接口不能满足持久化屏障或多角色会话要求，允许在同一 `runtime-pi` 包内改用 pi 的公开 Agent/Harness API 加薄适配。必须记录缺口和回放测试，禁止默默 fork SDK 或重新实现完整循环。

固定核验过的确切包版本和锁文件；若该源码版本未发布，构建带来源提交记录的固定制品。安装阶段禁用自动生命周期脚本；确需原生构建的依赖单独列出。上游升级通过契约回放测试后合入。

```text

  package.json
  src/main.ts                   # 装配与进程生命周期
  src/transport/                # RPC、Blob、STT、内部桥接
  src/services/                 # 会话、角色、记忆、自唤醒、作业、Mon
  src/workers/                  # 后台任务入口
  tests/                        # 组合级契约与恢复测试
packages/
  api/                          # Eden wire schema、类型、生成客户端
  runtime-pi/                   # 唯一允许直接使用 pi 运行时接口的适配层
  store/                        # Eden SQLite、迁移、事件投影、outbox
  permissions/                  # 授权、审批、操作日志
  plugin-sdk/                   # 模型生成插件可用的接口与模板
  plugin-host/                  # 草稿、构建、验证、安装、生命周期
  execution/                    # 沙箱、进程树、终端与文件能力
  integrations/                 # MCP、连接器协议、Mon 外部服务适配

Connectors/                     # 现有官方 worker 按协议继续接入
frontend/                       # 保留现有子模块
Archive/2026-09-09-rust-runtime/
```

首次搭骨架只创建实际需要的包，服务先按目录分模块；不为每个业务功能创建独立 npm 包。

Electron 分别启动两个 Node Server：mon `127.0.0.1:40092`、local `127.0.0.1:40093`，Web 仍为 `40091`。独立 Node 运行时随发行包提供，避免使用用户 PATH 中不确定的 Node；精确版本在制品验证时固定。后端不运行在 Electron 主进程或渲染进程中。

mon/local 分别生成能力令牌、持有数据库和模型配置。构造子进程环境使用允许列表，local 凭据不进入 mon，Mon 凭据不进入 local。独立进程并不提供同 OS 账户下的文件系统隔离；插件沙箱另行实施。

## 5. 宿主和 pi 的职责契约

pi 负责模型调用循环、消息转换、工具调度、上下文压缩和其内部会话语义。Eden 负责 admission、输入排队、每会话单写者、会话参与者、角色编排、外部副作用、审批、任务调度、恢复和客户端状态。

`runtime-pi` 对外只暴露 Eden 类型：创建/恢复会话、提交输入、steer、follow-up、abort、等待静止、压缩、获取快照、订阅事件、发布工具版本、关闭。禁止在前端、数据库业务表或插件 SDK 中传播 pi 内部类型。

每会话只能有一个活动回合；同会话输入由持久队列领取，不以 HTTP 请求生命周期作为任务生命周期。取消必须传至模型、工具和子进程，并等待执行结束；退出时停止领取新任务，排空持久化，超时终止仍存活的进程树。

角色导演先产生确定的 actor 执行计划，再由同一会话协调器顺序提交 actor 输出；不得让多个 pi 实例同时修改共享会话存储。actor 模型路由、共享历史与压缩后的说话者信息必须做专项验证。

保留模型调用上下文清理、长工具结果裁剪、工具参数验证、缓存与用量统计等行为；逐项比较后选择 pi 等价机制或 Eden 适配，不逐行翻译旧 AgentCore。

## 6. 数据所有权、持久化与恢复

### 6.1 单一持久事实来源

新数据放在 `Data/realms/<origin>/v2/`，旧数据保持只读。Eden SQLite 是生产接受输入、回合状态、模型请求快照、已完成消息/工具结果、审批、作业、插件版本和客户端事件的持久事实来源。

pi 会话在第一版使用内存 SessionManager；需要恢复的 pi 会话条目、分支、模型变更和压缩条目由适配层以有版本的 checkpoint 写入同一 Eden 数据库。pi JSONL 默认目录不参与生产写入。内存 SessionManager 不是恢复方案：其导出、重建和恢复屏障必须先在 P0 证明可行。

若公共 SDK 不能完整导出/恢复所需状态，切换公开 Harness 存储接口或提出存储方案修订；不得依赖私有字段，也不得悄悄退化为只保存聊天文本。pi 的 SQLite 包不直接读取旧 Eden schema。

建议表域：`realm_meta`、`sessions`、`inputs`、`turns`、`events`、`runtime_checkpoints`、`model_requests`、`tool_operations`、`permissions`、`questions`、`jobs`、`outbox`、`plugin_versions`、`plugin_activations`、`plugin_grants`，及角色/记忆/语音业务表。

### 6.2 提交顺序

1. 事务写入输入及幂等键后返回 accepted。
2. 领取输入并记录回合。每个模型请求记录实际模型配置、完整组装上下文或可重建引用、工具 schema 和插件 revision。
3. 产生 Eden 事件与状态变更，在同一事务写入相应 checkpoint / 操作状态。
4. 事务提交后才广播事件；以每会话单调 seq 对外排序。
5. 副作用执行前持久化 operation intent；结束后保存结果与状态。

第一版保留已发布流式增量的持久化语义。若需要批量提交，可批量持久化后逐项广播；不得在未变更协议契约时先广播临时增量。压缩、模型切换、扩展重载都必须与 checkpoint 对齐。

本地 pi 的低层事件迭代器不等待异步消费者，高层 Agent 的监听器有等待语义，AgentSession 的外部订阅又有不同接口。必须通过故障注入验证实际屏障；仅在事件回调里启动一个异步写入不足以满足要求。

### 6.3 崩溃处理

恢复时读取已提交 checkpoint 和后续持久事件；未完成回合标记 interrupted。已领取但未执行的输入可重排；状态不明的外部副作用标记 unknown，不自动重试。只对有提供方幂等键或可核对结果的操作安全重试。

客户端按 seq 去重，缺口触发快照与事件补齐；补齐历史不能重新触发语音播放、截图或外发。数据库首次绑定 origin，正常启动不可跨世界改绑。

## 7. 智能体自编写插件

### 7.1 两种执行信任

宿主维护的受信扩展可以作为 pi TS Extension 运行，用于工具代理、角色策略和生命周期协调。

智能体生成插件默认是独立沙箱进程中的 TS 程序，通过 Eden Plugin SDK 调用宿主能力。不能直接作为任意 Node 模块导入持有凭据的 Server。`vm`、worker_threads、TypeScript 类型和独立进程都不单独构成权限隔离。

首版开放工具、工作流和声明式事件订阅；不开放任意宿主回调、任意 HTML/JS UI 或修改权限策略。后续可增加有输入输出 schema 的记忆/上下文变换能力，由受信适配器验证输出、限制大小并记录到模型请求。

### 7.2 生命周期与制品

```text
draft -> validating -> tested -> installed -> awaiting_grant -> active
                    -> failed                         active -> disabled
新 revision 重走验证；回滚是激活先前已安装 revision。
```

草稿可变，安装制品不可变。revision 覆盖源码、manifest、依赖锁文件与构建产物；测试报告必须绑定确切 revision 和运行环境。测试后修改任何内容都会使报告失效。

manifest 必须包含 schemaVersion、id、version、entry、运行时约束、工具 schema、事件订阅、权限声明、依赖锁摘要。限制文件数量、大小、路径、符号链接及解包目标；保留旧插件格式的只读导入适配，不能直接改变其含义。

本地生成来源记录 creator session/turn、来源类型、revision、验证记录和授权主体。测试通过不等于受信签名；生成器不能持有市场签名私钥或修改信任库。

### 7.3 模型工具与权限

以下为拟新增接口，不是当前已有 API：

| 工具 | 作用 |
| --- | --- |
| `plugin_create` | 从固定模板创建世界内草稿 |
| `plugin_validate` | 校验 manifest、schema、路径、依赖策略 |
| `plugin_test` | 运行隔离测试并返回结构化诊断 |
| `plugin_inspect` | 返回内容差异、权限差异、验证结果 |
| `plugin_install` | 将验证过的 revision 安装为不可变制品 |
| `plugin_activate` | 请求在宿主授权范围内启用 revision |
| `plugin_disable` / `plugin_rollback` | 停用或切换到明确旧 revision |
| `plugin_list` / `plugin_logs` | 发现插件与读取脱敏诊断 |

编辑草稿使用现有工作区写入工具，但只能访问被授予的草稿路径。模型不获得 `permissions.set`、任意 trust key 写入或宿主执行模式切换接口。

用户可预授权“在特定目录只读、无网络、限制资源的本地插件”等策略。每个新 revision 都重新评估策略并生成独立授权记录；当前 revision 专属审批不自动继承。超出预授权范围时，将具体差异提交审批。开发、测试、安装和启用分别校验，拒绝后不影响其他独立工作。

### 7.4 插件运行和升级

Plugin Host 清空继承环境，不下发 Server token、模型 key 或数据库路径；以能力代理提供文件、HTTP、存储、事件和工具调用。所有代理请求在宿主重新检查 origin、plugin revision、能力和资源范围。默认禁止直接外网与宿主文件访问。

构建可执行不可信代码，也必须隔离。依赖下载由受控构建器按锁文件完成，测试不获取真实凭据；CPU、内存、墙钟时间、输出和子进程数有限额。没有可用 OS 沙箱时禁用生成插件的执行，不自动降级。Windows 无可用后端时明确报告能力缺失，直到隔离后端通过验收。

插件与 Server 的协议包含版本协商、tools/list、tools/call、cancel、health、drain、shutdown 和带 requestId 的响应；工具定义由宿主校验后代理给 pi。MCP 插件可复用现有标准通道，Eden SDK 能力代理另行定义版本契约。

一次模型请求绑定工具集合及 revision。正常升级等待受影响调用结束，在请求边界发布新集合；旧调用不被新实现替换。安全撤销立即阻止新调用并取消旧执行。首次启用与升级均先运行健康检查，失败保留旧活动指针并记录原因。

回滚代码不会撤销已发送邮件或恢复业务数据。插件存储迁移需声明版本、备份和兼容性；不兼容迁移失败时保持禁用，不谎报回滚成功。

### 7.5 自唤醒与循环约束

使用场景由宿主策略选择工具，不能沿用只有静态名称的白名单来排除所有新插件，也不能将插件声明直接视为授权。事件 Hook 进入持久作业，携带 causationId、origin、plugin revision；设事件去重、递归深度、频率和预算，防止插件自触发无限安装/执行。

## 8. API、前端与桌面迁移

`packages/api` 中的运行时 schema 为新协议事实来源，同时生成 TypeScript 类型和 RPC 客户端。边界解析、磁盘数据、插件响应都做校验；同进程业务函数使用静态类型。错误码、可选字段、seq 表示、时间格式保持显式。

从旧 Rust API 和现有生成客户端生成逐方法清单，第一轮保持现有方法及结果兼容。无法兼容时发布协议版本并同时迁移消费者，不保留永久双实现。传输仍有 `/rpc`、`/blobs`、`/healthz`、`/readyz`、实时 STT 及经过认证的自唤醒内部接口；metrics 权限按旧实现核对。

Web 的改动集中在生成客户端、事件映射及新插件开发页面。插件页面展示草稿、源码差异、测试诊断、权限请求、活动 revision、日志和回滚。pi TUI 组件不直接进入 React；问答和确认映射为 Eden 持久交互对象。

Electron 将 rust-server 监管器替换为通用 Node Server 监管器，保留 readiness、重启退避、进程树退出和令牌注入。发行包显式包含 Node、Server 构建产物、第一方扩展、沙箱 helper 和连接器资源。

## 10. 数据迁移与切换

1. 停止旧 Server 后用 SQLite backup 或一致性快照备份每个世界，记录数据库和 Blob 清单；不在运行中直接复制 db/WAL 文件组合。
2. 在 v2 新目录执行幂等迁移，保留旧 origin、业务 ID 和来源记录；必要 ID 转换生成映射表。
3. 迁移会话、消息、工具结果、附件、角色、记忆、memo、自唤醒日记、语音配置、作业和插件元数据。旧审批过期，旧运行中任务 interrupted，外部副作用 unknown 待核对。
4. 压缩记录若无法无损映射，保留原文和来源并标明导入上下文策略，不丢弃历史伪装成原生 checkpoint。不可识别事件保存原始载荷供只读查看。
5. 比较逐表数量、ID 映射、附件摘要、会话抽样回放及失败项；失败项有报告，不静默跳过。
6. 新运行时先以禁用外部副作用模式验收，切换后只允许一个生产运行时领取任务。
7. 回退时停止新服务、保留其数据、重新指向旧备份；切换后新增业务不会自动出现在旧系统，需导出/补偿策略，禁止宣称无损逆向迁移。

## 11. 分阶段实施与完成标准

### P0：SDK 契约验证与清单

核验确切 pi 制品；建立全部旧 RPC、工具、事件、表域和业务功能清单。实现最小 runtime-pi 探针：自定义模型、受控工具、steering、取消、压缩、checkpoint 重建、扩展重载及多个隔离会话。

完成标准：录制模型响应回放通过；SQLite 故障时无后续外部副作用；SDK 无法满足的契约有明确替代决策。未过关不开始批量迁移业务。

### P1：可启动 TS 双世界底座

创建 TS workspace、API、存储、Node 入口、令牌鉴权、两套状态目录、健康检查和关闭流程。调整 npm 开发命令及 Electron 监管器；Rust 归档退出默认 CI，剩余原生代码有独立检查入口。

完成标准：干净检出可构建；两个独立 Node Server 与现有 Web 建立连接；错世界 token、数据库、模型配置均被拒绝或隔离。

### P2：对话、工作区与恢复

接入 pi、模型配置和 Mon 路由、消息与事件、工具执行、审批、问答、终端、Blob、上下文压缩与恢复。

完成标准：真实 UI 完成对话与工具审批；录制回放、事件断线补齐、取消、磁盘失败和进程重启测试通过。此阶段不将原始 pi 内置工具直接暴露为绕过权限的第二入口。

### P3：自编写插件闭环

交付 Plugin SDK、模板、草稿目录、隔离构建测试器、模型管理工具、版本准入、升级回滚和 Web 展示。

完成标准：用户要求“统计指定目录内 Markdown 字数”，智能体自行创建新工具插件、修复测试、在预授权只读范围启用并调用；重启后仍可用。越界路径和未授权外网被拒绝；失败升级不替换旧版本。

### P4：Eden 完整业务

迁移角色导演、记忆、自唤醒、桌宠事件、语音、多智能体、作业、Mon 同步、市场、MCP 和四类官方连接器。

完成标准：功能清单逐项具有代码位置、回放测试和必要真实验收证据；不存在“暂不支持”却标记完成的项目。真实外部动作只在专用测试资源和对应授权下验收。

### P5：迁移、发行与收尾

实现可重复数据迁移、平台打包、升级/回退演练、文档与 CI。清理旧生产路径、更新 AGENTS/README，保留归档及来源说明。

完成标准：历史数据迁移报告合格；Linux/Windows 所声明功能均经过发行包验证；新运行时无归档源码依赖；未达标平台能力明确标记不可用。

## 12. 测试、观测和验收矩阵

| 类别 | 必测行为 |
| --- | --- |
| pi 适配 | 流式、取消、工具次序、steering/follow-up、模型切换、压缩与重建 |
| 存储 | 提交前不广播、断电恢复、重复输入幂等、磁盘满、事件缺口、未知副作用 |
| 双世界 | token/origin 错配、环境凭据清理、数据库绑定、子进程目录 |
| 插件 | 测试与 revision 一致、非法 schema、路径逃逸、依赖变化、超时/失控进程、升级并发 |
| 权限 | 预授权命中、新增能力审批、拒绝生效、撤销、无沙箱时拒绝执行 |
| 生命周期 | 扩展重载资源释放、关闭排空、作业重复领取、Hook 自触发限制 |
| 业务 | 角色归属、记忆作用域、自唤醒场景工具、多智能体邮箱、语音不重复播放 |
| 发行 | 无开发工具环境启动、原生 helper、资源路径、更新和回退 |

结构化日志携带 origin/session/turn/operation/plugin/revision，凭据脱敏。记录模型首 token 延迟、事件提交延迟、插件启动/执行耗时、队列深度、恢复耗时和资源用量。使用同一录制会话、同一硬件建立 Rust 基线与 TS 对照，再确定阈值，不预先承诺性能提升。

CI：类型检查、边界/schema 检查、单元与录制回放、生成客户端差异、集成故障测试、平台打包冒烟。真实模型和外部服务验收单独触发，不用真实 API 支撑普通单元测试。

## 13. 首个实施批次

先做 P0 和 P1 必需的最小骨架：固定 pi 依赖、完成 runtime-pi 契约探针、建立 API 与新数据库、跑通无副作用聊天及重启恢复。暂不批量搬运业务，更不直接让新服务打开旧数据库。

本方案完成的是设计，不等同于迁移实现。只有 P0 至 P5 的完成标准全部具备证据，才移除旧生产入口并宣布替代完成。
