# 运行时进程资源与故障诊断

2026-11-07，针对《EDEN_运行时中断错误报告_2026-11-06》确认的源码问题实施修复。客户原始安装目录不在本机，本轮验证使用隔离数据库、录制模型 HTTP 服务和真实 Node 子进程；不能将验证结果等同于客户全部 134 退出均已确认为 OOM。

## 资源预算

`packages/runtime-pi/src/process-policy.ts` 统一解析实际 fork 参数，覆盖单角色、多角色、压缩、标题、导演及记忆提取使用的隔离运行时。

| 设置 | 默认 | 有效范围 |
| --- | --- | --- |
| `EDEN_AGENT_RUNTIME_HEAP_MB` | 2048 | 64–16384 整数 |
| `EDEN_AGENT_RUNTIME_ABORT_TIMEOUT_MS` | 10000 | 50–120000 整数 |

值在创建子进程前验证；空值、非整数和越界值明确报错。测试或嵌入方可以使用公开 `ProcessPolicy.maxOldSpaceMb`／`abortTimeoutMs` 覆盖环境值。生产默认不需要配置。

开发启动的临时配置示例：

```powershell
$env:EDEN_AGENT_RUNTIME_HEAP_MB = '2048'
$env:EDEN_AGENT_RUNTIME_ABORT_TIMEOUT_MS = '10000'
npm run dev
```

参数限制 V8 老生代，既不预分配 2 GiB，也不限制整个进程 RSS。并行进程分别拥有预算；保留已有启动和心跳截止机制，没有引入 OS 沙箱或改变工具权限。图片 base64 校验使用字符范围、长度与填充位验证规范性，不再仅为校验而分配整份解码 Buffer 及再编码字符串；8 张及合计 32 MiB 的限制保持。

## 诊断输出

子进程 stdout、stderr 改为 pipe 并持续消费。每路仅保留末尾 16384 个字符，同时累计实际读取字节数；故障结束时写入宿主原有 JSONL 日志，继续经过原日志限长、脱敏和轮换。不会逐块落盘无限输出，也不记录提示词、工具参数或附件载荷。

`runtime.process.started` 记录 PID 与实际堆预算；心跳带回 RSS、heapUsed、heapTotal、external、arrayBuffers 和实际 V8 heapLimit。最终 `runtime.process.failed`／`runtime.process.cancelled`／`runtime.process.disposed` 包含退出码、信号、存活时长、距最后活动时间、最后方法／工具标识和有界输出尾部。正常会话、多角色压缩及辅助模型请求均接入同一个宿主日志适配器；清理等待 close，确保读取剩余错误输出。

只有错误输出包含堆耗尽证据时才分类为 `out_of_memory`，退出码 134 单独不足以作此判断。监视超时为 `unresponsive`，启动失败为 `startup`，其他异常退出为 `crashed`。保留 typed `RuntimeProcessError` 供调用方区分。

## 取消与恢复

取消先终止宿主工具信号并请求 SDK 停止，默认允许 10 秒完成；不合作的运行时经过有限 IPC 排空宽限后强制结束，使用 `RuntimeCancellationError` 标识。显式用户取消记录为输入／回合 `cancelled`，清除故障 error 字段，发布 `input.cancelled`；服务器关闭不冒充用户取消，真正的存储失败仍保留故障原因和恢复边界。

已持久化为 completed 的工具回执保持不变；仍为 running 的操作转为 unknown。崩溃后的后续排队输入保持 held，不会自动重放未知副作用。用户提交下一条新输入时创建新运行时并读取已保存的会话检查点，无须重启整个账号服务。
