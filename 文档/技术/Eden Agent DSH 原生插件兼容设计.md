# Eden Agent DSH 原生插件兼容设计

状态：2026-11-05 设计草案；尚未实现、测试或宣称兼容。范围是为 Eden 增加按 DeepSeek Harness（DSH）机制加载原生插件的能力，不改变 Eden 既有业务事实所有权。实现以本文件为目标，实际支持范围由逐项验收结果决定。

同日按用户要求进行了现有入口实测：原始 dsh-purge 包在 Eden `plugin.inspect` 因缺少 Eden 清单被拒绝，未进入安装；临时空 Eden 包可通过同一预览、安装和启用接口。此结果仅确认当前不支持原生 DSH 包，不代表本设计已实现。Node 版本、隔离数据和验证边界见 [实施跟踪](Eden%20Agent%20TS%20迁移实施跟踪.md)。

## 1. 目标和参照

目标是让针对指定 DSH 版本编写的插件，能够以原来的 npm 包、`dsh.bundle.patch`、Cordis 插件入口和配置在 Eden 中装载；已经接通的 DSH 服务与事件按其原契约工作，插件无需改写为 Eden 单文件工具。目标不是把 DSH 整个应用嵌入并运行第二套 Agent：会话、消息、模型、工作区、账号与权限仍由 Eden 负责。

参照固定为本地 `文档/参考/deepseek-harness` 提交 `687f282e8625c6b8d11ff58211a90524be2e4317`，仓库版本 `0.2.1-rc.2`，内置 `@deepseek-ai/cordis` 为 `4.0.5`。具体事件、包导出和 peer dependency 均以该提交为准；不把另一个 DSH 版本、`dsh-purge` 的目标声明或升级后的行为混为此基线。参考代码只是设计依据，不能把 `文档/参考` 当作生产运行时依赖。

DSH 的关键契约是 Cordis 上下文、`inject` 依赖就绪、服务提供与插件树、`apply`/Service 挂载、effect/disposer、事件及其 `emit`、`parallel`、`serial`、`bail`、`waterfall` 分发语义；profile 叠加 bundle、profile patch、home patch 和单次启动 patch。参见 [Cordis 入门](../参考/deepseek-harness/docs/cordis-primer.zh.md)、[DSH 架构](../参考/deepseek-harness/docs/architecture.zh.md) 和 [工具契约](../参考/deepseek-harness/docs/cookbook/adding-a-tool.zh.md)。

## 2. 架构选择和隔离事实

每个已启用 DSH profile 的 Eden 世界／账号运行一个受监管的 Cordis 宿主进程，内部使用与基线匹配的真实 Cordis 和经过依赖闭包验证的 DSH 公开包。插件在该进程中按 DSH 原生方式挂载；Eden Server 通过有版本的 IPC 桥接已经实现的服务、工具和事件。不能仅做 `apply()` 外形相同的假 `ctx`，也不把 Eden Server 的内部对象、SQLite 句柄或 pi 类型直接传给插件。

```text
Eden Web / Desktop ──现有 RPC──> Eden Server（每世界／账号）
                                  ├─ 会话、持久事件、审批、模型、工作区
                                  └─ DSH profile 管理与 IPC 桥
                                            │
                              受监管的 Cordis 插件宿主进程
                              ├─ DSH loader / profile / 插件树
                              ├─ DSH tools / prompt 等已接入服务
                              └─ 原始插件及其依赖
```

进程边界用于故障隔离、重启和生命周期管理，**不是 OS 沙箱**。按当前项目指示，插件、安装依赖及构建脚本使用当前系统账户权限。插件可直接调用 Node 文件、网络和子进程 API，不保证受 `workspaceRoot`、声明权限、世界或账号的 OS 边界限制；IPC 能限制的是经桥接进入 Eden 的能力。使用精简环境变量和分别管理的凭据不构成对本机文件或进程的安全隔离。不得提供可重新启用沙箱的开关；若未来恢复沙箱，先经开发者审阅。

使用真实 Cordis 不等于已实现所有 DSH 服务。DSH 的回调、可变对象、同步 guard、service 引用和 waterfall `next()` 不能被普通 JSON IPC 自动透明转发。应把同一条同步调用链及其注册回调保留在 Cordis 宿主内部，通过明确的异步事务边界与 Eden 交换序列化快照；跨进程无法维持原语义的扩展点标记为不支持，不伪造成功。优先验证上游包的依赖闭包及这些边界，若某条调用链要求持有真实 Eden 同进程对象，须调整该边界或明确不支持，不能只增加类型声明就声称兼容。

## 3. 状态所有者与版本

| 状态 | 所有者和约束 |
| --- | --- |
| 世界和账号 | 沿用现有 runtime scope；Mon 每账号独立 profile、安装状态和进程，Local 独立。进程崩溃不串号；这不构成 OS 权限隔离。 |
| 插件制品 | 扩展现有插件市场仓库管理来源、内容快照、版本、信任与选择；增加 DSH 来源类型和构建元数据。既有单文件插件、组件包、连接器和 MCP 继续原样可用，不自动迁移或删除。 |
| Profile | 每账号保存 bundle 有序列表、profile patch、配置修订与启用意图；用户范围 home patch 与启动 overlay 必须明确归属，不能隐式读取其他世界／账号配置。profile 是持久事实，Cordis 进程中的树是可重建的运行状态。 |
| 调用与事件 | Eden 仍负责输入队列、审批、工具操作、模型请求和事件的持久化；先提交再广播。Cordis 不独立创建与 Eden 冲突的业务真相。 |
| 版本 | 固定 DSH ABI 基线、Cordis 和实际依赖锁；每次安装保存完整已解析依赖、锁文件、运行时版本及内容摘要。升级基线须重新执行兼容矩阵，不继承旧版通过结论。 |

状态分为 `installed`、`selected`、`starting`、`active`、`degraded`、`failed`、`stopping` 和 `disabled`；保存的选择不代表插件已运行。记录每个 bundle、条目的实际激活状态、缺失依赖、profile 修订、错误和需要重启的原因。恢复时先加载已批准快照，再按原启用意图重建；未知结果的外部副作用不自动重放。

## 4. 包、profile 和装配

1. **发现与预览**：支持本地路径和后续市场／npm 源。读取 `package.json`、`exports`、`dsh.bundle.patch`、客户端声明、依赖、构建脚本和目标版本，列出将安装／运行的条目及作用域。预览时不 import 插件、不执行生命周期脚本；不把 package metadata 的声明当作实际可用的服务清单。
2. **锁定与安装**：对确切包和依赖树做内容寻址快照，记录来源、依赖锁与完整性。远程索引／签名按来源实际能力区分：签名或校验成功只证明来源／内容，不能推断行为安全；本地无签名包明确标识。依赖解析、下载、脚本执行均走现有对应授权，构建脚本单独列明并批准。禁止插件替用户批准或把检查包等同批准执行。
3. **配置合并**：按基线 DSH 的 bundle → profile → home → 单次 overlay 顺序解析，保留按 ID 覆盖、插入、禁用及 `config.plugins` 嵌套语义。配置中存在 `!!js` 等表达式时，不能在预览中执行；哪些表达式及可用绑定可以准确支持，须与该版本 include/loader 对照实现并标记版本。尚不支持的表达式、缺失服务、循环依赖或无法解析的 patch 明确报错，不静默忽略或把无法加载的条目标记为 active。
4. **挂载与卸载**：Cordis 宿主负责服务等待、插件 fiber、注册和 disposer；把稳定插件身份、版本和激活代次与桥接注册关联。禁用、切换版本及关闭时先阻止新调用，再取消或等待既有调用、撤销贡献并释放资源；未确认的进程退出保持失败诊断。
5. **更新和回滚**：更新生成新快照并重新审批；选择旧的已安装快照实现回滚。激活失败保留已选与实际运行的区别，不覆盖旧制品；在可恢复前提下撤销新贡献，报告不确定的外部副作用。配置热重载和模块热替换分别报告，不承诺所有模块都能热替换。

DSH 的 pnpm 依赖、peer dependency 和多导出包并不等同 Eden 当前组件包。实现时应先验证可发行依赖闭包与固定版本解析；如需要打包上游 MIT 代码，保留各项目原始许可证和版权声明，并更新第三方清单。不得假设 package manager 生命周期脚本安全，也不得从用户真实数据目录构建测试夹具。

## 5. 桥接的具体契约

所有跨进程请求携带协议版本、世界／账号作用域、profile 修订、插件 ID／revision、激活代次和有界请求标识；模型只接收业务需要的内容，内部追踪值留在宿主。序列化只用于桥接边界，不把 Cordis 回调当作 JSON 值传输。请求有取消与期限，断线后拒绝新调用并清除对应工具目录；响应丢失后，已经派发的副作用结果记为 `unknown`，禁止自动重试。

建议的实现归属：`packages/api` 定义公开管理 RPC 与内部桥接的可序列化契约；`packages/plugin-host` 管理 Cordis 进程、协议、装配和版本化服务桥，不依赖 Server；`Server/src/modules/plugin-market` 继续拥有包快照、来源、安装／选择和 profile 持久化，新增专职 profile repository；Server 内独立的 DSH 桥接模块组合会话、权限、工具和提示服务；`runtime-pi` 只接收既有运行时抽象与结构化提示，不导入 Cordis。前端管理页展示来源、配置、审批、兼容矩阵及实际状态；Client 插件执行器属于独立后续模块，不混入声明式卡片解析。

IPC 至少区分 `initialize`／`ready`、`profile.apply`／`profile.status`、`catalog.replace`、`tool.invoke`／`tool.cancel`、`prompt.assemble`、`dispose` 和心跳。Server 发起的请求使用关联号；Cordis 发起的能力调用必须附带由 Server 创建的有效作用域，不能接受插件自行指定其他账号。`catalog.replace` 带进程实例及单调代次，旧实例迟到消息不能复活已撤销工具。协议类型、消息上限、回调身份、超时和错误码在实现前单独确定并覆盖双向重入；这些名称是设计草案，不是已存在的 RPC。

持久化设计在既有插件包仓库旁增设以世界／账号为作用域的 profile、profile 版本／配置、bundle 选择及运行代次记录；不将运行进程 PID、临时回调或活跃调用作为可恢复业务真相。安装快照与 profile 选择应各自事务提交；先记录期望配置，再启动候选进程，只有候选达到约定 ready 状态才切换实际激活代次。失败时保留历史选择、候选错误和旧运行代次，避免数据库写入成功却误报新版本已生效。表结构、迁移编号和旧库的具体回退方法在实现时依当前 schema 制定；不能将用户已有包自动升级为 DSH 包。

| DSH 入口 | Eden 接法与完成条件 |
| --- | --- |
| `ctx.tools.register`、工具输出及 disposer | Cordis 进程持有真实注册和回调；向 Eden 公布经过校验的工具描述快照、稳定名称映射与激活代次。Eden 接收调用后检查作用域、版本、权限和预算，再经 IPC 调用；插件停用时撤销贡献。DSH 参数 DSL、规范输出、render 及错误语义逐项映射，无法无损转换的 schema 明确拒绝。 |
| `tools/pre-execute`、guard、`tools/execute`、`tools/post-execute`、`tools/result` | 在 Cordis 进程内按上游规定顺序执行事件链，保留同步 guard、waterfall `next` 和结果观察语义。Eden 的账号／渠道／子任务策略、审批及审计属于桥外最终约束，插件的 allow 不能覆盖 Eden 拒绝；不能在桥接中让已拒绝调用继续执行。跨进程 deadline 与取消必须能传递到实际执行者。 |
| `ctx.systemPrompt` 和 `system-prompt/assemble` | 保留 DSH 段、变量、作用域、排序及 complete/waterfall 的原始语义；在 Eden 指定的装配边界调用，输出要与角色、工具说明、附件、临时记忆、压缩预算及上下文来源记录一致。若某个插件要求替换或重排 Eden 的必需规则，不能静默假装等价：标记该行为不兼容并拒绝该配置，或经明确产品决策后实现可审计映射。 |
| `ctx.on`、`ctx.effect` 和插件服务 | 支持真实 Cordis 的监听、生命周期和 disposer。仅针对有契约测试的事件适配 Eden 事实；事件名称相同不代表载荷、同步性和时序相同。缺少的服务不能提供空对象让 `inject` 误以为已就绪。 |
| `ctx.sessions`、`ctx.agents`、`ctx.llm`、`ctx.jobs` | 按公开接口逐方法建立适配清单；身份与作用域由宿主注入。消息追加、任务派发和模型调用必须沿用 Eden 持久化、权限、取消与预算，不允许创建第二套互不一致的会话状态。未实现的方法明确不可用。 |
| DSH Client `./client`、slots、设置和 RPC | Eden 现有受控 JSON 卡片不能执行 DSH 客户端模块。需另设计与 DSH 客户端版本匹配的模块加载、React/服务依赖、slot 生命周期与通信边界；不直接在现有主渲染进程注入任意脚本并声称已兼容。客户端插件作为单独阶段，缺失时在预览和运行状态明确展示。 |

工具注册与工具说明展示继续分离：`load_tools`／`unload_tools` 只影响模型说明，不能成为执行注册的权限判断。插件直接返回的业务内容保留原契约；宿主只投影自己的包装、追踪字段，不按字段名批量删除第三方业务 ID。结果投影失败不得回退原始宿主回执。

## 6. 调用顺序和失败语义

以模型调用插件工具为例：

1. Server 依据当前账号、会话、行动角色和插件代次选择注册工具；冻结参数和来源，验证 schema、工具策略及子任务预算。
2. 原有 `beforeTool` 路径持久化操作开始；按现有权限策略请求实际调用授权。等待期间插件版本、工作区或账号范围变化则拒绝旧调用。
3. 将本次调用交给 Cordis 宿主；其内部按 DSH 原生事件链运行，并在执行主体前再次执行 Eden 的最终许可与代次检查。这里需要设计可等待的许可边界，不能把 DSH 同步 guard 误写成跨 IPC 的同步调用。
4. 成功或明确失败时先持久化原始回执及状态，再广播；模型仅获取相应业务结果。若运行进程退出、超时或 ACK 丢失，记录 `unknown`／取消事实并提示人工判断，不断言副作用未发生。
5. 禁用、撤销授权和关闭会使已登记贡献失效、取消在途任务；必须等到进程树退出或清楚报告无法确认。结果先发生而回执未持久化时，绝不能自动重放。

精确工具管线的位置和 DSH 的 `ask` 决策需通过上游调用链验证；上面是 Eden 应保持的事实顺序，不是声称当前已经实现同等时序。所有模型可见提示变化需记录来源、顺序、插件版本与实际模型载荷，压缩、角色隔离和旧快照恢复须维持可重建性。

## 7. 兼容等级与 dsh-purge

每个能力的状态分别标注 `未实现`、`已实现未验证`、`契约已验证` 或 `目标插件已验证`，并列出 DSH 基线版本、插件版本、测试平台及限制。只有实际使用原始插件、原始包和真实目标宿主链路通过相应验证，才可称该插件兼容；不能把某个工具夹具通过扩大成整个 DSH 生态兼容。

`dsh-purge` 可作为后期复杂样本：其 [package.json](../参考/dsh-purge/package.json) 含 DSH bundle、client、peer dependency 和安装脚本；[入口](../参考/dsh-purge/lib/index.js) 使用 systemPrompt、tools、事件、条件服务与 Web。它还包含面向 DSH 安装布局的宿主文件修改逻辑，不能假定存在同样的 Eden 目标文件或该行为可安全映射。现有 Eden 提示词移植不是该插件的运行验证；不自动执行上游安装脚本、补丁或用户已有配置更改。对于无法对应的行为，逐项给出不可用原因，不以降级后的部分功能冒充完整兼容。

## 8. 分阶段实施与验收

以下为后续工作计划，当前全部未实施；测试数据只能使用临时目录、合成账号和独立服务，不使用真实用户数据库作为夹具。测试是否执行以用户当时授权为准。

1. **基线与依赖闭包**：盘点 DSH 固定提交的 Cordis、loader、include、tools、system-prompt 公开包、事件分发和许可证，建立机器可读 API／事件矩阵；验证可构建发行依赖，不依赖参考目录。退出条件：每个入口、运行平台、跨进程可行性和缺口都有来源与决定。
2. **profile 与原生生命周期**：实现包预览、版本快照、profile patch、受管进程、真实插件树、依赖注入、dispose、错误状态和重启恢复；继续保留旧插件路径。退出条件：不改插件源码即可装载基础 Cordis 夹具，验证依赖等待、顺序、更新、卸载及多账号隔离。
3. **工具与权限闭环**：原样运行 DSH `greet` 示例，贯通注册、参数、输出、策略事件、Eden 审批、持久操作、调用、取消和卸载。退出条件：实际模型或录制模型通过 Eden 发出调用；证明拒绝、版本变化、崩溃、重复请求和 ACK 丢失下不会意外重复执行。
4. **提示、会话和任务适配**：逐项支持经过确认的 systemPrompt 与会话／agent／jobs 入口，覆盖单／多角色、子任务、长期记忆、压缩、重启与请求来源。退出条件：比较 DSH 固定基线和 Eden 的可观察行为，不可映射部分如实拒绝。
5. **客户端与复杂插件**：设计并接入 DSH Client 所需的模块、服务和 slot，再按版本评估原始第三方插件。退出条件：真实客户端装配、设置、卸载和资源释放通过；`dsh-purge` 依赖、事件、提示和宿主专用补丁逐项核验，未验证功能保留不兼容状态。
6. **真实环境与发布验收**：在独立数据的目标系统上检查安装、更新、回滚、重启和可见 UI；依赖许可证、发行包完整性及双世界行为齐全后再评估发布。任何外部服务调用或真实机器副作用按既有授权单独处理。

## 9. 待技术验证的问题

- 基线 DSH 包的真实发布包、peer dependency 与源码工作区依赖能否组成可复现、可发行的 Cordis 最小闭包；应复用哪些上游服务，避免维护不完整复制品。
- DSH 工具和提示流水线中存在的同步服务调用、共享对象、作用域对象和 event wrapper 能否在所选 IPC 事务边界保持原语义；不能时应选择更大边界还是明确不兼容。
- 包 profile patch 的 `!!js`、条件、嵌套和热更新的确切运行时约束，以及用户和插件提供表达式时的授权及审计方式。
- Eden 必需策略、角色身份和 DSH 插件要求的 `complete`、审批接管或文件补丁之间的冲突如何向用户明确呈现；不得以权限放宽或隐藏规则来假装兼容。
- DSH 客户端模块加载器与 Eden 的 React/Electron 构建、生命周期和消息边界如何共同工作；原生 DSH UI 不应被误认为现有声明式卡片。
- 本地和远程包的许可、签名、脚本、安装器来源及平台能力如何展示；没有签名不等于一定不可使用，但不得显示为已验证发布者。
