# Eden 扩展真实模型验收

完成日期：2026-11-07（北京时间）。结论：当前源码中的智能体能够根据公开协议自主编写、安装并修正原生 API 2 扩展，但不能承诺一次生成即无错误，仍需真实业务验收。

## 验收方式

使用已保存的 DeepSeek／deepseek-flash 配置，关闭推理，Node 22.23.1。只读获取模型配置，不复制真实业务数据库。每次从空的临时工作区和宿主数据库开始，向真实模型提供功能要求与固定的可访问性／验收标记；不提供扩展业务源码、脚手架产物或录制模型回复。

模型自行读取内置技能与 manage_ui_plugins.describe，编写 plugin.json、API 2 清单、Worker 和 HTML，执行检查、安装及状态查询。隔离 Chromium 使用生产工作台、Worker、页面消息桥和真实 RPC 操作模型生成的扩展。没有人工修改成功测试中的生成业务代码；平台与协议说明的修复发生在两次空工作区测试之间。

通过的测试仅开放技能、当前工作区文件和插件管理工具，排除真实桌面、终端、对外消息、代理委派和后台进程。限制由临时测试宿主的工具注册及调用校验执行，不是修改客户的默认策略或恢复操作系统沙箱；白名单及路径／转发防绕过有 3 项专项测试。

## 已验证的业务

1. 页面新增待办，后端只出现一条对应数据。
2. 完成操作更新实际业务状态。
3. 删除操作实际生效。
4. 原生树形视图读取与页面一致的数据；验收器支持展开分组后检查，不强制采用平铺布局。
5. 生成的工具栏命令及包含实际总数的状态栏可用。
6. 工作台修改声明的设置后，生成页面显示新标题。
7. 完整宿主重启后，待办及完成状态恢复。
8. 重启后继续读取已保存设置。
9. 卸载撤下界面及命令，保留后端业务状态。

两次成功验收的浏览器异常均为 0。最新生成页面截图已检查，可读且主要交互可用；本轮不是视觉设计质量评测。

## 测试发现并修复的问题

- 宿主仅允许 iframe 脚本，未允许表单，Chromium 会抑制正常 submit 处理器。独立浏览器复现：无 allow-forms 时页面加载但 submit 不触发，添加后正常。现允许表单事件，仍以 CSP form-action none 禁止向 URL 提交表单；自动回归已改为实际 form／submit 交互并通过。
- 公开 API 2 指南没有充分明确参数顺序。现写清 showMessage(message,severity?)、单参数 postMessage(message)、配置事件只传 keys 数组、api.context 不存在，以及消息请求与返回值的包装规则。
- manage_ui_plugins.inspect 原先把相对路径交给进程工作目录。现相对路径按所选会话工作区解析，审批展示实际目录；审批期间工作区改变时拒绝继续。绝对目录兼容保留，并新增回归。
- 指南补充小写 ID 规则、inspect 的目录参数及 install 必须使用检查结果中的业务 id。模型仍可能写出 camelCase ID、把文件当包目录或使用不唯一的 oldText；这些错误由工具拒绝，模型可读错自修，尚不能保证零错误开发。

本轮模型只开发使用宿主存储的待办类扩展，没有独立 MCP／连接器进程；没有验证真实模型制作自定义文件编辑器或全部扩展类型。结果来自隔离浏览器中的当前源码宿主，不代表已验收完整 Electron 客户包。
