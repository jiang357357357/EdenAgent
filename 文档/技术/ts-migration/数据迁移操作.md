## 入口

从仓库根目录调用，使用项目已有 tsx 加载器。下面路径仅是占位示例，不应直接替换为正在使用的生产目录执行。

```bash
npm run legacy:export -- /path/to/legacy.sqlite /path/to/new-snapshot local
npm run legacy:import -- stage /path/to/new-snapshot /path/to/new-staging local /path/to/legacy-blobs
npm run legacy:import -- status /path/to/new-staging local
npm run legacy:import -- resume /path/to/new-snapshot /path/to/new-staging local /path/to/legacy-blobs
```

伊甸园使用 mon，尘世使用 local，每个世界各自导出和暂存。stage 的目标目录必须不存在；resume 必须指向已初始化、世界一致的 incomplete 暂存库。最后一个 Blob 根目录参数可省略，省略时附件表保持待处理。

| 退出码 | 含义 |
| --- | --- |
| 0 | 审阅导出成功；转换命令仍不提供完成迁移入口 |
| 1 | 转换、读取或报告写入失败 |
| 2 | 参数错误 |
| 3 | 命令执行结束，但迁移仍 incomplete，禁止启动宿主 |

export 的成功退出码只证明导出函数正常结束，不证明数据已转换。

## 进度与恢复

stage/resume 输出 JSON，同时逐领域更新私有 migration-report.json。status 通过只读连接和读事务读取数据库中的已提交表状态，不升级 schema、不触发转换，也不把磁盘 JSON 当进度事实来源。异常退出时 JSON 可能落后数据库，以 status 为准；status 不核验外部附件和快照文件完整性。

resume 核对快照的表集合、摘要及行数；已有 converted 表跳过，尚未提交表重做。失败附件目录保留为 blobs-incomplete-<UUID>，在新 blobs 目录重新复制，不删除半成品。只有相同快照可以继续，不能换一份新快照覆盖已经提交的数据。

新建和恢复导入持有 .conversion.lock。异常退出可能留下锁；确认原导入进程已经停止后才可处理残留锁，不根据文件年龄推断进程已死。当前不提供自动解锁命令。正常异常处理会释放锁，错误和提交状态保留。

## 业务恢复摘要

报告 recovery 单独列出待恢复输入、不确定作业/操作、自唤醒运行/通知、桌面提醒、连接器事件和待刷新模型的数量，每类最多列 20 个记录标识，并给出处理方向。报告不包含请求正文或模型凭据。工作区只报告选择状态，不在恢复摘要中暴露路径。

同一任务可能同时出现在输入、作业和动作记录中，数量不能相加视为独立任务数。计数归零也不代表迁移完成；完整运行上下文、待处理表和最终验收仍需完成。

## 可选恢复旧插件版本文件（实现未执行）

stage/resume 的 Blob 根参数之后可提供旧插件 **versions 根目录**。原 Rust 目录结构为 `<versions-root>/<plugin-id>/<version>/<revision>`；不要传任意单版本路径，不使用数据库保存的绝对 root_path 直接读取文件。只恢复插件、不恢复 Blob 时，第四个参数使用 `-`。

```sh
node --import tsx Script/Project/import_legacy.mjs resume /path/to/snapshot /path/to/staging mon - /path/to/old-plugin-versions
```

实现将文件复制到 staging/recovered-plugins/copy-*/files，旁边 recovery.json 保存文件大小和 SHA-256。停止旧宿主及插件写入后再恢复；目录链接、特殊文件、复制期间变化、超出 520 文件/1024 条目/16 层/64 MiB 会拒绝该次复制。源与目标必须分离。

## 超限上下文的显式摘要恢复（实现未执行）

当 runtimeContexts 列出待审阅会话，可将该会话历史导出到一个不存在的新文件。命令仅访问指定世界的 incomplete 暂存库，持有同一个 .conversion.lock；会升级暂存 schema，不启动宿主。输出文件权限为 0600，包含对话正文，应按私有数据保存。

```sh
node --import tsx Script/Project/import_legacy.mjs review-context /path/to/staging local SESSION_UUID /path/to/new-review.ndjson
```

成功输出 sourceSha256、行数和字节数。NDJSON 保留原事件顺序、压缩事件与 turnCompleted 标记；子会话包含原任务与 context.messages（没有 context 时为 parentHistory），不导出完整配置或凭据。审阅时区分 transient、未完成轮次、已完成结果和原说话者，不能把未完成调用写成已执行成功。失败导出可能留下部分文件，不能用于恢复；重新导出需使用新文件。

在独立 JSON 文件中填写摘要和说明，显式确认其将成为初始上下文：

```json
{
  "format": "eden.legacy-context-summary.v1",
  "sessionId": "SESSION_UUID",
  "sourceSha256": "替换为成功导出返回的64位摘要",
  "summary": "按原说话者记录事实、已完成结果、未完成事项及重要约束。",
  "note": "审阅说明，包括摘要覆盖范围及需要继续核对的内容。",
  "acknowledgeReplacement": true
}
```

```sh
node --import tsx Script/Project/import_legacy.mjs apply-context-summary /path/to/staging local SESSION_UUID /path/to/summary.json
```

摘要文件最大 256 KiB，summary 最大 192 KiB，note 最多 4000 字符。仅接受 review_required 且没有会话/角色 checkpoint 的导入会话；无效角色身份须先解决身份映射，摘要不能绕过。提交前重新计算源摘要，历史或角色身份变化后必须重新审阅。摘要、源 SHA-256、说明、初始 checkpoint 与 prepared 状态同事务保存，原事件及旧子会话原文保留。每个当前角色获得独立 checkpoint，后续各自积累。

该操作不调用模型、不重放工具，也不恢复子会话模型/工具权限或打开关闭的会话；旧子会话仍为 context_prepared_policy_required。迁移仍 incomplete，成功应用返回退出码 3。若数据库提交后报告文件写入失败，先用 status 查看已提交状态，不要删除记录强行重做。迁移激活与整体验收仍待实现。

## 旧 TOML 角色的离线审阅导出（实现未执行）

旧宿主按用户角色目录、当前项目 `.edenagent/agents` 目录依次读取 TOML，项目同名角色优先。新增独立导出脚本保留两种来源，不把项目角色自动覆盖为整个世界的用户角色。该工具需要 Python 3.11+ 的标准库 tomllib；它仅用于离线资料转换，TS 宿主运行不需要 Python。

```sh
python3 Script/Project/export_legacy_roles.py --user-root /path/to/old/user-agents --project-root /path/to/workspace/.edenagent/agents --output /path/to/new-role-review.json
```

两个来源参数至少提供一个，均须明确指定；输出必须是来源目录之外的新文件。只读取目录下直接的 `.toml` 文件，每个最多 256 KiB，每目录最多 256 个，总原文最多 16 MiB。拒绝链接/特殊源文件和读取期间变化，输出权限为 0600；失败写出可能留下部分文件，不覆盖重试。

每项保留原 TOML、来源范围/路径、SHA-256、候选 definition 与 issues。工具名存在无法对应项或不支持字段时，definition 为 null，必须手工核对，不能丢掉 denied_tools 后继续导入。只读角色明确收窄到已有对应工具，不因新宿主新增读取工具就扩大历史名单。候选仍须通过当前角色 schema 校验。

确认用户范围的候选后，可将 definition 对象复制到子任务面板的角色 JSON 编辑器，检查模型、技能、费用上限与工具名，再显式保存；保存不是启动任务。项目候选应先选择对应工作区，在角色编辑器选择“当前项目配置”，再审阅保存。仓库按当前项目、当前世界用户、内置角色依次解析，保存核对工作区与 revision；不要将项目候选批量写为用户配置。移除项目覆盖可恢复下层定义，已有任务快照不改变。未知工具映射、目录自动导入及完整旧任务恢复仍待完成。

### 批量保存已审阅角色

子任务面板→自定义角色配置→导入旧角色审阅文件，可选择上述 JSON，勾选候选，再预览目标范围、内容与覆盖情况。每批最多 32 个角色、序列化后 512 KiB；大文件分批勾选，未知工具或无效定义不可选择。项目条目统一映射到当前工作区，导入前先选正确项目。

服务端核对原文 SHA-256、候选 schema、重复作用域/名称和大小，建立 15 分钟预览，私有保存原文/来源与目标版本。用户确认的是预览中的候选定义；原文摘要仅证明其与审阅文件对应，不证明映射语义已经通过自动校验。

确认后整批角色和修改历史在同一事务保存；工作区、任一目标 revision 或容量变化使整批失败，没有部分保存。已成功提交的 preview ID 可重复查询同一结果，不再次覆盖后续编辑。此流程只保存配置，不启动旧任务或恢复旧授权。普通宿主仍不能打开 incomplete 暂存库，离线迁移激活仍需后续实现。
