## 入口

从仓库根目录调用，使用项目已有 tsx 加载器。下面路径仅是占位示例，不应直接替换为正在使用的生产目录执行。

```bash
npm run legacy:export -- /path/to/legacy.sqlite /path/to/new-snapshot local
npm run legacy:import -- stage /path/to/new-snapshot /path/to/new-staging local /path/to/legacy-blobs
npm run legacy:import -- status /path/to/new-staging local
npm run legacy:import -- resume /path/to/new-snapshot /path/to/new-staging local /path/to/legacy-blobs
```

伊甸园使用 mon，尘世使用 local，每个世界各自导出和暂存。stage 的目标目录必须不存在；resume 必须指向已初始化、世界一致的 incomplete 暂存库。最后一个 Blob 根目录参数可省略，省略时附件表保持待处理。

| 退出码 | 含义 |
| --- | --- |
| 0 | 完成；当前实现不提供完成迁移入口 |
| 1 | 转换、读取或报告写入失败 |
| 2 | 参数错误 |
| 3 | 命令执行结束，但迁移仍 incomplete，禁止启动宿主 |

export 的成功退出码只证明导出函数正常结束，不证明数据已转换。

## 进度与恢复

stage/resume 输出 JSON，同时逐领域更新私有 migration-report.json。status 通过只读连接和读事务读取数据库中的已提交表状态，不升级 schema、不触发转换，也不把磁盘 JSON 当进度事实来源。异常退出时 JSON 可能落后数据库，以 status 为准；status 不核验外部附件和快照文件完整性。

resume 核对快照的表集合、摘要及行数；已有 converted 表跳过，尚未提交表重做。失败附件目录保留为 blobs-incomplete-<UUID>，在新 blobs 目录重新复制，不删除半成品。只有相同快照可以继续，不能换一份新快照覆盖已经提交的数据。

新建和恢复导入持有 .conversion.lock。异常退出可能留下锁；确认原导入进程已经停止后才可处理残留锁，不根据文件年龄推断进程已死。当前不提供自动解锁命令。正常异常处理会释放锁，错误和提交状态保留。

## 业务恢复摘要

报告 recovery 单独列出待恢复输入、不确定作业/操作、自唤醒运行/通知、桌面提醒、连接器事件和待刷新模型的数量，每类最多列 20 个记录标识，并给出处理方向。报告不包含请求正文或模型凭据。工作区只报告选择状态，不在恢复摘要中暴露路径。

同一任务可能同时出现在输入、作业和动作记录中，数量不能相加视为独立任务数。计数归零也不代表迁移完成；完整运行上下文、待处理表和最终验收仍需完成。

## 可选恢复旧插件版本文件（实现未执行）

stage/resume 的 Blob 根参数之后可提供旧插件 **versions 根目录**。原 Rust 目录结构为 `<versions-root>/<plugin-id>/<version>/<revision>`；不要传任意单版本路径，不使用数据库保存的绝对 root_path 直接读取文件。只恢复插件、不恢复 Blob 时，第四个参数使用 `-`。

```sh
node --import tsx Script/Project/import_legacy.mjs resume /path/to/snapshot /path/to/staging mon - /path/to/old-plugin-versions
```

实现将文件复制到 staging/recovered-plugins/copy-*/files，旁边 recovery.json 保存文件大小和 SHA-256。停止旧宿主及插件写入后再恢复；目录链接、特殊文件、复制期间变化、超出 520 文件/1024 条目/16 层/64 MiB 会拒绝该次复制。源与目标必须分离。

文件及目录持久化后才记录 M72 恢复副本；已记录的版本续跑时跳过。中断残留不会覆盖或自动删除，下一次创建新 copy-* 目录。恢复副本仍需按新宿主插件检查/安装流程核对签名、历史 revision、组件和权限；复制摘要不是签名证明，不执行代码，也不启用插件。相关审阅接线仍在实现。
