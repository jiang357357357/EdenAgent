| 退出码 | 含义 |
| --- | --- |
| 0 | 审阅导出成功；转换命令仍不提供完成迁移入口 |
| 1 | 转换、读取或报告写入失败 |
| 2 | 参数错误 |
| 3 | 命令执行结束，但迁移仍 incomplete，禁止启动宿主 |

export 的成功退出码只证明导出函数正常结束，不证明数据已转换。

## 进度与恢复

stage/resume 输出 JSON，同时逐领域更新私有 migration-report.json。status 通过只读连接和读事务读取数据库中的已提交表状态，不升级 schema、不触发转换，也不把磁盘 JSON 当进度事实来源。异常退出时 JSON 可能落后数据库，以 status 为准；status 不核验外部附件和快照文件完整性。

resume 核对快照的表集合、摘要及行数；已有 converted 表跳过，尚未提交表重做。失败附件目录保留为 blobs-incomplete-<UUID>，在新 blobs 目录重新复制，不删除半成品。只有相同快照可以继续，不能换一份新快照覆盖已经提交的数据。

新建和恢复导入持有 .conversion.lock。异常退出可能留下锁；确认原导入进程已经停止后才可处理残留锁，不根据文件年龄推断进程已死。当前不提供自动解锁命令。正常异常处理会释放锁，错误和提交状态保留。

### 尚未续接旧任务的历史用量确认

旧任务详情的“确认迁移前累计用量”仅处理未知历史基线。先停止整棵任务树，从最深子级向父级核对；提供历史累计 token、微美元费用及证据说明。已知字段锁定，未知字段也不能低于现存已记用量，不能用零代替缺失凭据。

### 重开恢复条件已满足的子会话

上下文、工作区、策略、历史用量与模型确认完成后，可以在任务详情选择“重开已恢复的子会话”。父会话必须活动且上下文准备完毕；过期截止期限、未处理输入/作业、未知工具操作或相关待审阅旧信箱均会阻止操作。

确认模型已变化时，先重新预览并确认；旧确认快照会保留在私有历史中。重开事务重新核对确认快照，激活模型绑定并将历史状态置 ready，保存明确的重开说明。任一步失败均回滚，不能以手工改 ready 绕过。

重开只恢复会话可用状态，线程仍保留原结果/终态；不会重发旧输入、排队旧任务或清零预算。继续工作需要新的明确续接指令，审阅模式仍禁止执行。待处理信箱、过期期限及其他未接齐的恢复操作仍在实现，现阶段不保证每个旧任务均可完成重开。

### 明确恢复旧任务期限

旧任务详情新增“恢复旧任务的截止期限”。先恢复工作区和角色策略，停止任务及其后代执行；核对当前截止时间，填写从确认时起的分钟数和续期原因，再明确确认。

期限取请求时长、角色快照最长时限及父任务截止时间的共同上限。父任务已过期时先续期父任务；不会通过续期子任务扩大父级期限。该操作具有固定幂等键和预期旧期限，重复提交不会重复延长，其他操作已改期限时要求重新读取。

续期只记录新期限，不重置已用预算、不增加轮数/调用/token/费用上限、不重发任务。策略恢复中的“不延长旧期限”仍成立；需要延长必须使用这个单独的明确确认入口。已完成历史恢复的普通任务不能继续用该迁移入口无限续期。

### 核对旧子任务信箱

旧任务详情的“恢复历史子任务信箱”按该根会话展示待处理消息。检查发送方、目标、类型、原触发标记和正文，再选择释放普通消息或保留原文归档，填写依据并确认。

释放仅适用于已明确映射、未消费的普通消息；它不会重现旧 trigger_turn 的自动执行。控制、根定向、未知归属等消息当前只能保留归档，原内容与类型仍留在历史表中，完整语义恢复尚待实现。长消息只显示前 16000 字符并提示，不能把截断展示当成完整源证据。

接收者活动执行时拒绝处理；源状态变化要求重新读取。未确认旧消息不会被新收件箱提前消费。已释放或归档项不再阻止对应任务因信箱待确认而重开，但其他恢复条件仍须满足。

### 核对未知作业结果

会话的操作记录面板增加“未确认作业结果”，可读取未知作业、查看任务内容与关联输入，并填写依据确认已完成或停止后续投递。停止后续投递不等于证明原执行没有副作用，未知工具操作仍须另外核对。

有 inputId 的作业要求对应输入先处理到相同结果；缺失或状态不匹配时拒绝，不通过直接改作业状态掩盖输入。更新时核对作业版本，确认记录持久保存，重试不会产生新的投递。输入处置和显式重提流程仍在实现。

### 处置被保留或中断的输入

普通会话操作面板、旧子任务详情均提供“被保留或中断的输入”。按原回合与正文核对后，明确选择停止继续处理或依据执行记录确认完成，并填写说明。未执行过的输入不能确认完成；原回合仍运行或未知工具操作未处理时也不能据此宣称完成。

确认保存的是独立处置记录，不覆盖原输入正文、metadata、回合中断错误或工具账本，不伪造模型完成事件。与其关联的作业可按相同结果继续处置。原输入不会自动重发；新的续接仍需明确提交，原附件/环境的完整重新提交入口继续实现。

### 明确重新提交普通输入

普通运行模式下，新输入可能立即执行；迁移模式仅提供预览。服务端重新校验附件内容及原 TS 快照、上下文与当前会话配置，持久受理和原/新输入关联同事务保存。重复确认同一原输入返回已受理结果，不再次创建回合。不同说明不能覆盖已记录的重提依据。

作业或子任务输入须通过所属业务流程继续；当前普通入口不绕过作业投递账本或子任务轮数/期限限制。无法识别的旧输入字段拒绝自动重提，须继续补兼容映射，不能删除字段后假称原输入已完整恢复。

### 经子任务流程重新提交作业

新作业按普通子任务续接计入轮数，继续受剩余用量、期限、父任务和工具策略约束。原消息保留原有格式，原/新作业关联与排队原子保存，重复确认不再次排队。普通模式下可能立即执行，迁移模式禁止执行。
