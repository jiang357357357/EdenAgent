# 桌面发行操作

状态：流程与工具已编写，未执行构建、签名、安装或验收。发布者密钥尚未创建或配置，当前 CI 只产出未签名制品。

## 制品组装

手动发行 workflow 组装 Linux/Windows x64 TS 宿主、Node 22.23.1、连接器、迁移工具与 Electron。桌面目录有 desktop-manifest.json，归档为 eden-agent-<platform>-<arch>-<version>.tar.gz，同名 .json 描述归档 SHA256、字节数及目标平台。归档保留执行位和符号链接。

本地可在匹配平台先完成 Node runtime 目录和 Web 构建，再运行 package_desktop.mjs 与 archive_desktop.mjs。参见 .github/workflows/windows-frontend-build.yml 的组装顺序。不要使用旧 Rust server 的构建命令。

## 发布者签名

在具备发布授权且已经验收制品后，用离线持有的 Ed25519 PEM 私钥签署描述文件：

```sh
node frontend/Script/Project/sign_release.mjs /release/package.tar.gz.json /secure/publisher-private.pem /release/package.signature.json --confirm-sign
```

工具先核对归档长度及摘要，再签署描述文件的原始字节。签名文件拒绝覆盖，不生成密钥、不上传文件。描述中的 signed:false 表示归档步骤没有签署，后来生成的独立签名文件为单独的真实性凭证；不要手改描述文件，否则签名失效。

私钥不放进仓库、应用包、插件、CI 普通构建任务或公共事件。可信公钥须由独立可信渠道交付，不能只取待安装包内的公钥。

## 使用者校验

归档目录附带 verify_release.mjs 和 release_signature.mjs，供已安装 Node 的管理环境使用；校验器本身应来自可信源码或可信发布渠道。执行：

```sh
node verify_release.mjs /release/package.tar.gz.json /release/package.signature.json /trusted/publisher-public.pem
```

实际文件名使用发行产出的完整平台/架构/版本名。校验要求签名与外部可信公钥匹配，并重新读取归档核对完整摘要。成功只证明这些制品字节属于该签名，不证明业务测试完成，不自动解压、执行、安装或改变当前版本。工具未实现公钥撤销目录与在线更新源。

## 更新与回退边界

当前没有自动更新器。新版本应解压到新的独立版本目录，保留旧应用目录。完全退出两个宿主后再切换启动入口；不要覆盖正在运行的 Node/Electron 二进制。

应用版本回退与数据回退分别处理。旧宿主可能拒绝新数据库 schema，不能仅将旧应用指向已升级数据库。正式升级前的数据快照、双世界停机、激活/回退流程见数据迁移操作.md；不要以复制应用目录冒充数据回退。安装器、更新选择界面及升级/回退演练仍待实现和验收。

## 安装到独立版本目录

新增发行描述绑定 desktop-manifest.json 的 SHA256。使用匹配平台/架构的 Node，先校验签名，再将可信归档解压至空目录，随后执行：

```sh
node install_release.mjs /release/package.tar.gz.json /release/package.signature.json /trusted/publisher-public.pem /unpacked/eden-agent-linux-x64 /apps/eden --confirm-install
```

实际路径和完整发行文件名按平台替换。该命令重新校验签名和归档，并校验解压内容与签名绑定的清单：文件集合、摘要、大小、POSIX 权限和范围内符号链接。复制至暂存目录后再次校验，通过后安装为 /apps/eden/versions/<版本>-<平台>-<架构>/app，附发行描述、签名和安装记录。

同一版本目录拒绝覆盖，安装锁阻止并发写入；失败清理本次暂存。不会运行新程序、切换默认版本、修改 Data 或关闭已有宿主。自动解压、启动入口切换和升级/回退协调仍待接入，不能将此命令称为自动更新器。

上述源码未执行。旧描述缺少 manifestSha256 时需重新生成并签署，不能补字段后沿用旧签名。

## 受管版本选择与启动

安装后先读取 current-version.json 的修订；首次不存在时使用 none。选择版本会重新检查已安装版本的独立签名和完整文件清单，不需要保留原归档才能核对：

```sh
node select_version.mjs read /apps/eden
node select_version.mjs select /apps/eden 1.10.1-linux-x64 none /trusted/publisher-public.pem "选择已验收版本" --confirm-version
node launch_version.mjs /apps/eden /trusted/publisher-public.pem
```

后续选择必须提供 read 返回的当前 revision。回退使用 rollback 动作、当前记录中的 previous 版本及当前修订，同样核对签名、平台和文件。切换只写入下次受管启动使用的版本，保留上一版本，既不运行应用也不更改数据库。

启动器校验后启动 Electron，并在其整个生命周期持有安装锁，退出后释放。安装和受管选择共用此锁，应用运行期间拒绝安装或切换。不能关闭启动器却留下子进程后直接删除残留锁；异常终止应先确认 Electron 和两个宿主全部退出。当前无自动残留锁回收。

该协调仅覆盖 launch_version.mjs 启动的实例。首次接管前，必须退出直接启动的旧应用与外部管理宿主；不能用安装锁判断这类进程已经退出。操作系统快捷方式、直接启动统一接管和图形更新入口尚未接线。

数据库升级仍须预先完成双世界快照与兼容核对。回退应用不会恢复数据库；不兼容的旧宿主应拒绝打开新 schema，不能把版本选择成功作为数据回退成功。未执行以上命令或演练。

## 已安装应用的启动约束与重启

新桌面主入口识别 versions/<版本>/app 下的受管安装，在启动任何宿主前检查安装记录、当前版本修订、安装锁、启动器父进程和本次 IPC 令牌。直接双击该受管目录中的程序会要求通过 launch_version.mjs 启动；源码开发与普通未安装便携目录保持原入口。

启动器为本次启动记录锁所有者，并持有 Electron IPC。界面中的运行根切换后重启会发送受管重启请求，再经过现有双宿主正常退出流程；启动器只有收到请求且 Electron 正常退出后才重启相同选定版本，并再次校验签名与文件。崩溃不会被当成用户请求重启。

这一机制是同一账户内的进程协调，不是抵抗同账户篡改环境/文件的安全隔离。旧版应用、未安装便携版和外部宿主仍须在首次接管时明确退出。启动器异常终止仍需核对进程后处理残留锁。上述新入口未实际启动验证。

## 固定运行时的用户启动脚本

首次安装并选择版本后，可运行：

```sh
node setup_launcher.mjs /apps/eden /trusted/publisher-public.pem --confirm-launcher
```

该步骤从已验签应用复制 Node 22.23.1 与签名清单覆盖的受管启动代码，复制内容再次与签名清单比较，并保存固定的发布者公钥。生成 /apps/eden/launcher/start-eden.sh（Linux/macOS）或 start-eden.ps1（Windows）。此后使用这些脚本启动，无需用户 PATH 中的 Node；Windows 使用 PowerShell 的 -File 指定生成的 ps1，不绕过系统脚本执行策略。

目录 launcher 已存在时拒绝静默替换，更新信任公钥或启动器需另行明确维护。脚本始终读取当前版本选择，因此应用版本切换不必改写启动路径。旧便携版的快捷方式不会自动迁移；系统入口见下文，macOS 原生应用包装仍待接线。

发行步骤现将 release-tools 放进 app 资源，再生成文件清单与归档；在此之前生成的制品没有这些工具，需要重新构建并签名。以上步骤未实际执行。

## 归档直接安装

新增 install_archive.mjs 支持从签名 tar.gz 直接安装，无须手工解压：

```sh
node install_archive.mjs /release/package.tar.gz.json /release/package.signature.json /trusted/publisher-public.pem /apps/eden --confirm-install
```

安装器先验签并复制归档/描述/签名/可信公钥至本次私有临时目录，重新验签核对同一发布者和同一描述后解压。受限读取器只接受项目制品需要的普通文件、目录、包内相对链接和有限路径扩展；拒绝硬链接、设备、稀疏文件、重复路径和逃逸路径，并限制条目数与展开大小。符号链接最后创建，不允许用作其他归档条目的父目录。

解压后仍由原独立版本安装器做完整签名清单核对和版本目录发布，不自动运行或选择版本。异常清理本次临时目录。Windows 创建符号链接可能需要系统相应权限；不支持的归档会报错，不静默跳过条目。以上代码未实际解压或验收。

## 用户菜单与桌面入口

选定版本并建立 launcher 后，使用发行包中的 setup_system_entry.mjs；第三个参数是用户明确选择的、已存在的菜单或桌面目录。例如 Linux：

```sh
node setup_system_entry.mjs /apps/eden /trusted/publisher-public.pem "$HOME/.local/share/applications" --confirm-system-entry
```

Windows 将第三个参数指定为用户的开始菜单 Programs 或桌面目录，生成 Eden Agent.lnk；Linux 生成 eden-agent.desktop；macOS 可指定桌面目录生成 Eden Agent.command，可从 Finder 打开终端启动。macOS 这一步不是 .app 包装，也没有添加 Dock 图标。

创建入口时持有安装锁，验证当前应用和 launcher 来源版本的签名与文件，逐项比较固定 Node/启动代码并核对固定公钥。launcher 来源版本需要保留，不能因切换到新版本而删除。所有入口直接调用固定 Node 与 launch_version.mjs，版本切换继续使用同一入口；不依赖 PATH 中的 Node，不直接绕过受管启动器调用 Electron。Linux/终端入口保留控制台以显示启动错误。

目标已有同名入口时拒绝覆盖；临时生成后排他复制到目标。若入口已经创建但后续检查失败，报告路径并保留现场，不能删除可能被用户改动的文件。脚本只创建入口，不启动应用、不注册自动启动、不删除旧便携版入口、不提权；创建其他账户或系统目录入口需由用户自行提供相应权限。本轮没有实际创建任何菜单文件或调用 PowerShell。

格式依据：[freedesktop Exec 规范](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html)与 [Microsoft WScript.Shell 快捷方式说明](https://learn.microsoft.com/en-us/troubleshoot/windows-client/admin-development/create-desktop-shortcut-with-wsh)。Linux 分别处理 Desktop 字符串与 Exec 引号转义，Windows 分别设置 TargetPath、Arguments 和 WorkingDirectory，不通过 shell 拼接启动路径。平台菜单识别、带特殊字符路径、执行策略及失败提示仍待集中验收。
