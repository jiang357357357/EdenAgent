# 协议生成迁移

本阶段只编写生成流程，不执行生成、构建、类型检查或测试。现有前端生成文件保留，新的入口待用户允许验证后运行。

## 当前来源

- `packages/api/src/rpc.ts`：协议版本与基础请求 schema。
- `packages/api/src/*.ts`：已迁移业务的运行时 schema 和推导类型。
- `packages/api/src/rpc-methods.ts`：逐域迁移的方法表，当前接入 MCP 四个管理方法；SchemaRpcMethodMap 直接从输入/输出 schema 推导，服务端 contractHandler 与前端类型桥共用此表。
- `packages/api/src/legacy-wire.ts`：从旧生成文件迁入的兼容类型与 83 项 RPC 映射，作为 B6 逐域替换基线；不依赖 Rust 或归档文件。该文件仅保留声明，超过 300 行的原因是兼容基线尚未按业务 schema 替换，不在其中新增业务实现。
- `Script/Project/templates/rpc-browser.ts.template`：浏览器传输代码模板，保留当前 uploadBlob 和 EdenAgentRpcClient 行为。
- `Script/Project/generate_rpc.mjs`：读取 TS 兼容声明、协议文件与模板，写入带来源摘要的前端文件，使用临时文件后重命名，失败清理临时文件。

根命令 `npm run generate:rpc` 已改为 Node 入口。它不启动宿主、不打开数据库、不调用 Cargo。生成后的客户端通过 `@eden/api/legacy-wire` 引用兼容契约，并保留本地 RpcMethodMap/RpcNotificationMap 接口供迁移期类型扩展使用。

模板以 SchemaRpcMethodMap 覆盖已迁移的方法，其余暂用 legacy-wire。生成摘要递归包含 API 包全部 TS 文件与浏览器模板，避免方法表变更未进入来源摘要。现有前端通过 lib/rpc-contracts.ts 获得相同 schema 方法类型，不依赖提前执行生成器。

前端类型桥现使用 Omit<旧映射, 已迁移键> 与共享方法表组合，避免旧 bigint 类型与新数字类型通过接口继承发生冲突；请求适配在 JSON 传输边界校验迁移方法。当前已接入 MCP 四项及连接器十二项，其他域保持兼容实现。

## 尚未完成

1. 逐域将 legacy-wire 的旧返回类型替换为当前 schema 推导类型，尤其 bigint、默认字段、nullable 和事件字段。
2. 将前端零散 RPC 类型扩展集中到 API 方法注册表，再由注册表关联服务端 schema 与浏览器客户端；不能把当前兼容文件当作最终单一事实来源。
3. 保留旧具名类型导出兼容，完整对照旧 RPC、工具、事件与 Blob/实时通道。
4. 业务完成后编写契约测试；用户明确要求后才运行生成及测试，核对完整前端接入。

本次没有生成新前端文件或宣称生成结果通过检查。迁入的浏览器模板保留旧行为，其超时、断线、未知响应等问题留待协议整合，不能据迁移来源改动宣称修复。
