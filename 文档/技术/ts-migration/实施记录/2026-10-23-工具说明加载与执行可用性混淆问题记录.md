# 2026-10-23 工具说明加载与执行可用性混淆问题记录

状态：代码修复及独立测试通过；Server 制品已更新，当前在线旧进程未手动重启。

所属模块：能力发现、会话工具解析、runtime-pi、隔离运行时。

## 问题与设计要求

修复前的实现把“向模型展示哪些工具说明”与“宿主允许调用哪些已注册工具”绑定在一起。智能体已经从历史上下文知道工具名称和参数，宿主也仍然注册该工具，却会因为本轮没有通过 `load_tools` 展示接口说明而拒绝调用。

用户于 2026-10-23 明确指出：“工具一直都是在的，加载工具只是让智能体知道，而不是加载工具后才有工具用。”

这项要求应落实为：**当前作用域中已注册且符合策略的工具始终可接受有效调用；工具说明的按需展示只影响模型上下文。** `load_tools` 用于补充完整接口说明，不能成为额外的调用前置条件。工具执行继续按当前账号、会话、角色、渠道和权限规则处理。

## 实际失败案例

最新 App 会话《问候与开场》在北京时间 2026-10-23 02:42:26–02:43:23 的最后一轮中，出现以下调用：

| 时间 | 调用 | 结果 |
| --- | --- | --- |
| 02:42:30 | `desktop_observe` | `Tool desktop_observe not found`，尚未进入业务操作表 |
| 02:42:32 | `list_tools` | 找到宿主已有的桌面工具，部分旧展示选择为 `stale` |
| 02:42:37 | `load_tools` | 9 个桌面工具的完整接口加入模型展示列表 |
| 02:42:41 | `desktop_observe` | 已能进入业务执行，随后因旧窗口引用失效而失败 |
| 02:42:49–55 | 重新查找窗口并观察 | 成功返回窗口和控件数据 |

第一次失败来自工具说明与执行注册耦合。旧窗口引用失效属于另一项有效性检查，重新发现窗口后才能继续，不能通过取消说明加载门槛一并绕过。

这一轮实际有 8 次尝试，操作表只有 7 条；首次未找到工具仅记录在运行时事件流。全会话有 3 次此类未进入操作表的工具未找到错误。依据为 `.artifacts/latest-session-tools-20261023/snapshot.json` 中的调用及计数。

## 修复前根因

修复前的代码在三处将展示选择作为执行条件：

| 位置 | 修复前行为 | 产生的影响 |
| --- | --- | --- |
| `Server/src/modules/capabilities/session-capabilities.ts` 的 `tools()` | 按 `visible` 过滤注册目录，只返回默认展示或显式加载的工具 | 已注册但未展示的工具没有交给运行时 |
| `packages/runtime-pi/src/harness-runtime.ts` | 将收到的同一组工具用于 harness 注册及活动工具集合 | 执行查找集合随模型展示列表一起缩小，模型从历史发出的有效调用得到 `not found` |
| `Server/src/modules/capabilities/call-resolution.ts` 的 `resolveToolCall()` | 要求入口及最终转发目标均属于 `visible`，否则报 `Tool is not loaded in this session` | 即使补齐运行时注册，宿主解析仍会用展示状态拒绝调用 |

修复前，审批等待后的 `assertCurrent` 也重复执行上述展示检查，因此卸载说明会被当成撤销执行资格。加载记录的角色、工作区和版本状态也会影响展示集合，进而间接影响工具能否执行。

这不是单纯的错误文案问题，也不能靠系统提示要求智能体“每次先加载”解决。需要在宿主和运行时同时分开说明展示与执行解析。

已核对当前安装的 pi 0.82.0：harness 构造的活动工具上下文同时用于调用查找，仅将全量工具注册却只激活展示子集仍然会报 `not found`。本次将全部允许工具交给 harness 的执行上下文，只在提供方发送请求之前筛选说明；没有修改依赖包，也没有使用 SDK 私有接口。

## 应有语义

| 层次 | 作用 | `load_tools` 的影响 |
| --- | --- | --- |
| 工具注册与作用域策略 | 确认工具当前存在，且属于当前账号、会话、角色和渠道允许的目录 | 不以说明是否加载为判断依据 |
| 说明展示 | 选择本次模型请求附带的工具说明、参数 schema 和必要提示 | 加入完整说明；`unload_tools` 从后续请求中移除说明 |
| 调用校验与执行 | 按当前定义校验参数，执行审批、归属、版本、取消和审计逻辑 | 有效调用可直接进入校验与执行，不要求先加载说明 |

智能体从历史、技能说明或目录中已经知道某工具的用法时，可以直接调用。需要确认参数时，仍可使用 `list_tools` 和 `load_tools` 获取说明。`loaded`、`unloaded`、`stale` 应表达说明展示选择的状态。

工具被实际卸载、连接器断开、插件停用、角色策略排除或渠道不允许时，应按真实原因拒绝。未知工具名和无效参数继续报错。工具定义或审批所依据的资源发生变化时，仍须重新校验，不能为了消除加载门槛而执行过期的审批快照。

`unload_tools` 仅移除说明展示。需要禁止某项操作时，应通过明确的权限、角色策略或插件启停规则实现，不能复用说明卸载状态。

## 修复范围

1. 为当前作用域保留完整执行注册表，独立计算向模型展示的工具定义；策略已排除的工具不进入可执行目录。
2. 调整调用解析和转发解析，移除以 `visible` 为依据的加载检查，保留当前定义、参数、作用域及审批一致性校验。
3. 在 runtime-pi 中将执行查找与模型请求中的工具说明分开；不要通过向模型发送全部 schema 来规避问题。
4. 将展示状态传递到隔离进程，保持宿主与子进程语义一致。模型请求记录、说明提示和上下文预算只计算实际展示的说明。
5. 更新 `list_tools`、`load_tools`、`unload_tools` 的描述及目录提示，删除“未加载就不能调用”的规则。保留现有 API 名称可作为兼容方案。
6. 调整现有测试中把“卸载说明”当成“禁止执行”的断言，并补充以下行为验收。

以上范围已落实到下述实现，原有接口名称及选择记录继续兼容。

## 验收标准

- 模型请求未展示某个已注册工具的完整 schema，模型根据上下文直接发出有效调用，工具执行成功，实际模型请求仍保持精简。
- 显式加载说明后，后续模型请求出现该工具定义；卸载说明后定义消失，但后续有效调用仍能执行。
- 重启或恢复会话后，历史中已知且仍注册的工具不会仅因展示选择过期而报 `not found`。
- 通用工具转发到未展示的真实目标时，按目标当前定义执行校验和审批；真正被策略禁止的目标仍被拒绝。
- 等待审批期间卸载说明不导致执行资格失效；审批拒绝、资源变化、工具实际移除或作用域变化继续正确阻止执行。
- 参数错误、工具真正不存在、插件停用及渠道限制分别保留明确错误，不被伪装成说明未加载。
- 隔离运行时与进程内运行时均验证直接调用、展示增减、当前版本校验、结果投影及一次调用一次审计。
- 模型请求与上下文预算保持一致，未展示工具的完整说明不占用模型上下文。

## 已实施修复

| 模块 | 输入与输出、状态归属 | 实现与失败行为 |
| --- | --- | --- |
| `SessionCapabilities` 与 bootstrap | 当前作用域的注册目录、说明选择 → 完整执行工具数组与展示状态 | 新增 `registeredTools()`，返回当前角色及渠道策略允许的全部工具，按展示选择附 `exposure`；宿主正常会话使用该方法。`tools()` 保留为展示子集视图，不再作为实际运行时的注册入口 |
| `call-resolution.ts` | 模型调用与当前注册目录 → 最终工具及参数 | 入口与最终转发目标均不检查 `visible`；真实未注册或策略排除、定义变化、循环转发仍拒绝。解析时捕获会话、行动角色、profile、工作区及渠道，审批后重查当前目录及执行定义，并继续调用工具自身的有效性检查 |
| `harness-runtime.ts`、`model-provider.ts` 与 `tool-presentation.ts` | 完整执行数组 → harness 全量注册；说明子集 → 提供方请求 | 按展示状态复制、筛选提供方的工具上下文，不修改 harness 的执行上下文；`refreshTools` 与 `replaceTools` 同步刷新展示状态。系统提示、请求记录的 schema／promptHints／contextSources 与自动压缩预算均只使用展示子集 |
| `process-protocol.ts` 与 `process-tools.ts` | 宿主工具 → 隔离进程的描述与私有句柄 | IPC 保留 `exposure`，子进程采用相同展示逻辑；工具闭包、转发解析、审批、结果投影及审计继续在宿主执行 |
| 能力工具说明与文档 | 当前目录与选择 → 模型发现提示及开发规范 | `loaded` 明确表示参数说明展示；目录同时列稳定 ID 和实际调用名称，明确已知名称及参数可直接调用。保留 `load_tools`／`unload_tools` 名称和返回字段，能力工具修订提升为 v2；同步修正工程约束、《工具与技能按需加载》和《开发与运行》中的旧调用规则 |

旧工具说明的加载选择没有被当作新的执行授权。旧选择过期时，仍可按当前注册定义直接调用；缺失插件、不可用连接器、失效窗口引用及其他业务资源继续由原有检查报错。工具参数仍按 SDK 和目标工具的实际 schema 校验，包括 SDK 既有的标量类型转换行为。
