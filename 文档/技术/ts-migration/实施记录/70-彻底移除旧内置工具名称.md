# 彻底移除旧内置工具名称

日期：2026-09-12

## 问题

工具目录虽然已经只发布无项目前缀的名称，API 中仍保留旧名称到新名称的运行时映射，子智能体策略每次读取和收窄时仍会执行兼容转换。历史上下文分类也继续识别旧附件工具模板。这使退役名称仍是活动运行时代码的一部分。

## 修复

- 删除 `packages/api/src/tool-names.ts` 及其公共导出。
- 删除子智能体策略创建、读取和继承时的名称归一化；策略只使用数据库中的当前名称。
- 数据库 schema 114 在升级时一次性迁移 `subagent_policies`、`subagent_roles`、`subagent_project_roles`、`subagent_role_snapshots` 中七个退役内置名称，并对数组去重。
- 新建或编辑子智能体角色时拒绝所有 `eden_` 前缀工具名，避免退役格式重新进入活动配置。
- 当前策略解析同样拒绝该前缀；未完成数据库升级的错误数据不能静默放宽权限。
- 历史上下文分类不再匹配旧工具提示模板。历史模型请求、工具结果和操作账本不改写，只作为审计事实保存，不参与当前工具解析。
- 插件系统及连接器实施文档全部改用 `manage_plugins` 和 `manage_connector_plugins`。

## 验证

- 名称与策略迁移专项 4 项通过，包括四种持久策略来源迁移、重复名称合并、当前策略收窄、旧前缀拒绝和当前上下文分类。
- `npm run typecheck:server` 通过。
- 真实 Mon/Local 数据库已升级到 schema 114；实际策略来源中升级前没有退役名称，因此没有用户策略内容被改写。
- 重启后真实 `tool.list`：Mon 55 项、Local 50 项，`eden_` 前缀均为 0。
- 活动代码中不再存在 `canonicalToolName` 或 `legacyBuiltinToolNames` 引用。

迁移 SQL 和历史实施记录中保留旧字符串，用来识别待迁移数据和记载当时事实；它们不是可调用名称或运行时别名。
