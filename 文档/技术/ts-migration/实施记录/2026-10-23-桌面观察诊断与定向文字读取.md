# 2026-10-23 桌面观察诊断与定向文字读取

用户授权修复桌面工具的信息缺失与核验困难。本轮完成代码、独立夹具测试和构建；真实 QQ、前台输入和硬件接管验收继续按此前约定暂缓。

## 实施内容

- `desktop_observe` 保留驱动的截图缩放、帧有效性、树完整性、降级原因及截断原因；未知字段以 `null` 呈现，白屏不能作为内容为空的证据。
- 分别返回系统观察器边界、驱动边界、截图尺寸及各方向的尺寸比例。控件矩形使用驱动桌面坐标，返回与驱动窗口的几何交集；交集只说明几何相交，不证明未遮挡。最小／最大窗口尺寸尚未测得，明确返回 `null`；后台投递能力由每次动作报告。
- 窗口内点击继续使用原始截图像素，由 SDK 转换一次。`resize` 的说明修正为驱动桌面坐标，禁止直接混用观察器边界或凭 DPI 猜尺寸。
- Windows 观察器在请求线程设置并核验 PMv2，返回窗口报告的 DPI、坐标基准、主屏幕、虚拟屏幕及所在显示器的工作区。DPI 仅表示窗口感知模式下的报告值；无法确认物理坐标时阻止跨窗口拖放。观察中位置／尺寸／DPI 变化及输入前尺寸／DPI 变化要求重新观察。
- 新增 `desktop_read_text`，桌面工具总数由 9 个增至 10 个。支持当前控件引用或精确的角色、标签和祖先路径。刷新无截图的可访问性快照，只返回唯一目标的当前值、Text 文字或目标 Text 子树；保留无操作 token 的文字节点，但阻止把它们当成可操作控件。
- 文字读取返回来源、完整性和截断标志；不可读值以 `null` 表示，有明确值来源的空串仍可读取。缺失／歧义／截断标签明确报错。树不完整、降级或文字截断时返回 `unknown`，不能确认成功。
- 控件引用继续按快照更新，返回的 `locator` 提供跨快照定位。文字读取返回目标新引用；再次使用坐标前需要有截图的观察。快照取得失败时也撤销旧引用，避免使用已经被 SDK 更新的旧 token。
- 错误补充窗口／截图几何、目标矩形、几何交集及恢复建议，经 broker 校验传输并记录到操作审计。异常继续保持失败／取消／未知语义；运行时错误文本附带可解析诊断 JSON，正常拒绝结果直接携带结构化诊断。
- 保留未知／已送达输入后自动观察一次的行为；精确替换读回还要求两次树均完整、未降级且值未截断。未知输入不会自动重放。已验证动作直接结果仍不代表完整 QQ 发信任务成功。
- 新工具登记模型结果契约并保持延迟加载。沿用当前任务审批、账号／世界／会话归属、暂停／停止、取消与审计边界；QQ 和自醒会话没有因此获得桌面权限。

## 坐标契约依据

本机安装版本为 `@trycua/cua-driver@0.28.0`。既有原生 SDK 工具目录记录 `.artifacts/desktop-control-20261022/driver-catalog.json` 明确说明：`click.x/y` 是窗口截图像素，`set_window_frame` 使用 `list_windows` 的桌面坐标，`include_screenshot=false` 可只刷新树。相关原文摘录保存到本轮 `driver-coordinate-contract.json`。

同时核对了 [Cua 官方坐标与观察说明](https://cua.ai/docs/cua-driver/concepts/how-cua-driver-works) 及其公开矩形实现。该契约解释了为什么不能仅凭窗口边界与截图相差两倍，就在宿主中再次除以二。本轮保留原始数据用于后续复现，不将尺寸差异直接定性为线上驱动故障。

## 生效与待验收

Server 与共享桌面驱动服务重新加载后生效，Windows 观察器随新的驱动服务启动。本轮未手动重启在线进程、操作真实 QQ、发送消息、发布或提交推送。QQ 截图白屏、实际物理／虚拟坐标差异、前台文字输入、跨应用拖放及硬件接管仍需后续真实验收；不能据本轮夹具通过宣称线上问题已经消失。

`desktop_read_text` 读取可访问性提供方暴露的内容；Text 子树内容及完整性不等于浏览器 DOM 的精确全文，也不能证明消息已经发出。实际最小／最大窗口尺寸仍为未知，不预先宣称某个 Chromium 窗口必然支持或不支持后台输入。
