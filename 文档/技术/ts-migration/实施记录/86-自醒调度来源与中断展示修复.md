# 自醒调度来源与中断展示修复

2026-09-14，用户要求检查并修复自醒页面。

## 已确认原因

- 9 月 12 日 run f5277a13-9989-4131-aace-506d34637a5c 的对应输入事件明确为 `input.interrupted`，原因 `Server restarted during execution`。
- jobs 中存在早已到期的本地定时任务 3c717237-af1a-492a-88da-534a7534bb23。伊甸园将此类任务交给 MonOs，宿主调度器不会执行；列表却使用 local ?? external，让这条旧交接记录遮住实际 MonOs 计划。
- MonOs 状态文件记录历史连续失败 2889 次及下次 2026-09-14 21:56:40 唤醒。签名调用当前 `/internal/self-awake/status` 查询已有作业返回 HTTP 200、completed，证明当前网络与认证可用。没有重触发真实自醒或外发操作。
- UI 用“平稳”“完成本轮观察”填补空决策，掩盖失败事实。

## 修复

- 列表按调度所有者选来源：外部调度使用 MonOs 文件，本地模式使用宿主任务。外部暂停、未安排和读取失败都不能回退成旧本地任务。
- 公开协议补齐 disabled/unscheduled/retrying 状态和空时间。历史失败退避显式显示“上次唤醒失败，等待重试”，详细原因与计划时间可从提示查看。
- 中断失败关联同会话同 inputId 的持久事件，保留真实原因；已有旧错误文本在读取时补全中文重启原因，不改写数据库审计或历史日记。
- 右侧状态显示运行状态，缺少行动时显示“未记录行动结果”。

## 验证

- 外部调度来源、列表、定时发布及队列专项共 12/12 通过；补充中断事件归属测试后新测试文件 2/2 通过。
- 签名状态查询使用当前部署配置，仅输出 HTTP 与业务状态，不输出认证密钥。
- 保留历史失败计数和 MonOs 退避计划，不通过清零记录或自动重放掩盖中断。
- 最终协议生成、前后端类型检查及构建通过；架构检查仅两项既有 Mon 复杂度错误。
