# 117：等待条件、历史来源与真实验证

日期：2026-09-20。用户批准“开始修复，然后完成真实测试”。通用机制使用“用户”；角色资料中的称呼由角色本身决定。

## 实现

- `packages/api/src/intentions.ts` 与 store 新增迁移：保存 `waitFor`、`waitingSince`，进展可保存证据。既有 waiting 记录回填原下一步及等待起点，迁移不删除历史。
- 打算默认查询 active。自醒期间，如果等待开始后没有同账号、同角色的新用户消息，all/open/waiting 查询也不展开该等待事项；直接按 ID 读取返回等待状态，完整记录在普通用户对话与存储中保留。
- 等待事项继续、追加进展、完成均需引用新的用户会话、回合、原话与相关性说明。宿主校验来源、账号、角色、时间和原话，排除自醒作业、内部交接与子智能体输入。暂停/放弃允许；暂停后恢复仍保留证据门槛。操作权限继续独立审批，证据不是行动授权。
- 新人类消息只使记录可供复核，不自动改为 active。相关性仍是模型判断，宿主不把 `relevance` 当作已核实事实；当前证据支持宿主用户会话，尚未接入 QQ/邮件/设备入站事件。
- 打算标为 `character_plan`，进展为 `character_report`。读取当前打算默认不附历史，`includeHistory` 显式查询旧进展。
- 显式工具保存的长期记忆返回 `character_report` 来源；召回保留来源及未验证历史标识，避免将 `kind=fact` 当作独立核实。
- 日记默认目录。完整日记使用 `includeContent=true` 与 `query` 在最近指定数量的日记中按文字匹配，空检索不批量展开；记录本身不删除。
- 模型侧唤醒上下文只保留时间、状态、来源，定时触发备注不再回流为当前任务；兼容 `wake_notes` 入口也仅返回时钟。审计存储中的原备注保留。
- 主提示简化为当下想法、共同交流、自主安排与实际唤醒时间；通用会话提示删掉容易诱发无条件巡检的“历史状态需要重新核实”。

正式账号库先做一致性 SQLite 备份，私有文件权限 0600。修复 intention 1 的下一步、原因和等待条件，保留历史进展；修正 memory 4/5 对“回复未知”和“本地桥身份”的不当结论，保留备份和更正审计。旧计划通过 JobRepository 替换并向 MonOs 发布，未直接编辑外部 state.json。

架构检查发现当前工作树其他文件已有的复杂度问题；本轮修正 intentions 新增的复杂度，并拆分所触及 self-awake context/prompt 的既有复杂度。完整仓库架构门禁仍未通过，不宣称全仓检查全绿。

## 验收边界

等待机制与证据校验已落地；真实模型的无关/相关用户答复对照通过。历史内容的来源标识不能保证模型推断正确；联系记录、长期记忆和备忘仍可能引出自主巡检。不得把局部机制通过写成“重复自醒和角色文风已全面解决”，也不得把真实模型自动测试视作真实用户的系统配置授权。
