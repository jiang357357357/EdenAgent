# 共享资料库仅发布方需要 DLC

日期：2026-10-06。用户纠正实施记录 178 的双端启用要求：“共享的一方有就行”。本轮将接收能力贯通到普通 Agent，DLC 仅控制发布目录。

## 结果与边界

发布方安装并启用 SharedWorkspace DLC，创建资料库并明确确认目录。接收方无需安装 DLC，普通 Agent 中保留发现、双向邀请配对、已授权资料库列表、目录确认和同步；可编辑权限允许向发布方回传修改，不要求接收方因此安装 DLC。每台电脑仍连接自己的 Core，LAN 不交换 Core Token 或用户 ID。

关闭 DLC 后拒绝该电脑发布资料库，包括已有库的文件读取、内容上传和版本提交，仍能接收其他发布者的资料。身份、授权、队列、历史与已下载文件不删除。退出本机账号则停止整个账号的 LAN 网络与同步。一个资料库仍由创建它的电脑提供版本服务，离线时本地副本和队列保留，没有多主接力提交。

## 代码与调用链

- 将 DLC 的通用 `client/` 与 `lan/` 移入 `Agent/packages/shared-workspace/`，增加私有工作区包 `@eden/shared-workspace`，Server 使用包公共导出静态导入并打入 Node 制品。移除唯一动态 DLC 导入和其架构例外，没有保留另一套接收实现。
- 新包运行时区分已验证本机账号的 `active()` 与发布开关 `canPublish()`。本机新建和全部本机库请求检查发布开关；异步内容保存/读取后再次检查。访问远端库只检查远端授予的资料权限，不检查本机发布 DLC。
- DLC 保留安装/启用清单与历史 Core 维护目录，当前清单使用 `workspace.publish.v2` 和固定 publisher 声明，不再提供动态客户端代码。默认关闭和无独立 MonPM 进程保持。
- Agent 的账号运行时不因缺少、禁用或不兼容的发布 DLC 停止接收，注册目录可在登录后恢复；状态增加 `canPublish/publishReason`，RPC 真源与生成客户端同步。恢复失败仍报告真实注册表/目录错误，不借 DLC 状态吞错。
- 页面提示接收方无需 DLC，仅禁用本机新建；配对、选择授权库和本机目录、同步及按 editor/viewer 处理冲突/历史继续可用。首次分享确认、作用域隔离和静默定时读取保持。
- 原同步引擎进入 Agent 架构门禁后，拆分文件记录校验、改名/采集和入站冲突判断，三处既有复杂函数得到收敛；行为由原完整同步/恢复用例验证。全部运行数据继续使用原协议 2 的 `shared-workspace-lan/` 路径，没有数据迁移。
- `npm install --ignore-scripts --offline` 仅增加一个本地工作区链接并更新锁文件，保留原有 Markdown 等依赖改动，没有新增外部运行依赖或访问远程源。
