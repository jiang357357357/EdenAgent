# 2026-10-22 桌面控制独立悬浮窗

## 结果

按用户要求，将 Electron 客户端的页面内桌面控制条改为独立原生悬浮窗。窗口可以拖动、默认置顶、切换置顶，并记住位置；主窗口隐藏后仍由主进程更新状态。浏览器访问保留原页面内控制条。

完成源码、Web 构建和后台验证。34 项相关测试通过，0 失败；真实用户前台拖动、鼠标／键盘及跨应用操作验收继续遵循此前“先完成代码，稍后再测前台”的指示，尚未执行。本轮没有重启现有客户端／宿主、使用用户数据库或发布。

## 交互

- 顶部握柄区域用于原生拖动，按钮区域不参与拖动。
- 右上角可切换置顶，关闭按钮隐藏窗口；任务仍在执行时，先请求停止，确认成功后隐藏。停止失败会保持窗口可见并显示错误。
- 暂停／恢复／停止沿用现有 `desktop.control` 协议。恢复不重放已经取消的输入，仍需重新观察。
- 有桌面任务、暂停或停止状态时自动显示，正常空闲时隐藏；从托盘“桌面控制”可以随时手动打开。
- 手动隐藏的停止提示不会每秒重新弹出。新任务开始或从托盘打开时再显示。
- 自动出现使用 `showInactive()`，不主动获取输入焦点；正常轮询不会反复抬起窗口。
- 窗口位置和置顶选择保存在 Electron `userData/desktop-control-window.json`，显示器移除或工作区变化后限制在可见区域。

## 实现

`frontend/desktop/src/desktop-control/` 按状态、服务、窗口、布局、preload 与渲染资源拆分：

| 文件 | 职责 |
| --- | --- |
| `control-service.cjs` | 主进程分别查询两个世界；聚合显示、控制请求、账号切换、隐藏与托盘重开 |
| `control-status.cjs` | 验证 RPC 状态并投影浮窗显示内容，不向窗口发送会话内部标识 |
| `control-window.cjs` | 原生独立窗口、固定 IPC、来源校验、置顶、显示时机、资源及监听清理 |
| `control-layout.cjs` | 工作区边界及位置／置顶偏好读写 |
| `control-preload.cjs` | 仅暴露状态订阅和固定控制动作 |
| `control.html`、`control.css`、`control-renderer.js` | 本地静态界面、CSP、按钮状态和原生拖动区域 |

主进程复用既有 `createRealmRpc`，能力令牌和 Core 账号凭据不进入浮窗渲染进程。浮窗启用 sandbox、contextIsolation，关闭 nodeIntegration；IPC 必须来自该窗口，不允许其他渲染器借用其控制入口。窗口内容使用 `textContent`，不将应用标题解释为 HTML。主进程认证广播也跳过此独立窗口。

两个世界分别轮询，慢服务不会阻塞另一世界的显示和更新。账号切换后丢弃旧账号任务标题和延迟回执；控制开始后丢弃旧状态轮询回执。控制失败不会向另一世界自动重试同一变更。

悬浮窗服务与提醒服务共同在主 React 界面首次绘制完成后启动，避免重新引入辅助窗口过早绘制的问题。托盘打开是显式用户操作。桌面 preload 声明悬浮窗能力，Web 控制组件据此停止页面内渲染和轮询，避免重复显示；旧桌面壳和浏览器继续使用原有页面内控制。

桌面发行脚本原有的 `desktop/src` 整目录复制会包含这些 HTML、CSS、JS 与 preload，不新增下载或美术资源。位置文件沿用桌面偏好文件的写法；读取异常回到默认位置，不改用户任务和数据库。
