# 共享资料库局域网直连与设备配对

日期：2026-10-06。用户明确目标为“每台电脑保留自己的 Core，直接在局域网发现设备、配对并共享目录”。本轮贯通 DLC、Agent RPC、本机账号生命周期与方案 B 页面，没有以界面模拟替代传输。

## 当前链路

每个已登录本机账号拥有独立 LAN 身份、监听器和资料库目录，所选工作区的同步引擎共用该账号运行时。Core 仅参与本机既有账号校验，设备间不交换 Core Token，不使用其他 Core 的用户 ID。每台电脑可以发布资料库，创建方作为该库的版本服务；没有统一 Core 或全局共享服务器。

一个资料库仍只有一个发布设备，持久存储版本、内容和设备授权。发布设备离线时，其他设备继续使用本地副本，修改进入 outbox，恢复后提交；没有离线发布方选举、第三方中继或多主一致性。当前仅支持局域网 IPv4。

## 实现

- `DLC/SharedWorkspace/lan/` 提供设备身份、配对、发现、认证加密 HTTP、SQLite 版本服务和同步引擎 Remote 适配，无新增 npm 依赖。Node 22 使用原生 TypeScript 类型剥离，生产代码不使用参数属性等运行时 TS 特性。
- UDP `239.255.73.42:40196` 每十秒发送签名身份，过期/无效广播拒绝，已配对设备按公钥核对发现地址。随机 TCP 端口与 Core 独立。只接受私有 IPv4 字面地址，拒绝公网、任意域名和重定向；发现不可用可填写配对地址。
- 十分钟、一次性随机邀请以 Ed25519 身份和临时 X25519 密钥完成配对。HKDF 派生设备间密钥，AES-256-GCM 加密请求与响应，认证上下文包含双方身份、请求 UUID、时间及方向；限制重放、时间、消息大小、并发与超时。验证覆盖篡改和重放，不声明经过外部密码学审计。
- 资料库 owner 为本机发布身份，editor/viewer 只授予已配对设备 UUID。配对不授予文件权限；撤销配对清除密钥、本机资料库授权和对方目录缓存，已下载资料保留。内容异步读取/保存后重新检查启用与权限。
- 复用原有路径校验、16 MiB 文件限制、内容快照、条件提交、操作幂等、持久队列、冲突、历史与备份。V2 使用账号 `shared-workspace-lan/` 数据层，不读取或删除旧中心 `shared-workspace/` 与 `Data/SharedWorkspace/server/`；权限和绑定需重新明确设置。
- Agent `SharedLanOwner` 是账号 LAN 的唯一所有者，文件夹服务不各自监听。最后一条已验证账号连接退出时停止网络与同步；工作区写入仍经过既有锁和取消机制。RPC 真源为 `packages/api`，已重新生成前端客户端；动态加载要求 `workspace.sync.v2`、LAN 协议 2 和真实工厂导出，拒绝回退到旧中心。
- Core 的可选加载器遇到 LAN 协议 2 清单直接跳过旧 Django app；旧协议实现保留维护，不迁移真实 Core 数据库。
- 方案 B 页面增加配对邀请、发现设备、手动地址、发布方与离线状态；权限改为已配对设备选择。账号、目录或视图切换后丢弃迟到邀请，创建和配对不自动绑定文件夹。一个绑定库的权限查询失败时，已成功读取的本机发现与配对信息仍更新；后台读取继续保留输入和焦点。
