## QQ 可用性及错误结果

- `ownerQqTarget` 先解析当前账号的管理摘要、默认机器人和私人接收目标，再检查 BotCore 连接。连接已建立时，查询当前账号的机器人摘要，按管理摘要的 Core 记录 ID 精确匹配机器人，并核对其 `status=online`。BotCore 的 WebSocket 连接本身不再被视为 QQ 账号在线。
- `list_contact_channels` 区分 `configured`、`online` 和 `readiness`。机器人离线、状态缺失、当前机器人未出现在摘要中、查询失败时，均不会声明 QQ 可发送；状态无法取得保留为未知，配置本身仍可保留。
- 新文本投递在持久化意图及 POST 前预检，文件上传在持久化意图后、实际上传前预检。已知成功的相同请求仍返回原回执，机器人随后离线不会使其再次发送；未知回执继续禁止自动重发。审批、文件快照和目标变更校验仍生效。
- App 自动发现唯一机器人后，实际 NapCat 读写操作会拒绝离线目标；能力目录和已有事件查询仍可读取。显式选中的机器人和 QQ 绑定会话继续由 Core 校验实际在线状态，业务失败会正确映射。
- 四个 NapCat 工具增加明确的结果契约：`success/selection_required` 为调用完成，`failed/not_configured` 为失败，其余为未知。读写工具的契约版本更新为 v2。通过真实 runtime 适配器与录制模型验证，正文 `failed` 不再进入 `completed` 审计。
- Core HTTP 拒绝及业务失败保留有限的 `message/detail/error/code` 原因，并进行凭据和 Bearer 脱敏。只保留诊断字段，不拼接整个收件人、请求或供应商回执。无法确认的网络/投递结果继续保留未知。

主要代码：`Server/src/modules/mon/qq-bot-readiness.ts`、`qq-contact.ts`、`contact-delivery.ts`、`contact-failure-reason.ts`、`napcat-outcome.ts`、`napcat-tools.ts`、`napcat-client.ts`、`qq-file-delivery.ts`、`qq-file-repository.ts` 和 `model-binding.ts`。

## 桌面结果确认及暂停原因

- 原生回执区分部分送达、无法验证、未观察到变化，保留安全错误码和公开枚举事实；不把原生句柄、进程 ID、控件令牌或原始驱动 JSON 暴露给模型。
- 替换、点击、插入、按键等走普通输入执行路径时，若驱动结果为 `unknown/delivered`，补充一次只读窗口观察，结果携带新截图及新控件引用。不给未知输入增加自动重放。窗口管理、启动和跨窗口拖放仍遵循原路径。
- 替换文本只有在前后完整观察均为唯一启用的 `Edit/set_value` 控件、输入指向该控件、窗口标题和标签一致、读回文本精确匹配时，才确认直接替换结果。歧义、多编辑框、截断、插入操作或观察失败均保留不确定状态。此规则不代表 QQ 富文本编辑区已经实测支持，也不代表整个任务已完成。
- `desktopStatus` 新增可选控制事件：动作、来源、时间、说明。区分手动控制、物理输入接管、全局停止快捷键、观察器退出、取消看门狗、旧格式状态和状态文件损坏。持久化并在新桌面服务恢复；旧记录来源标为未记录，不倒推为用户手动暂停。
- 原生独立控制窗与浏览器控制条显示具体暂停/停止原因；双世界汇总优先采用最新控制事件，防止旧世界的暂停快照覆盖之后的恢复。兼容没有原因字段的旧服务。

主要代码：`packages/api/src/desktop-control.ts`、`Server/src/modules/desktop/{native-driver,action-confirmation,window-targets,input-arbiter,input-observer,broker-server,desktop-executor}.ts`、Electron `desktop-control` 服务及渲染器、Web `DesktopControlBar.tsx`。中文模型工具说明同步更新，观察后的旧控件引用不可继续使用。
