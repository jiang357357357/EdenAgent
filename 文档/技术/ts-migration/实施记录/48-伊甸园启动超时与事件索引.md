# 伊甸园启动超时与事件索引

2026-09-11，用户报告 `npm run dev` 中 local 就绪而 mon 健康检查超时，要求定位修复。

## 定位证据

- 启动脚本原先最多轮询 100 次，每次间隔 100ms；连接立即拒绝时约 10 秒即失败，错误没有保留请求失败原因。
- 本机 Mon 数据库仅以 SQLite readOnly 模式读取计数、查询计划和耗时，未启动用户宿主、未修改用户数据、未复制真实库作为测试夹具。约 791 MB、89,910 条事件；Local 事件表为空。
- 事件表只有主键和 `(session_id,seq)` 唯一索引。恢复使用的按轮次/类型过滤查询实际只能按 session_id 扫描；30 次回复查询合计约 4,094ms，单次最慢约 3,016ms。
- 初始化在 HTTP 监听前恢复历史记忆；缺失索引和短启动窗口是已确认的性能与诊断问题。原始失败没有阶段日志，不能据此断言排除了其他初始化耗时。

## 实现

- store 追加 schema 迁移：`events(session_id,kind,seq)` 与 `events(session_id,turn_id,kind,seq)`，支持会话元数据/响应和记忆恢复查询。通过正式迁移执行，不直接修改生产库。
- 记忆回复读取使用迭代器，找到对应角色最近有效回复即停止，避免先加载全轮次消息。
- 健康检查改为 60 秒墙钟截止时间，单次请求和重试间隔受剩余时间限制；保留世界、端点、退出状态、响应身份或请求失败原因。
- 宿主输出 `server.startup` 阶段与累计耗时，不输出配置、凭据或消息内容。恢复仍在接收业务前完成，不跳过失败边界。
