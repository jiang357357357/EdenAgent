# 160 — 高频流式写入与长历史阻塞修复

日期：2026-10-03。依据用户提供的《工作日志-EDEN智能体故障修复-2026-10-03.docx》排查，用户随后明确要求找到问题并修复。本轮修改源码、补充回归；未修改真实用户数据、重启用户服务、打包发布或提交推送。

## 问题定位

工作日志记录旧客户端主会话约 19.2 万条事件、流式中间事件占绝大多数，完整回放期间健康探针超时，同时存在空参与者向 Core 投影失败。本地源码已有差分存储、账号校验后的持久事件补发及前端重连恢复，但仍存在以下负载来源：

1. 每个 SDK 流式更新都会创建连续序号，并进入 SQLite `synchronous=FULL` 同步事务。差分压缩减少正文大小，没有减少事务和事件行数。
2. 历史 `event.list` 在一次同步调用中读取并还原整页；实时补发的每次读取使用独立还原缓存，重复恢复差分链。
3. Core 同步读取并还原全部中间更新，再跳过不需要投影的事件，而且逐条更新进度。空参与者仍会发往 Core，产生可避免的错误投递。

日志中 `mon_projection_outbox=unknown` 与 Legacy 身份错误不是同一个状态域。Legacy 拦截检查 `legacy_core_identities` 和 `legacy_core_outbox`；此次保留该检查，没有把旧状态改成成功。

日志里的 `eden-bridge/lib/eden-rpc.mjs` 和 `ask-dsh-service/server.mjs` 不在当前工作区，本轮修改的是 Agent 宿主的对应故障路径，没有声称验证了外部桥接部署。

## 实现与失败行为

| 模块 | 输入、状态归属及结果 |
| --- | --- |
| `sessions/turn/stream-coalescer.ts`、`runtime-callbacks.ts` | 每个 runtime callback 实例持有一个待合并快照。同一消息、角色、delta 类型和内容块的 text/thinking/toolcall 更新，在分配事件序号之前合并；首条立即持久化，持续更新时约 100 ms 采样，完整快照深拷贝且累计 delta 字符串。非 delta 事件原样经过；每 32 次快速更新让出事件循环。 |
| 流生命周期与副作用边界 | 消息结束、错误、模型请求/响应、checkpoint、工具开始/结束等边界先 flush。没有后台写库 timer，因此正常结束/取消后没有迟到写入。存储失败进入 sticky 失败状态，清空待写数据，后续工具 intent 在写入和外部副作用前拒绝。 |
| `sessions/event-read-cache.ts`、`session-events.ts` | 差分还原复用按 sessionId+seq 定位的 LRU，最多 256 个条目、8 MiB 序列化内容；这不是进程总内存上限。读取前校验归属、返回深拷贝；同连接写入、外部连接修改、事务状态变化使缓存失效，缺失/损坏基底仍报错。 |
| `session.routes.ts`、`websocket/upgrade.ts` | `event.list` 使用固定序号上界，每 25 条让出事件循环，保留原分页、序号和协议；每条 WebSocket 的生命周期 signal 传入读取，连接关闭时停止后续批次。普通聊天仍使用最终消息分页。 |
| `mon/session-projection.ts` | HTTP 和 outbox 之前验证当前会话的 Core 助手：1–8 个唯一正整数，兼容数字字符串。普通空草稿仍合法；需要同步时给出可恢复的配置错误，不借用其他会话或账号的参与者。投影时间来自语义事件。 |
| `mon/sync-worker.ts` | 数据库先筛选需要投影的会话/最终消息/导演事件；忽略的流式行不再还原。成功批次仅推进一次游标；失败不推进，已成功交付的 outbox 保证重放幂等。参与者待配置时不递增重试、不新增 unknown，配置变更后重新同步。 |

没有删除历史或重新编号。直接删除中间事件会破坏连续补发游标和已有差分 `baseSeq` 引用，不能照搬日志里的 SQL 清理作为通用修复。

采样由下一个事件触发，没有 timer；供应商中途停流时，最后待合并的中间快照会等待后续事件或结束/取消边界，不能承诺停流后 100 ms 内必定广播。进程被强制终止时，未持久化的中间快照可能丢失；已落盘事件及完整结束消息的协议保持不变。

## 实际验证

以下使用 Node **22.23.1**，临时 SQLite、本机 HTTP/WebSocket 和本地录制模型；没有访问真实供应商或用户数据库。

| --- | --- |

## 交付范围

本轮降低后续流式事件写入频率，改善历史读取与同步时的并发响应，没有建立自动历史保留/删除策略，也不承诺数据库长期大小固定。旧 `unknown` 投递和 Legacy 重绑定需要按其真实交付状态处理，未盲目清除。真实 Electron UI、真实模型供应商及长期浸泡未验证。
