# 请求前自动压缩链路

2026-09-12，用户要求接入达到上下文上限前的自动压缩。

## 实现与触发条件

runtime-pi 在公开 context 钩子中逐次检查即将发送的对话，覆盖首次/恢复请求和工具结果后的下一次请求。阈值为：

`输入预算 = contextWindow - maxTokens - max(512, contextWindow × 5%)`

计算包括系统提示、工具定义、动态工具提示、对话和临时输入；文字按中文字符与其他字符保守估计，图片按每张 8192 token 的预留估计，不把 base64 长度当作实际图片 token。此为宿主启发式预算，不能保证与所有供应商 tokenizer、图片计费及协议封装一致。

超过预算时先总结历史，再发送原请求。最后一条待回答用户消息保留原文；工具执行后的上下文可总结已执行操作与回执，然后继续模型循环，不重放工具。较大的单条历史消息以 Unicode 字符边界分段总结，完整保留分段输入而不静默截断；摘要迭代请求最多 32 次，并共同计入回合原有模型请求预算。

自动摘要使用公开 generateSummaryWithUsage API，使用当前会话已绑定的模型与鉴权，禁用重试，要求中文简洁记录任务、约束、已完成操作及待办。摘要与保留尾部通过公开 Session.appendCompaction 写入持久化检查点，保存成功后发布 session_compact 事件并继续。不存在历史数据库原地改写。

临时角色交接输入参与容量预算和当前请求，但排除于持久化摘要与 retainedTail。短对话手动 /compact 功能不加限制。

## 故障行为

- 系统提示/工具本身已占满预算、当前单次输入过大：明确失败，不通过删除用户输入绕过上限。
- 空摘要、压缩后未缩小或仍超过预算：不写入新压缩检查点，停止当前请求，保留历史。
- 取消、模型失败、持久化失败：停止后续请求；执行账本与原始事件保留，不重放已完成副作用。
- 自动压缩开始和失败均产生运行时事件；成功附带 automatic 与同口径宿主前后估计，前端显示“自动压缩上下文”及真实保存摘要。
- 当前是请求前预算检查，不增加供应商超限报错后的自动重试。若供应商真实计数与宿主估计存在较大差异，仍可能返回超限错误；需依实际报错继续校准，不宣称已保证所有模型绝不超限。
