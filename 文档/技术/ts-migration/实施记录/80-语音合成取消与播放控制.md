# 语音合成取消与播放控制

日期：2026-09-14。

## 问题与行为

聊天及桌宠在语音合成期间只显示不可点击的等待图标，同时隐藏播放控制；前端取消队列也没有逐请求通知服务端。服务端 WebSocket 串行等待合成响应，使新增取消 RPC 排在合成之后。

合成期间现在显示“取消本条消息的语音合成”按钮。已开始播放时同时保留暂停、恢复按钮；暂停只控制播放，合成继续。取消按消息停止合成、清除该消息待播放任务并停止其当前播放，抑制后续流式文本重新自动触发该消息合成。之后可手动重新播放/合成。

## 实现

- API 新增可选 requestId 和 voice.tts.cancel，旧调用仍可合成；取消使用 sessionId 与 requestId 定位。
- SynthesisJobs 独立管理任务及请求者。共享缓存键的请求复用上游工作，最后一个请求者取消后才中止上游；迟到结果不能移除新的重试任务。
- 前端 AbortSignal 转换为取消 RPC，固定使用发起合成的连接。消息代际检查丢弃迟到结果，取消当前消息不清空其他消息队列。
- 已初始化连接的语音合成及取消独立调度，避免互相阻塞；仍经过同一 RPC 校验并受连接请求数量限制。其他方法保留串行调度。
- 聊天和桌宠使用同一语音 hook，按钮调用同一取消路径。已重新生成 RPC 制品。

## 验证

使用临时目录、内存数据库及本机 HTTP 合成桩，无真实用户数据库及付费模型调用。

- 服务端专项与附件 RPC 回归 5/5：共享请求分别取消、最终上游中止、重试与迟到结果、实际 HTTP 断开且未持久化语音结果、真实 WebSocket 上两项共享合成与取消/普通请求并行处理。
- 前端取消请求、调度队列、播放门控 16/16；聊天组件服务端渲染按钮状态 2/2。
- 服务端及前端类型检查、服务端和 Web 构建通过。
- 架构门禁仍有两项既有 Mon 模块错误：model-binding.ts 复杂度 16，model-catalog.ts 复杂度 18；本次修改未新增架构错误。
- 日志：`.artifacts/speech-cancel/`。

尚未在当前运行的桌面窗口人工点击验收，也未重启或更新安装版。已验证取消会关闭上游 HTTP 请求；供应商收到断开后是否立即停止内部计算取决于其服务实现。
