# 工具参数根结构导致会话排队中断

日期：2026-09-13

## 问题

用户消息显示“已排队”，但模型没有开始回复。Mon 宿主健康状态同时报告 `sessionFaults: 2`，对应输入最终记录为 `interrupted`，错误为 `Tool parameters must have an object root`。

新增的 `control_esp32_device` 使用 Zod 判别联合生成公开 JSON Schema。生成结果以 `anyOf` 为根，没有模型工具协议要求的根级 `type: object`。运行时在组装模型工具目录时会校验全部工具，因此即使本轮不调用该设备工具，也会在模型请求发出前终止整轮执行。

## 修复

- 将 `control_esp32_device` 的公开参数 schema 改为单一对象根，列出动作及其可用字段。
- 执行阶段继续使用严格判别联合校验，保持每种动作的字段约束和拒绝未知字段行为。
- 运行时 schema 错误加入具体工具名，后续故障可以直接定位来源。
- Server 创建服务时检查完整工具目录。静态内置工具出现非法根结构时，服务会在启动阶段明确失败，不再等到消息入队后才中断会话。

## 验证

- ESP32 工具、工具命名和模型目录相关专项 11/11 通过。
- runtime-pi 工具适配与动态刷新相关专项 6/6 通过。
- 服务端 TypeScript 类型检查及差异格式检查通过。
- 开发运行时重启成功，Mon 健康状态 `sessionFaults: 0`。
- 真实运行目录包含 58 个工具，非法对象根数量为 0。
- 使用当前 Core 登录和 Mon 模型绑定执行临时真实会话，模型请求以 `turn.completed` 完成且无中断原因；临时会话随后删除。

原故障输入保留为 `interrupted` 审计记录，重启后不会继续显示为正在排队或自动重复执行。
