# 可选共享资料库反复恢复警告

日期：2026-10-06。模块：共享资料库发现与账号连接后台恢复。

## 原因与行为修复

桌面 `createDesktopReminderService` 的默认轮询周期为 5000ms，`createRealmRpc` 每次请求创建控制 WebSocket、完成 initialize 后读取提醒并关闭连接。服务端在非会话连接的账号认证成功后执行 `sharedWorkspace.attach`；原实现每次 attach 都排队恢复共享目录，并用抛异常的 `requireInstallation` 检查 DLC。因此没有可用共享资料库时，即使只是正常读取提醒，也每 5 秒打印恢复失败 WARN。

现场只读发现结果为：源码 DLC 目录存在，`E:\EDEN\.run\dlc\state.json` 不存在。原发现代码直接读启用文件，ENOENT 被外层归类成“共享资料库 DLC 未安装或配置无效”；它应保持默认禁用，并显示“尚未启用”。

修复内容：

- `discovery.ts`：无启用状态文件时返回未启用；真正损坏的 JSON 配置仍报告不可用，未自动创建启用记录。
- `service.ts`：attach 在 DLC 不可用时只暂停同步，不启动客户端、不排队恢复注册表；已经排队的恢复在执行前再次检查可用性。
- 保留认证凭据租约，以便之后启用时由新连接恢复现有注册目录；没有改变账号隔离、权限或显式共享操作的可用性校验。
- 有效 DLC 的注册表损坏、目录缺失等真实恢复异常继续报告，不按字符串屏蔽警告。
