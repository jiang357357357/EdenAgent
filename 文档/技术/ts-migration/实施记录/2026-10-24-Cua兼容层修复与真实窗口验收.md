# Cua 兼容层修复与真实窗口验收

后续结果契约和在线 broker 已由[桌面派发、核验与模型结果修复](2026-10-24-桌面工具派发核验与模型结果修复.md)更新。下文 85 项回归、8 组验收、旧字符串 verification 与 PID 属于本轮之前的历史证据；驱动 unverifiable 继续保留，但新的宿主结果会分别说明派发和核验，不再一律记为调用未知。

日期：2026-10-24。范围：桌面模块、Cua 独立工作进程、Windows 输入观察器、内置技能和发行依赖。用户已授权修复并进行真实测试。

## 已确认的原因与修复

1. **纯坐标调用附加了元素快照。** Eden 给 `x/y` 点击也加了 `snapshot_id`，而固定版本 Cua 0.28.0 的元素参数解析器明确拒绝没有索引或 token 的快照，返回 `element_index_required`。现在截图引用继续在宿主验证，但只有元素操作向驱动附加元素快照；坐标、拖动和无元素按键不附加。
2. **内嵌 SDK 继承 Node 的 DPI 虚拟化。** 在当前 Windows 125% 缩放下，用未经初始化的 SDK 和自有 WinForms 窗口实测：物理屏幕为 `1920×1080`，SDK 返回 `1536×864`；请求可见边界 `(320,180,640,460)`，应用自身读回 `(378,195,679,472)`。现在专属 `cua-worker` 在加载 SDK、创建原生线程和窗口前，通过固定依赖 `koffi@3.3.3` 设置并验证进程和当前线程的 PMv2 DPI 上下文。只配置该独立进程，不修改客户端、Server 或系统 DPI；初始化失败明确返回 `CUA_DPI_CONTEXT_UNAVAILABLE`，不启动驱动。
3. **兼容结果丢弃官方错误正文。** 新增有界 `driverMessage`，保留原始拒绝原因；保留结构化拒绝码和升级建议，并穿过 worker 校验及兼容结果诊断。诊断中的原生寻址句柄、元素快照和内部会话名称不作为模型业务引用发布。官方错误正文不被统一中文兜底替代。真实最大化窗口调整现在能返回 `is maximized; restore it before setting its frame`。
4. **窗口边界缺乏独立核验。** 观察器新增 DWM 可见边界；`resize` 参数表示物理像素下的可见窗口边界，不含不可见的缩放边框。操作后独立读回，返回 `requestedBounds`、`observedBounds`、`windowFrame` 和 `verification`。不匹配或读回失败保持 `unknown`，不能按驱动声称成功直接标记完成。任何窗口操作都会使旧输入观察失效。
5. **拒绝后的观察与引用恢复不完整。** 明确拒绝也会尝试重新观察并返回新引用，保留原失败状态，不重放输入。跨回合或服务重启后的旧窗口引用仍按原作用域失效，但错误明确提供 `desktop_list_windows`、`desktop_observe` 恢复步骤，不按同名窗口猜测重绑定。技能补充新观察引用、可见边界、原始错误和恢复流程。

`background_unavailable` 仍代表实际投递限制；`unverifiable`、`partial` 和未知输入结果继续保留。点击是否生效由后续状态判断，不因为增加读回就把所有未知结果改成成功。

## 真实测试及证据

真实验收使用临时目录、内存 SQLite、真实权限工具入口、独立 broker、正式 Cua worker/SDK/原生库和自有 WinForms 应用。应用自行记录文字、点击计数及 DWM 边界，作为独立判据；没有用工具返回成功替代实际效果。全部输入只发送到唯一名称的测试窗口，另一个窗口用于核对没有错误输入。

固定 Node `22.23.1`，SDK `0.28.0`，实际 Windows 显示缩放 `1.25`：

| 真实验收组 | 结果 |
| --- | --- |
| SDK 屏幕与物理观察器一致 | `1920×1080`，比例 `1.25` |
| 两次移动和缩放 | `(240,160,620,440)`、`(360,200,560,420)` 均由应用读回精确匹配 |
| 最大化窗口拒绝与显式恢复 | 保留官方具体错误；恢复后继续观察 |
| 元素点击 | 应用计数恰好增加一次 |
| 截图坐标点击 | 不再触发 `element_index_required`；应用计数恰好增加一次 |
| 原生 `cua_*` 元素点击 | 原生公开引用和私有快照有效；应用计数恰好增加一次 |
| 新回合旧引用及重新发现 | 旧引用被拒绝，重新发现后恢复；没有猜目标 |
| 替换文字及前台插入 | 文字精确落地且只插入一次，另一测试窗口未改变 |

点击的部分官方回执仍为 `unknown`，但应用计数确认实际生效。这是保留驱动能力边界的预期行为。窗口截图可以不含不可见边框，不能断言 PNG 尺寸必须等于 `GetWindowRect` 外边界。

桌面自动化回归 **85 项通过**；普通测试入口另跳过 1 个需显式授权的真实窗口父测试。真实入口的 **8 组检查全部通过**（Node 报告包含父测试共 9 项）。技能测试 2 项、搬迁制品测试 1 项及依赖计划测试 2 项通过。Server 类型、构建和全仓架构检查通过，架构检查 1313 个源码文件、0 错误。搬迁制品包含 Koffi 及对应平台原生依赖，在独立目录真实启动 worker 并加载官方 SDK，无需外置 Cua 安装。
