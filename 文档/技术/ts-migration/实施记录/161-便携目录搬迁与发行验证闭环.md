# 161：便携目录搬迁与发行验证闭环

日期：2026-10-03。

## 问题与处理范围

源码中的工作区选择修复已在[实施记录 158](158-工作区搬迁与账号启动恢复.md)完成，但本机正在运行的 Windows 便携包仍使用旧 Agent 制品。手动修正某个账号的 `workspace.root` 只能恢复该安装，不能证明分发给另一台机器后可用。

本轮补齐桌面默认数据位置、整包搬迁验收和分发检查。没有编译新版本、替换运行中的制品、提交、推送或发布；没有把真实用户数据库作为测试夹具。

## 运行时约定

- 默认账号工作区保存 `managed/default` 逻辑选择，启动时根据当前账号数据目录推导实际位置。整包移动后随新位置解析。
- 用户主动选择的项目保存为 `external`，保留原路径。来源不明的历史绝对路径同样保留；路径失效时账号仍可初始化，用户可重新选择或回默认目录。不会按路径后缀猜测并改写用户项目。
- 便携桌面在创建服务、配置和 Electron 会话前，把 `userData`、`sessionData` 定位到当前包的 `Data/Desktop/Agent`，默认尘世数据库和模型配置因此一起搬迁。独立安装与开发模式保持原行为。
- 数据路径不可写、被普通文件占用或经 junction/symlink 重定向时，桌面明确报错并停止，不回退到全局配置。不会自动导入其它安装的全局 profile；显式外部数据环境变量仍保留原合同。

## 分发检查

根脚本 `package_state.py` 提供统一只读检查。`assemble.py`、`refresh_core_candidate.py`、`prepare_release.py` 与 `verify_candidate.py` 共同拒绝非空私有 ENV、用户 Data、数据库及旁路日志文件、令牌、私钥和重定向目录。公开模型和地点资源仅允许在约定位置，其内容仍由资源清单验证。合法的源码/依赖 `data` 目录不按用户 Data 误判。

`prepare_release.py` 的默认及 `--validate-only` 模式均不删除文件。当前加入 DeepSeek 测试配置且已经登录的 `EDEN-portable/EDEN_win` 是运行副本，不能直接作为客户包归档。

`workspace_artifact.test.mjs` 支持 `EDEN_AGENT_ARTIFACT_ENTRY` 与 `EDEN_AGENT_ARTIFACT_REPORT`，在临时副本中执行旧工作区恢复、默认目录整体搬迁、显式外部目录保持三类检查。所有场景和进程/文件清理成功后才生成报告；测试开始时移除同目标旧报告，失败不能遗留旧的通过状态。

报告绑定实际 Server `main.mjs` 与执行测试的 Node 22.23.1 SHA-256。全量组装要求 `--agent-relocation-report`，包内保存为 `runtime/agent/relocation-verification.json` 并记录在 `BUILD-INFO.agentRelocation`。复用与最终审计重新核对独立运行时和桌面内嵌的 Server/Node，缺报告、报告失败或字节变化均拒绝。报告证明这组制品通过了指定行为测试，不代替源码提交来源证明或完整客户验收。

## 验证结果与交付边界

- Server 工作区定向回归：22 项通过；覆盖完整临时便携目录搬迁、多个账号与显式项目保持。
- Desktop 相关四组测试：39 项通过；包括中文空格路径、整包移动、旧全局 profile 不导入，以及 `Data`、`Desktop`、`Agent` 三级真实 junction 拒绝。
- Windows 组装、复用、隐私和报告检查：47 项，46 通过、1 跳过。跳过项为本机没有创建文件 symlink 的 Windows 权限；真实 junction 的根、子目录及祖先路径检查通过。复用测试使用真实 7-Zip 临时归档。
- 已有 `Agent/dist/server/main.mjs` 的独立进程制品验证：2 项通过，覆盖报告要求的三类场景；两次整包改名后旧目录不存在，账号会话和原文件可读，健康检查通过。
- 候选运行时漏打依赖的回归：1 项通过；显式候选必须使用自带 `node_modules`，不能偷偷从源码补齐。仅开发用的精确 `Agent/dist/server/main.mjs` 位置允许源码依赖回退。
- 旧便携制品负验证：临时程序副本复现旧路径 ENOENT 和缺少 managed 信息，2 项预期失败、进程返回 1；事先放置的旧通过报告被移除，没有产生新通过报告。没有启动实际用户安装。
- 当前用户运行目录只读预检：因私有运行状态被拒绝作为分发源，旧 Agent 也因缺少匹配报告被拒绝复用；没有输出配置内容或修改任何文件。
- Server TypeScript 类型检查通过。未执行新制品构建、可见 Electron 客户流程或最终完整发行包验收。

Python 使用 `Core/.venv/Scripts/python.exe -B`，Node 使用固定 22.23.1；测试服务均监听临时本机端口，没有外部联网或代理。Python 合跑最初因旧 `test_assemble.py` 使用顶层导入而失败；补充测试进程的脚本目录 `PYTHONPATH` 后上述六组全部完成，没有改动测试断言或降低门禁。
