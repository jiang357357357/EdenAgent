# 工具业务 ID 与内部标识边界排查

日期：2026-10-11。

更新：2026-10-16 用户授权全面落实。下方初次排查与“待修复”表保留为历史；本次已在当前源码加入工具目录统一登记、各域最小结果视图和历史上下文投影，覆盖表内已确认的宿主包装路径，尚未进行本批行为测试。长期记忆先前已采用最小模型视图，本次纳入统一目录和历史处理，不再列为当前未改造项。当前范围、失败行为和待验收项以[实施跟踪 2026-10-16 批次](../../Eden%20Agent%20TS%20迁移实施跟踪.md)为准。

用户要求检查 QQ 以外的工具是否也向模型返回内部标识，并明确规则：正常业务 ID 可以让智能体知道，其他内部标识不应进入模型。当前多处工具把宿主记录直接作为模型结果返回；应建立独立模型视图，保留正常业务 ID，移除仅供宿主运行的技术字段。以下新增项登记为待修复；已有 QQ 修复见 [QQ 平台标识与模型结果隔离](2026-10-11-QQ平台标识与模型结果隔离.md)。

## 按用途区分标识

| 类别 | 示例 | 模型边界 |
|---|---|---|
| 正常业务 ID | QQ 号、群号、机器人 ID、设备 ID、状态查询的命令 ID、子任务 ID、记忆/备忘 ID、附件 `blobId`、连接器 ID、网页 `refId` | 在当前授权范围内保留，用于选择或操作明确的业务对象。UUID 或名为 `id` 的字段不自动属于内部标识。 |
| 宿主内部标识 | 请求追踪号、回合/工具调用号、幂等键、审计关联、仅供归属校验的会话关联、内容哈希、快照修订号、执行代际 | 保存在宿主，不进入模型工具结果、宿主提示上下文或恢复给模型的历史副本。 |
| 内部平台标识 | 已确认为 QQ 平台实现细节的 `tid`、消息/文件/目录/申请标识 | 原始值留在审计及私有关联；后续操作使用有账号、会话和目标作用域的业务引用，执行前由宿主还原并审批。 |
| 明确的历史版本选择 | 插件安装或回滚选择的制品版本 | 属于业务选择时可以保留；普通工具调用不要求模型照抄当前内部哈希或执行快照。 |

同名字段必须结合具体工具判断。例如 `commandId` 用于查询设备命令状态，是正常业务 ID；`request_id` 用于宿主幂等和追踪，应隐藏。附件的 `blobId` 用于读取附件，可以保留；`sha256` 由宿主检查完整性，不需要交给模型。会话 ID 若服务于明确的跨会话业务操作，可定义专门的输入输出和权限；当前结果中只用于内部关联的根会话、子会话和来源会话字段应省略。

内部字段分类不改变 SDK 协议元数据。宿主继续保存历史树节点和工具调用配对关系，模型结果投影不应破坏协议关联。用户文件、网页正文和第三方业务内容中的任意数字或 ID 不应被无差别替换。

## 已确认的返回路径与待修复项

下表均为现有源码返回路径，状态为待修复；正常业务 ID 与需隐藏的内部字段分别列出。

| 工具或模块 | 正常业务 ID 或结果 | 需隐藏的内部字段及入口 |
|---|---|---|
| `send_external_email` | 渠道、是否接受、重复投递事实和已读限制说明 | `mon/contact-delivery.ts` 返回 `requestId`；`mon/contact-tools.ts` 的邮件工具没有模型投影。请求号由回合和调用号组成。 |
| `control_esp32_device`、`get_esp32_command_status` | 设备 ID、供状态查询的命令 ID、动作、命令及通话状态 | `mon/model-binding.ts`、`mon/esp32-command.ts` 直接返回 Core 结果。配套 Core 的 `Application/Domain/Agent/Devices/serializers.py` 明确包含 `request_id`。 |
| `set_self_awake_timer` | 实际安排时间、时区、调整原因及业务需要的任务 ID | `self-awake/timer-receipt.ts` 展开整个 `JobInfo`，带出 `key`、`causationId`、内部 `sessionId`、`inputId` 等字段。 |
| `run_skill_tool`、技能直达工具、`create_skill` | 技能名称、业务输出、创建内容及结果 | `skills/code-execution.ts` 返回内容哈希 `revision`；`skills/tools.ts` 创建后返回完整安装描述，包含 `contentHash` 等宿主快照字段。技能发现和加载已有最小视图，应复用该边界。 |
| `query_shared_workspace`、共享写入/编辑 | 所选目录、业务资料库/文件对象、路径、内容及同步状态 | `shared-workspace/model-query.ts` 返回完整目录快照和文件索引，包含目录/文件 `revision`、`sha256`；`shared-workspace/file-access.ts` 写入结果还带文件哈希。正常对象 ID 按实际业务用途保留。 |
| `read_attachment` 列表 | 当前输入附件 `blobId`、文件名、类型和长度 | `attachments/tool.ts` 返回完整附件快照，包含 `sha256`；读取功能仍需保留 `blobId`。 |
| `show_desktop_reminder`、`get_desktop_reminder` | 可查询的提醒 ID、标题、正文和真实状态 | `notifications/repository.ts` 记录中的内部 `sessionId`、`turnId` 被 `notifications/tools.ts` 直接返回。 |
| 子智能体创建/列表/等待及消息读取 | 子任务 ID、路径、角色、状态、结果、必要的发送方业务身份 | `subagents/repository.ts` 带出根/子会话关联、内部协调批次；`subagents/mailbox-repository.ts` 返回 `senderSessionId`。子任务 ID 仍供后续操作使用，发送方可用业务身份表示。 |
| 长期记忆创建/搜索/更新 | 记忆 ID、内容、类别及有业务意义的来源说明 | `memories/repository.ts` 返回内部来源会话 `sourceSessionId`；当前模型工具不通过该字段选择源会话。记忆 ID 必须保留以支持更新/删除。 |
| 连接器发现与事件读取、MCP 服务列表 | 连接器/运行时 ID、宿主事件 ID、声明能力和业务事件内容 | `connectors/discovery-tools.ts` 带出实现 `revision`；`connectors/event-repository.ts` 返回用于去重的原始 `externalId`；`mcp/lifecycle.ts` 列表包含组件修订元数据。不得同时删除正常调用或事件读取所需的 ID。 |

`write_diary`、自醒上下文和最近日记也有运行、日记或会话 ID。它们需要逐字段判断实际业务用途；不能仅凭数据库生成就全部判为禁止字段。

## 第三方结果与现有合规路径

`packages/runtime-pi/src/tool-adapter.ts` 的 `projectResult` 在工具未定义 `modelResult` 时使用原始结果。插件调用、代码技能输出和连接器能力结果通常直接透传业务输出；MCP 的 `mcpModelResult` 目前只替换图片字节，没有通用标识分类。这证明边界尚未统一，并不证明每个第三方结果已经包含不应暴露的 ID。后续应分别审查宿主包装字段和提供方输出契约，保留正常业务标识。

工作区读写工具已经把读取哈希和编辑快照留在宿主；`list_tools`、`load_tools`、`load_skill` 等发现/加载结果使用正常名称和稳定 ID；`request_user_input` 返回业务回答。这些路径不能因为含有业务 ID 而被列为问题。命令 stdout、文件正文和网页正文属于请求读取的内容，不采用按字段名称或文本形状全局删除 ID 的策略。

## 后续实现与验收要求

1. 每类工具定义最小模型结果，明确保留的正常业务 ID 和宿主专有字段；包装层不复用完整管理端记录。宿主审计保持完整，结果状态保持真实。
2. 先处理已确认的请求追踪、幂等、哈希和执行快照泄露，再按业务契约收敛会话关联及第三方包装字段。需要原始内部平台标识的后续操作由宿主引用解析，继续验证目标范围并审批。
3. 修复覆盖工具结果、宿主上下文、已知内部标识的历史恢复和压缩入口；不能仅隐藏前端，也不能靠提示词要求模型不复述。投影失败中断模型执行，不回退原始结果或重放副作用。
4. 验收同时证明内部标识没有进入实际后续模型请求、正常业务 ID 仍可完成选择/读取/修改、原始审计保留、恢复和压缩不重新带入已知内部标识，以及投影失败不会重复外部操作。按当前用途保留的业务 ID 不得被误删。
