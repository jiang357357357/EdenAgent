# 自醒调度文件环境绑定修复

日期：2026-09-27。范围：Mon 服务配置、开发启动器和桌面托管启动器。

## 现象与根因

09-26 23:00 的自醒执行已写入日记，但两次 `set_self_awake_timer` 均返回 `MonOs timer delivery requires scheduleStateFile; local scheduling is disabled`。这轮没有保存下一次自醒作业。日记中写的 09-27 06:30 是角色文字，未成为定时请求。MonOs 状态文件中另有 09-27 11:00 的 watchdog 兜底计划，Agent 页面因没有读取状态文件而显示“尚未安排”。

安装版 `run-service.sh` 已将 `MONOS_SELF_AWAKE_STATE_PATH` 传给 Agent 进程。Agent 在显式 `MON_SERVICE_SHARED_SECRET` / `MON_SERVICE_USER_ID` 认证分支直接返回，仅从 `mon-service.json` 读取调度文件，因此丢失了该环境路径。以上依据在线数据库、进程环境和 MonOs 状态文件的只读检查；没有改写在线数据或触发自醒。

## 修正

- 显式环境认证分支读取 `MONOS_SELF_AWAKE_STATE_PATH`，要求非空绝对路径及可读普通文件，并将其交给现有 MonOs 发布和页面状态读取链路。不混合可能属于另一部署的 `mon-service.json`。
- 开发启动器和桌面托管启动器只向 Mon 服务传递该环境变量。
- 更新启动配置说明。此修正只作用于新启动的服务，不会把已有日记中的时间倒推为定时作业。

## 上线前检查

Server TypeScript 类型检查、构建、两个 JavaScript 入口语法检查及静态差异检查通过。首次核对时新服务制品与安装版制品仅有本次配置修复一处差异；安装版服务健康，两个 Mon 数据库均无排队中的自醒作业。当时尚未运行自动化/UI 测试或替换在线制品。
