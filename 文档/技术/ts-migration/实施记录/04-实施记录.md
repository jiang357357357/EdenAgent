## Blob 存储基础

- 新增 API BlobInfo、MIME 校验与数据库第 14 次迁移。元数据 SQL 独立放入 BlobRepository，文件操作与业务服务分别建文件。
- 文件按 SHA-256 派生路径，数据库不接受任意存储路径。内容默认上限 32 MiB；文件写入前校验大小和 MIME，并复制调用者缓冲区。
- 临时文件使用独占创建和 0600 权限，内容同步后以硬链接发布，再提交元数据；并发相同内容去重，沿用旧协议首次 MIME。
  POSIX 同步目录；Windows 不声称具有相同的目录 fsync 保证。数据库提交失败保留不可变内容供重试，不返回伪成功；孤儿文件回收尚未实现。
- 读取限制长度并验证 SHA-256，拒绝符号链接文件。这里不是针对同一 OS 账户并发替换祖先目录的完整 openat 沙箱。
- 专项 **5/5 通过，零失败、零跳过（本次 Linux）**：并发去重、磁盘重建读取、写前校验、调用者缓冲区变更、内容损坏、元数据故障重试及符号链接拒绝。
  类型检查、工程门禁通过（186 个源文件、0 错误）。本批未重复全量宿主测试，上一批全量结果见上文。

  当前尚无可用 Blob HTTP 端点，turn.start 仍明确拒绝附件；不能据此验收聊天附件功能。

## Blob HTTP 与宿主生命周期

- 生产容器创建各自 dataRoot/blobs 下的 BlobService，新增 POST /blobs 与 GET /blobs/:id，兼容现有前端上传/读取地址与 BlobInfo JSON。
  使用当前世界 capability token 的 Bearer 鉴权，常量时间比较；带 Origin 的请求必须匹配 allowedOrigins，不接受 URL 查询令牌。
- 为允许的前端来源处理 OPTIONS 预检，只开放 GET/POST 与 Authorization/Content-Type。预检通过不会豁免后续请求鉴权。
  下载设置 no-store、nosniff、attachment 和限制性 CSP，错误响应不暴露存储路径或损坏内容。
- 新 EDEN_AGENT_MAX_BLOB_BYTES 默认 32 MiB，配置范围 1 字节至 1 GiB。显式 Content-Length 与实际分块接收均检查上限；拒绝压缩请求体。
  上传总时限 30 秒，Blob 请求并发上限 8。当前采用有界内存缓冲，配置大上限时需要相应内存，尚未改为磁盘流式暂存。
- BlobHttp 独立跟踪异步请求。关闭宿主先拒绝新请求、中断未完成的上传并等待文件/元数据操作结束，再关闭 SQLite。

## 附件引用与可持久化快照

- 新增严格 AttachmentRef/Snapshot API schema；turn.start 的 attachments 从任意 JSON 数组改为显式引用，仍由后续未迁移保护拒绝非空附件。

## 当前输入的附件读取工具

- 生产容器注册 eden_attachment，支持 list/read。AttachmentRepository 只查询当前 sessionId/turnId 的 running 输入，且会话必须 active。
  read 的 Blob ID 必须出现在该输入已持久化的附件快照中；不因同一世界曾上传过某个 Blob 就允许任意访问。
- 文本以严格 UTF-8 解码，offset/nextOffset 使用 UTF-16 单位并避免拆开代理对；页上限 16384 单位。请求 1 单位恰逢代理对时返回完整字符。
  二进制使用 Base64 分页，offset/nextOffset 为字节数，不把无效 UTF-8 悄悄替换成乱码。读取前后检查取消与输入状态。
- 普通文件已解除内部 startWithAttachments 的未接通保护；角色系统上下文明确标识附件引用和内容为不可信数据，并指引使用附件工具。

## 记忆工具与角色审批范围

- 生产容器注册旧四个工具名。搜索只读；保存、修改和遗忘先申请 memory.write，审批内容包含角色范围、规范化输入和旧记录版本。
  批准后再次核对当前输入范围，并使用仓库版本检查执行修改/删除。子智能体上下文只允许搜索；模型参数不能指定角色或 agentPath。
- 新 MemoryScopes 只接受 active 会话的 running 输入，以接收时 participants 快照确定归属，兼容 characterId 与 profile.character.id。
  多人输入缺少执行角色 ID 时拒绝访问；CompanionSessionExtension 已把实际发言者 ID 传给生产工具工厂，避免共用第一角色的记忆。

## 单角色与多角色自动记忆召回

- MemoryRecall 接入生产单角色及演员系统上下文。角色范围取当前 running 输入快照；无绑定角色时无召回，不会退回全局记忆。
  导演不接收角色私有记忆，角色间只分享公开对话。召回结果是历史事实，明确要求服从用户当前陈述且不构成工具授权。
- 沿用旧召回的最近 100 条候选、片段匹配排序、最多 5 条、单条最多 1200/合计 4000 Unicode 字符的正文预算。
  为限制超长输入的排序开销，检索片段只取用户文本前 8192 字符、最多 256 个词和 256 个相邻字符对；模型仍接收完整用户文本。
  零匹配时按最近更新时间排序，预算截断只作用于召回副本，不修改数据库。原始实际模型请求经既有持久化屏障保存。
- 完整生产多人测试确认两个模型各自召回并搜索对应角色记忆，第一角色公开回复可见，私有记忆不出现在另一角色请求、导演请求或公开消息。
  单角色测试确认跨轮刷新、遗忘后不再召回，以及存储失败时不发出下一模型请求。存储失败采用停止当前会话的策略，未沿用旧实现忽略错误后继续。
- 召回专项 **3/3**、工具回归 **3/3 通过**，类型检查、工程门禁通过（218 个源文件、0 错误）。
  自动提取候选、记忆历史数据迁移和自唤醒相关策略仍待实施，不宣称完整记忆业务已经全部迁移。
- 宿主全量回归 **162/162 通过，零失败、零跳过**，另 3 项工程测试通过。没有修改前端，本批未重复前端全量。

## 自动记忆候选提取器

- 核对旧自动提取规则后新增 extractMemoryCandidates，复用公共 pi completeText，不提供工具。用户/助手文本各取前 6000 Unicode 字符，提取时限 30 秒。
  实际请求必须经调用方 record 持久化后才能发送；空来源直接返回空候选，取消和持久化失败不降级为一次普通请求。
- 兼容带代码围栏的 JSON；候选只接受四个记忆类型、0.85 到 1 的置信度、最多 4000 字符的规范化正文，沿用凭据模式过滤。
  同批候选按规范化正文去重，输出最多 64 个原始候选、响应最多 128 KiB。无效候选被过滤，损坏或超限响应报错。
