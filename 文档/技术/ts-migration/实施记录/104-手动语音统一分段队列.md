# 手动语音统一分段队列

日期：2026-09-18。用户指出无缓存时手动播放等待整段回复合成，要求统一为分段排队播放。

## 原因与实现

原 synthesize() 虽按文本分块请求，但等待全部 sources 收齐才返回，toggle 再调用 playSources，造成首音等待整条回复。

- 删除独立的整段等待合成分支，手动请求复用 enqueueStreamingChunk；该函数新增 manual/auto 意图参数，只有自动请求检查自动合成窗口授权。
- 两种入口共用文本分块、消息内合成调度、重试、分段 Blob 缓存、播放组和逐段播放；每个播放任务仅等待自己的合成结果。手动任务以 manual 意图申请桌面播放租约。
- 手动播放开始时停止旧播放，替换当前消息旧合成任务；切换播放目标会取消前一手动合成 lane 并使旧响应失效。重复点击未就绪手动任务不重复排队。
- 每段就绪即更新缓存，完整成功后标 ready。部分失败或取消后重新点击会重新按完整文本排队，不把不完整音频当成完整回复。
- 有完整缓存时同样使用播放队列，保留原多音频时间轴、暂停/恢复及拖动能力。输出门闩覆盖手动队列等待期间。

本轮未运行语音服务、单元或 UI 测试，也未合成真实用户消息。实际首音时间、桌面与桌宠抢占、暂停/拖动与长回复仍需实播验收。静态检查结果记录在实施跟踪。
