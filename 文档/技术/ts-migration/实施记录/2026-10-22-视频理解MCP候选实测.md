# 视频理解 MCP 候选实测

## 结论

按 Eden / QQ 接收视频后的分析需求，优先选用 VideoContext MCP 的固定版本并纳入 Windows 兼容补丁。它在本轮实测中提供了完整的本地视频、语音转写、时间线、选帧、预览与清理链路，且没有复现另外一个候选的跨视频缓存错误。原版在本机 Windows 上的语音工作进程存在兼容问题，不能直接记为原版全部通过。

VMRam95/mcp-video 暂不采用：原版从同目录读取已有 `frames/`，未按视频及抽帧参数区分，实际把前一段视频的八帧返回给另一段运动视频；改变时间范围和分辨率也复用了旧结果。ipythonist/mcp-video 暂不采用：默认依赖安装不能启动，兼容修正后的两次 Eden MCP 调用均超时，原因尚未定位；独立 CLI 对同类本机 HTTP 视频的下载可成功，因此不能简单归因于网络不可达。

本轮只做比较试验与记录，兼容修正均位于 `.artifacts/video-mcp-20261022/sources/` 的独立副本。尚未安装进正式插件列表，也未修改 Eden 的生产视频业务。

## 样本和判断方式

使用自己生成的 24 秒、640×360、12 FPS 视频：红色方块、绿色圆形、蓝色三角形、黄色星星，各持续 6 秒，并带有可读的 ALPHA/BRAVO/CHARLIE/DELTA 标记。中文语音由本机 SAPI 生成，约 19.17 秒，包含上述对象及“一二三四五”。另有静音 MP4、WebM、GIF、12 秒白方块移动视频、损坏文件，以及中文和空格文件名。

判断依据是实际 MCP 握手及工具返回、图片字节、导出图像的可读性、已知时间戳、输入切换后的缓存正确性、语音内容、错误边界，以及图片是否进入 Eden 下一次模型请求。仅收到 `isError=false` 不视为内容正确；`partial_success` 与 `complete` 分别记录；图片进入模型请求也不等于完成语义理解。

程序检查了画面主色和顺序，实际查看了四张导出关键帧，确认形状和画面文字清晰。没有用未知答案的视频自评，也没有把当前会话模型查看图片等同于 Eden 的生产模型已完成视觉理解。

## 对照结果

| 项目 | 原版安装/启动 | 实际媒体结果 | Eden 相关问题 | 判断 |
|---|---|---|---|---|
| VideoContext | 按锁文件安装，9 个 MCP 工具可握手；本机非管理员启动成功 | MP4、中文路径、WebM 和选帧通过；原版音频为 `partial_success`，Windows 环境补丁后转写完成 | GIF 被拒绝；必须控制一次返回帧数和模型窗口 | 优先选用，保留兼容补丁与格式适配 |
| VMRam95 | `npm run build` 的 TypeScript 编译通过，但后续 `cp` 在 Windows 不可用；已生成的 stdio 入口可运行，2 个工具 | 首次抽帧正确，MP4/WebM/GIF 均取到画面；切换范围/视频后错误复用旧帧 | 默认此样本返回 12 帧，超过 Eden 单次最多 8 图；目录缓存导致内容不可信 | 暂不采用 |
| ipythonist | 默认 MCP 2.3.0 与 FastMCP 1.x 导入不兼容；固定 1.28.1 后 `description` 参数仍使启动失败 | 改为 `instructions` 后可握手 5 个工具；本地路径及本机 HTTP 视频的实际 MCP 调用各到 120 秒超时 | 连接超时关闭后未继续统计后续请求为独立媒体测试；CLI 下载对照成功，MCP 超时原因未定 | 暂不采用，不能宣称已完成视频理解验证 |

### VideoContext 的有效结果

- 原版四张帧图及预览通过 Eden 的图片解析，但有声音视频转写失败；通过其相同 Whisper worker 的直接调用可转写，复现了最小子进程环境触发 `WinError 10106`。
- 原版 `minimal_environment()` 缺少 Windows 系统环境。仅在临时副本为 Windows 子进程保留 `SystemRoot`、`WINDIR` 后，语音返回由不可用变为 `complete`，帧数仍为 4，语音段与帧共同进入时间线。补丁保存在 `videocontext-compat.patch`。
- 两轮补丁后 24 秒样本处理约 3.9 秒和 4.2 秒，含实际本地 tiny 转写与四帧准备，未计依赖/模型安装；不是跨机器或跨模型性能保证。
- 请求 1、7、13、19 秒的帧，时间线分别为 1000、7000、13000、19000 毫秒，画面顺序正确。
- 改为 18–24 秒范围，只得到 19、22 秒的黄色星星；换成运动视频，四帧白方块的横坐标中心约为 29.5、149.5、269.5、389.5，未复用四幕视频图像。
- 损坏文件、逆序范围和允许目录外的实际文件被拒绝；生成作业的删除接口完成。GIF 不在它的本地输入扩展名范围内，需要另做转换入口，不能记为支持。
- tiny 转写有明显错词：“绿色圆形”被识别为“預測原型”，其余红色方块、蓝色三角形、黄色星星和数字序列可辨。转写链路跑通不代表中文准确率已满足正式用途；更大模型的效果本轮未测。

### VMRam95 的可复现错误

首次请求 8 帧、640 宽正确。随后同一文件改为最后 6 秒、最多 2 帧、320 宽，仍返回此前全部 8 张 640 宽图片，哈希完全一致。把同目录中的另一个 12 秒运动视频作为输入，还是返回相同 8 帧。源码中的 `dirname(video)/frames` 固定目录及无条件复用分支与现象一致。此项仅复现并记录，没有在候选副本修复。

### ipythonist 的限制

除默认依赖与启动参数问题外，当前源码的 `get_transcript` 使用固定英文字幕参数，未见普通本地视频的 Whisper 转写调用；不能用其可选依赖声明推断中文语音已经可用。两次超时为本轮 Eden 标准 MCP 客户端实测；直接 CLI 的成功是诊断对照，不能代替该插件的 MCP 接入通过。

## Eden 模型请求验证

使用真实 VideoContext stdio 进程、Eden `McpClient`、`mcpResultImages`、`mcpBusinessResult` 及公开 `runtime-pi.createRuntime`，模型端是独立回环录制协议端点；实际工具执行与图片编码没有替身。不同窗口采用独立缓存。

| 模型窗口 | 本次取帧 | 下一次实际模型请求收到的图片 | 结果 |
|---|---:|---:|---|
| 32,000 | 1 | 1 | 通过 |
| 32,000 | 2 | 0 | 自动压缩先发生，图片没有进入后续主模型请求 |
| 32,000 | 4 | 0 | 同上 |
| 131,072 | 4 | 4 | 通过，无自动压缩 |

本地预算把图片按较高固定值计算，MCP 图片的业务占位内容也可能参与预算。应在接入阶段单独修正/核实该预算，并结合视觉模型窗口安排取帧；不能只用“最多 8 图、8 MiB”作为成功标准。单帧通过不表示连续单帧观看全部通过，累积历史仍需管理。本轮没有改动生产压缩策略。
