# 会话首次连接误报恢复

用户反馈每次聊天会出现“连接已恢复／会话状态已重新读取，可以继续操作”。已在真实 WebSocket 与 React 界面中复现：修复前只有一个仍正常打开的会话连接，没有发生断开，首次加载后也出现了恢复成功卡片。

根因在 `useSessionConnectionFeedback.ts`：收到会话通道的 `connected=true` 后，调用 `controller.opened()`，但忽略其 `recovering` 结果，再无条件调用 `synchronizing()`。这将首次连接、正常会话快照读取和断线恢复合并为同一条 `restoring → restored` 路径，正常打开新会话也会显示恢复通知。此提示本身不能作为用户网络实际断线的证据。

修复将 `opened.recovering` 传入同步状态控制器。`ConnectionFeedback` 记录当前同步修订号和是否属于恢复；首次读取保持安静，成功后维持 `idle`，实际同步失败仍进入可重试的 `sync-error`。真实断线后继续等待恢复快照成功才进入 `restored`，旧同步结果不能覆盖新的断开或账号／世界状态。同一会话重复的连接成功状态不再重复读取快照或触发恢复。

生产修改限于 `frontend/web/src/hooks/useSessionConnectionFeedback.ts` 和 `frontend/web/src/lib/connection-feedback.ts`。未删除恢复提示，未改 WebSocket 重试、事件游标、用户消息提交或工具执行逻辑。
