# 模型接口移除内部版本负担

日期：2026-09-14。

## 原因

真实会话中模型将 get_esp32_command_status 的版本哈希末尾 734a 两次抄成 734c，导致整批工具加载失败，并被统一的“工具变化”错误误导。版本快照属于宿主执行一致性机制，不应成为普通工具加载的模型参数。

## 修改

- load_tools 只接受工具 id；逐项保存、返回 loaded/failed，单项错误不撤销其他成功项，重复 ID 去重。发现和加载结果不再暴露内部版本。
- 工具搜索归一化空格、下划线、冒号、连字符，按词匹配，名称命中优先。
- 通用工具加载记录跨工作区保留；技能代码及工作区文件/命令工具仍校验工作区。角色、会话、当前策略及内部工具版本检查保留，历史记录无须数据库迁移。
- 技能模型 schema 与管理端 RPC schema 分离，移除 expectedContentHash/expectedWorkspaceRoot；目录只提供名称、概要与必要依赖状态，正文结果提供内容与参考文件列表。技能执行的快照校验由宿主直接完成，不通过模型参数传递。
- manage_plugins 的普通 invoke 只接受 id/input，宿主解析已激活版本，并在审批和执行中锁定该版本。安装、激活、回滚及编辑并发控制继续使用精确制品/草稿版本。
- 更新工具说明、插件调用指南和实现设计文档，在工程约束中加入模型接口边界规则。

## 验证

新增模型接口回归，覆盖最小 schema、目录不含哈希、混合成功失败批次、搜索分隔符以及跨工作区保留/跨角色隔离。更新实际模型调用夹具，不再计算版本哈希。

25 项专项通过，包含真实临时宿主模型请求、技能代码执行、审批期间替换拦截、插件开发安装及按 ID 调用。完整服务端与共享包回归 377 项：376 项通过，插件开发用例在并发运行时触发进程超时；全量结束后独立复跑该文件 3/3 通过，未修改超时阈值。最终类型检查与宿主构建通过。架构检查保留既有 model-binding.ts、model-catalog.ts 两项复杂度错误，无新增错误。证据见 `.artifacts/model-interface-cleanup/`。

测试只使用临时数据。未修改当前用户数据库，也未重启当前开发进程；运行中的服务需重启后使用新接口。
