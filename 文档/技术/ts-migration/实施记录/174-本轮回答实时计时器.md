# 本轮回答实时计时器

日期：2026-10-06。模块：API 会话契约、sessions 只读投影、Web 输入框。

## 行为与实现

用户明确选择“当前这一轮回答耗时”。输入框右侧上下文占用圆环上方新增同尺寸计时器，图标加 `mm:ss`，超过一小时显示 `h:mm:ss`。实际执行开始归零并每秒更新；正常结束、用户停止和失败后保留本轮时间；下一轮实际开始重新计时。排队等待不计入，工具执行、模型重试和审批等待计入。没有回合显示 `00:00`，读取中显示 `--:--`；恢复连接和读取失败在提示中区分。

协议事实来源为 `packages/api/src/session-timing.ts`，新增只读 `session.timing.read` 返回最近回合 ID、开始/结束时间、结果、服务端观察时间和字符串序列游标。SessionRepository 首先验证会话归属、运行世界及删除状态，再读取最近 `turn.started` 和同一会话/回合的结束边界。使用现有两个事件索引，最多读取一个开始、三个结束和一个最新序列；不扫描流式正文、历史消息或 turns 表。计时起点使用持久事件时间，与原回答末尾耗时保持一致；没有修改数据库结构或成功回答末尾的语义。

Web 计时器复用现有会话通道，新增观察入口只订阅已有事件，不建立新连接或重试循环。打开会话及连接恢复时读取快照，运行中用服务端观察时间加本地单调时钟更新，每秒没有网络请求。回合开始/结束事件直接更新；缺失开始边界时补读快照。字符串序列按 BigInt 比较，较旧快照、重复事件和其他会话事件不能覆盖新状态。Hook 按会话及账号/世界代际绑定，切换或卸载取消订阅及 interval，丢弃未完成请求的结果。

新增文件均为独立协议、边界查询、计时状态、React Hook 或显示组件，生产文件不超过 100 行。前端订阅函数保留完整生命周期，旧前端逐步执行规模约束；原 session.routes 长函数提醒继续存在，仅增加一条读路由。没有扩充共享全局状态。

Server 测试使用内存数据库，验证执行/排队边界、下一轮归零、停止/启动恢复、精确事件时间、10,000 条无效正文流不参与查询、索引计划、失败及错误时间、账号/世界/删除和 UUID 边界。首次路由夹具错误使用同步断言，改为等待生产异步 contractHandler 后通过；不是服务业务失败。

编译制品夹具在独立临时目录、随机端口和专用 Node 22 子进程运行。真实前端 RPC 客户端创建会话、建立会话通道，读取尚无消息的运行中时间；夹具只向临时数据库追加持久边界。重新连接读取停止时间，并拒绝同一通道读取其他会话。正常 IPC 退出并删除临时夹具；没有调用模型或使用真实用户数据库。初次夹具导入使用 Windows 路径而非 file URL、并误用不存在的 control 事件模式；修正为 file URL 和实际 discovery 模式后联调通过，运行约 1.5 秒。

没有进行真实 Electron 桌面视觉验收，静态 React 渲染不替代完整桌面验收。
