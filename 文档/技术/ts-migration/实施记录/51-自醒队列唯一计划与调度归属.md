# 自醒队列唯一计划与调度归属

2026-09-11，用户要求修复工具实现，禁止通过修改智能体提示词规避重复自醒。

## 问题与实现

- 原工具每次调用都新增自醒任务；MonOs 同时维护自己的下一次自醒，Agent 本地队列也会执行工具创建的任务，形成两条调度链。
- 每个世界数据库只允许一条 queued 自醒，数据库部分唯一索引兜底。新计划在事务中取消旧待办并写入新任务；历史记录保留。重复 operation key 返回原任务，不会复活已替换任务。
- 自醒运行、等待外部行动或行动结果不确定时占用执行名额；其他普通任务不受限制。延迟派发和重启恢复遵守唯一待办规则。
- MonOs 管理的世界中，Agent 定时任务作为持久化待投递计划，通过现有 `schedule_requests` 文件协议交给 MonOs。Agent 不再本地执行这些定时任务，只执行 MonOs 提交的激活任务。独立世界继续本地执行。
- 文件原子落盘后登记投递记录；失败保留计划并明确报错，后台重试，健康状态暴露故障。连续计划使用单调创建时间，使 MonOs 能选择最新请求。缺失外部调度路径时拒绝静默回退本地执行，身份环境覆盖继续保持账户隔离。
- 相同用户在已有外部自醒未结束时再次提交，关联已有任务并保存幂等别名，不创建额外自醒会话；原有请求哈希及用户归属检查保留。
- 升级保留最新历史待办，将其他待办标记取消。旧数据导入也遵守相同规则。自醒列表展示最新待办。
- 未修改智能体提示词、工具描述或审批要求，未修改 MonOs 源码或二进制。
