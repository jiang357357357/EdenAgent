# 2026-10-29 共享资料库局域网与云主机分离

用户指出局域网和云主机的交互没有分开，要求明确分成两种。共享资料库顶部增加「局域网共享 / 云主机共享」模式入口；每种模式保留自己的功能导航和资料库选择。局域网集中展示本机状态、局域网设备、发现与配对；云端集中展示云主机，并将连接已有主机与 SSH 部署新主机分别展示。

## 范围与状态

资料库列表、管理主机和新建资料库的目标都按模式过滤。管理目标变化后清空旧邀请和设备列表；无该模式管理主机时隐藏设备操作。切换模式清除临时提示和邀请，卸载 SSH 表单以清空凭据；正在运行的部署保留后台任务，并在云主机入口显示部署中。

首次界面分离时，切换模式只改变视图，目录绑定保持原状。当前目录绑定另一模式资料库时，不展示其同步、冲突、历史或权限操作；重新绑定仍需明确选择目录并确认。长目录在顶部省略显示，保留完整路径提示和详情。同日后续按用户确认改为实际互斥工作姿态，以下自锁补充取代此处的“只改变视图”。

后台在认证后的 capabilities 响应中取得主机类型，持久存入 peers JSON 元数据，重配对保留该属性。客户端重启且云主机离线时仍归入云模式；分类不授予权限。没有 SQL 表结构或共享协议变更。局域网配对使用既有 pairDevice 私有地址校验，补齐裸 IPv4:端口的规范化；云端继续使用 connectHost。

## 同日：自锁工作姿态与局域网停用

用户要求改为自锁按钮，并明确确认“切到云主机时，本机局域网发现和发布一起停止”。顶部按钮使用 `aria-pressed` 和按下样式，选择另一按钮才切换；重复点击、关闭重开、服务重启或云主机离线不会解除已选姿态。

权威状态由 Server 的账号级 `SharedPostureSelection` 保存到私有 `posture.json`（独立 schema 1），通过 `sharedWorkspace.posture.read/select` RPC 读取和修改。选择使用修订号防止其他窗口覆盖，同姿态选择不改修订或重启连接，部署进行中拒绝切换。不同账号的记录不能混用；缺失记录初始为 LAN，无效记录报错。

`SharedLanOwner` 在切换前暂停原网络和全部目录引擎，取消在途请求、关闭原监听，然后保存新姿态。云端客户端关闭组播发现、本机发布，只监听回环地址；库列表和主机请求在后端验证姿态归属。切回 LAN 恢复发现、按 DLC 开关发布，以及属于该姿态的同步引擎。独立云主机继续单独运行，子机的姿态切换不关闭云端服务。

`SharedPostureDirectories` 保留旧 `selected-directory.json` 作为 LAN 选择，云端独立使用 `selected-directory-cloud.json`；对外目录修订包含姿态修订，切走再切回也会拒绝旧审批与旧操作。初次云端选择为空，不继承 LAN 目录；另一姿态的绑定在前后端都禁止操作。资料库、文件、身份、配对与持久队列不删除，不自动迁移、重绑定或上传。云端离线保留姿态及缓存分类，不选本机库作为备用。

前端从后端读取姿态和对应目录，再读取当前状态。切换清除旧主机、文件、权限、邀请与 SSH 表单凭据；迟到响应按作用域和序列丢弃。修正切换保存失败时被替代的刷新/历史等待状态未清除的问题，失败保留原锁定并允许重试。服务的姿态协调仍在既有 `service.ts`，文件未超过 500 行；持久存储、目录修订和网络生命周期分别由独立所有者管理。
