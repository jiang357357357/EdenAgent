# 2026-10-08 令牌续换与语音、投影有限重试

本轮根据客户《死循环根因报告-20261007.md》修复当前源码，并构建本地便携修补制品。正式产品版本保持 1.11.4，没有提交、推送、上传或创建新的正式发行。客户机安装状态不能由本机验证代替。

## 已修复的行为

- 后台服务令牌保留 Core 返回的有效期，提前一分钟续换；同账号并发请求共用一次交换。收到明确的 401 后最多续换并重试一次，不因 403、超时或连接中断重放请求。账号、Core 地址、服务凭据来源均受检查；普通浏览器凭据失效不会借用后台身份。
- 新建后台自醒与 QQ 会话记录私有的服务凭据来源。旧服务会话仅按持久通道分类、Core 地址和已确认账号归属恢复；显式浏览器重绑定会记录禁用状态，重启不会再次提升为服务身份。独立子模型的已确认绑定随同账号续换保留。
- 同步目标以账号数据库中的 Core 地址确定，令牌变化不建立新目标。迁移仅使用当前绑定的精确旧凭据，保留投递收据、游标和错误事实；其他目标不合并。更换 Core 地址仍建立独立游标。
- Core 明确拒绝的投影立即暂停；暂时故障和可幂等核对的未知结果最多自动尝试八次。会话、消息和导演投影均保留原事实与错误，不删除未知投递。在“Mon 同步记录”处理原因后点击“已处理原因，恢复同步”才能开始新的有限尝试；外部 QQ、邮件、设备操作不由此入口重放。
- 语音使用最多两个运行任务、32 个等待任务的可取消队列，按会话轮换；排队和执行分别限制为一分钟、两分钟。相同任务的消费者独立取消，最后一个消费者离开才中断上游；关闭和超时不依赖失去响应的提供方自行结束。
- 自动语音按消息和配置、文本累计失败，不把流式修订视为新预算。单句最多四次失败，消息总失败最多八次；明确失败、结果未知、传输中断与预算耗尽停止自动处理。失败预算写入私有数据库，重启也不会清零。队列满、排队超时和执行超时同样写入停止状态；用户取消不计失败。手动播放可明确恢复该消息，其他消息保留自己的状态。
- HTTP 错误保留状态、端点及有长度限制、敏感字段脱敏的结构化原因；RPC 继续传递失败分类和是否允许重试。`success:false` 的 HTTP 500 是明确业务失败；缺少确认事实的 5xx 仍为未知，不把全部 500 一概判为失败。
- 真实 React 夹具发现旧流式修订的播放占位会保留等待状态：现在修订切换清理旧占位，回答结束时封闭所有剩余占位，失败后能释放输出等待并手动恢复。

## 报告中需要区分的事实

后台在每次任务准备时也会交换令牌，问题是已经持久绑定的长生命周期连接缺少续换，并非只有启动时交换。`mon_operations.state=unknown` 是审计事实，本身不是无限重试队列；无限增长来自调用方不断新建操作。普通流式追加已有游标，重复修订和重入缺少累计预算。

当前 Core 合成成功返回音频 URL，音频单独下载且仍限制 32 MiB；8 MiB 的 JSON 限制继续保护模型目录等响应，没有通过取消限制来掩盖旧组件或错误响应。TTS、模型请求与运行时取消分别验证，不能仅凭错误计数推断模型取消期限故障的全部因果关系。
