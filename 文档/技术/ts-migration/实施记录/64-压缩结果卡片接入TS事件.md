# 压缩结果卡片接入 TS 事件

2026-09-11，用户确认短对话也允许压缩，不增加长度门槛，并要求检查前端卡片。

问题：MetaPartCard 已有压缩样式，但 TS 的 agent.session_compact 事件未接入 apiMessage / projectSessionEvent，导致实时与历史消息均不能产生对应卡片。

实现：将持久化压缩事件转换成具有稳定身份的独立 assistant 元消息，复用 compaction part、摘要展开和 Markdown 展示。实时推送与历史回放使用同一投影。卡片标记“已完成”，明确短对话结果可能更长；有同口径前后值时按正负显示减少、增加或大小未变，不再把负收益截断成减少 0%。缺少 tokensAfter 时不伪造压缩率或压缩后数值。保留原始摘要，不通过输出文字猜测成功与否。

本次没有增加压缩长度限制，也没有变更后端压缩策略。只有持久化成功事件生成完成卡片；处理中及失败状态仍走现有回合状态/错误显示，本次未新增其独立卡片。

验证：前端类型检查、diff --check 通过；compaction-card 两项测试通过，覆盖实时/历史一致、原始摘要、缺失统计不伪造及畸形事件。首次从主仓库运行测试因 Vite 根目录错误未加载，切换 frontend/web 后通过。未做实际浏览器视觉验收。
