# 模型请求快照内容去重

2026-09-11，用户要求修复模型请求快照重复存储。此前只读统计 92 条请求 JSON 合计约 24.96 MB；同一会话重复保存历史消息、系统文本和工具定义。

## 实现

- store 新增 `request_contents(hash,content_json)` 表，通过正式 schema 迁移创建。内容按 JSON 的 SHA-256 存储在所属世界数据库内；无跨世界存储、公开内容下载接口或外部副作用。
- sessions 新增 `RequestPersistence`，对 `model.request`、`director.model.request`、`memory.extraction.model_request` 的 payload/tools/snapshot 内较长字符串和较大数组对象抽取引用。小字段原样保存，避免引用比原文更大。
- 历史消息和工具定义相同时复用内容；消息变化生成新的内容哈希。相同哈希已有内容必须完全一致，损坏的旧内容不能静默复用。
- requestId、actor、model、provider、contextEstimate 等顶层审计和统计字段保留原位，原有上下文代数和自醒 SQL 摘要继续有效。
- 内容写入与事件写入要求同一事务；失败共同回滚，不发布事件。请求发送前持久化屏障继续生效。
- `event.list` 在存储读取边界完整还原快照，校验引用 schema、路径、占位与 SHA-256。缺失或损坏的内容明确报错，不能伪装为完整审计。
- 广播和 RPC 仍提供原来的完整请求结构；兼容历史内联快照，不更改前端、模型请求本身或缓存统计含义。

- 合成 20 次逐渐增长的历史请求，原 JSON 613,015 字节；去重后事件 JSON、内容 JSON 和内容哈希合计 77,299 字节，减少约 87.39%。不包含 SQLite 页和索引开销，不代表生产库回收比例。
- 存储测试覆盖去重、历史增长、导演与记忆请求、旧格式、小快照、事件写入失败回滚、内容损坏/缺失，以及顶层统计字段保持可查询。
- 真实 pi 宿主连接本地录制模型执行两轮请求，关闭重开后事件快照完全一致；逐条对比快照中的实际请求 payload 与模拟供应商收到的请求，完全一致，重启不重复调用模型。RPC 不泄漏内部存储引用。
- 初跑修正了测试夹具使用非法事件 UUID 和重复 requestId 初始化；工程检查发现还原函数复杂度超标，改为 schema 校验后门禁通过，未修改阈值。

## 生效与边界

重启新宿主后新增请求使用去重存储。真实用户数据库没有作为测试夹具，也未被手动重写；历史请求不会自动转换，数据库文件不会因此立即缩小。网络审计输出仍是完整请求；本轮优化数据库重复存储，不改变模型实际上下文。没有提交或发布，保留前几轮尚未提交的改动。
