# 74：服务端测试分层与递归发现

日期：2026-09-13

## 问题

`Server/tests` 已有一百余个测试文件，但默认命令使用
`Server/tests/*.test.ts`，只能执行顶层测试。继续建立 `unit`、`integration`、
`contracts` 和 `regression` 目录会静默漏测，因此此前只能把新测试继续堆在顶层。

## 实施

- 增加 `Script/Test/discover_tests.mjs`，稳定排序并递归发现受支持的测试文件。
- 增加 `Script/Test/run_typescript_tests.mjs`，打印各测试根的发现数量，并通过
  Node 原生测试运行器和 `tsx` 执行完整列表；发现数量为零时直接失败。
- `test:server` 改为递归覆盖 `packages` 与 `Server/tests`。
- `test:architecture` 纳入发现器防回退测试，覆盖嵌套文件发现、非测试文件排除，
  并锁定 `package.json` 不得恢复浅层 glob。
- 新增 `Server/tests/README.md`，明确单元、集成、契约、回归、夹具和 live 测试边界。
- 将 ESP32 设备工具测试迁入 `Server/tests/unit/mon/device-tools.test.ts`，验证
  新目录可以由默认入口执行。

现有顶层文件暂作为兼容区保留。当前工作树同时包含大量业务改动；一次性移动全部
文件会放大相对导入修改和审查风险。后续测试修改时按业务逐组迁移，新测试不得继续
进入顶层。

## 验证

- `npm run test:architecture`：6 项通过。
- 嵌套设备工具专项：5 项通过。
- 递归发现：Server 103 个测试文件，packages 23 个测试文件，共 126 个文件；
  已确认包含 `Server/tests/unit/mon/device-tools.test.ts`。
- 默认服务端与共享包回归：351 项通过，0 失败、0 跳过。
- 根仓库与 Server 子仓库 `git diff --check` 通过。

## 边界

- 没有访问真实用户数据库或真实外部服务。
- 没有改变生产运行时行为。
- 没有提交、推送或发布客户端。
