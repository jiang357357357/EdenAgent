## 发现与修复

当前 Core 实体 2：vendor=deepseek、model=deepseek-v4-flash，官方 api.deepseek.com 端点；保存的 default_params 为 thinking_enabled=true、reasoning_effort=medium。原 resolveCoreModel 只读取 context_window/max_tokens，推理与采样设置没有进入 Agent 绑定。因此以前请求省略参数，实际采用供应商默认行为。

本轮实现：

- configuredModelSchema、RuntimeModel 新增严格限定的 sampling 字段，承载 temperature、topP、presencePenalty、frequencyPenalty。
- Core 模型绑定保留上述采样设置及原生 thinking.type/旧 thinking_enabled、reasoning_effort；原生开关优先。未配置的值保留供应商默认，显式非法值拒绝。
- pi 公共适配器将采样设置写入实际请求后再记审计，调用级参数优先于模型默认。
- DeepSeek 的 off 显式传 thinking.type=disabled；medium/xhigh 映射 high，minimal 映射 low。思考模式省略无效的温度与重复惩罚，top_p 按有效下限 0.95 处理；关闭思考省略无效 top_p。依据当前官方文档实现，未修改 Core 存储中的用户偏好。
- 重新绑定及新自醒读取的新配置生效；已有绑定快照保留其原配置，不静默改写历史模型绑定。

参考：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。官方当前说明思考默认 enabled/high，medium 映射 high，思考下 temperature/presence_penalty/frequency_penalty 无效；top_p 思考下有效范围为 0.95–1.0，关闭思考固定 1.0。运行时按已知 DeepSeek 供应商适配，不将此策略套用其他供应商。

参数确实可以改变本组样本的继续调用工具/直接收尾倾向，但没有解决重复旧任务。样本量很小；收尾 probe 已包含真实旧记录，适合评估继续同一上下文的行为，不能据此推断整轮自醒的最终工具次数、整体人格或某参数必然更优。没有对 thinking on/off 做严格单因素成对估计，也没有据此关闭正式思考或提高正式温度。
