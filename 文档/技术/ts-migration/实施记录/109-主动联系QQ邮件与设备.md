# 主动联系 QQ、邮件与设备

2026-09-18，用户明确纠正主动性的重点为主动找用户，并批准实现。

## 实现

- 自醒提示改为优先思考想和老师聊什么：共同话题、分享、问近况、小邀请均可成为联系理由，允许没有任务也联系，也允许安静。角色打算继续保留，作为延续话题和兴趣的辅助，不再每次强制先做任务。
- 新增 send_qq_message，复用已有私人 QQ 目标解析、发送台账和请求幂等机制。目标来自 Core 已配置的用户渠道，模型无法指定其他联系人。标题可省略，以自然聊天正文发送。执行走 contact.qq，子智能体禁用外发工具。
- 自醒默认提供渠道发现、近期联系、QQ 回复读取、QQ 发送、邮件发送、设备发现/控制/状态查询工具。新增 eden-contact 内置技能，日常对话亦可按需加载。
- 新增 read_contact_history，按当前会话的账号归属跨会话读取 QQ/邮件/桌面发出摘要和设备控制工具回执；无账号归属时只读当前会话。查询不返回接收者地址和凭据，限 30 条。
- 设备历史返回发送时状态及可用命令 ID，当前状态由 get_esp32_command_status 再读取；QQ 回复通过 read_qq_messages 实时查询。邮件与设备没有回复正文接口，工具明确报告这一边界。
- 修正原自醒 recent_contacts 对直接发送 QQ/邮件缺少正文的问题，从已存投递 payload 投影消息内容。
- 邮件渠道发现从“状态接口可达”修正为检查 ready 和默认收件者是否存在；QQ availability 仅表示配置了可解析的私人目标，不保证机器人实时在线。
- 提示约定一次选择合适渠道、核实最新联系与回复、同一话题留出间隔、结果未知先核实。该部分为模型指导，并非新增硬性跨渠道限流器。实际副作用继续执行既有权限检查，不改变账号授权设置。

## 验证与加载

Server TypeScript 与根仓库/Server 差异空白检查通过。本轮为实现阶段，未运行单元或专项测试，未主动发送真实 QQ/邮件或设备命令。

待验收：QQ 无标题与指定私人目标真实投递、跨账号摘要隔离、设备回执 ID 与后续状态、渠道不可用/结果未知处理、多轮回复延续、联系频率与角色表达。未增加邮件收件或设备回复正文采集，未实现新的消息驱动自醒触发器；沿用现有唤醒时钟。

加载完成：确认无运行中输入后重启 Agent 开发宿主，账号服务 ready、Mon Server 重新监听、开发链路启动。后续正常自醒将使用新版提示及工具。
