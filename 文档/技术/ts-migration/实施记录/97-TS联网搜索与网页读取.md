# TS 联网搜索与网页读取

日期：2026-09-17。

## 问题

活动的 TypeScript 宿主只有工具发现机制，联网搜索实现仍留在旧 Rust 归档中。内置技能目录也缺少网页研究技能，因此角色即使知道应当查询实时资料，也没有可加载和执行的正式工具。

当前 `.monconfig` 还残留 `parallel_mcp,exa_mcp` 配置，但这两个名称既不是已注册 MCP 实例，也不是搜索 Provider，实际运行链路无法使用。

## 实现

- 新增 `web_search`、`web_fetch` 和 `web_find` 三个宿主工具，作为延迟暴露能力进入现有工具目录。
- 新增 `web-research` 内置技能摘要与说明。技能负责检索流程，工具接口的存在与技能是否读取保持独立。
- 搜索 Provider 由宿主配置选择，不向模型暴露 Provider、API Key、版本号或超时等运行参数。`auto` 优先使用已配置的结构化 API，并以匿名 Brave、搜狗、Bing 与 DuckDuckGo 作为无需密钥的降级入口。匿名 Brave 请求由宿主串行节流，避免多查询并发触发限流。
- 支持最多四条并发查询、域名与时效筛选、结果去重、同域限制、短期缓存及会话级 `refId`。
- `web_fetch` 可直接读取公开 URL，也可读取搜索结果的 `refId`；HTML 清理为正文后可用 `web_find` 定位片段。
- 网络请求拒绝用户信息、localhost、私网、链路本地、文档地址及其他保留 IPv4/IPv6；DNS 解析后固定已验证地址，每次重定向重新检查，跨源重定向剥离认证头。
- `.monconfig` 的 `[search]` 配置已接入 TS 宿主，进程环境变量保持更高优先级；项目默认改回有效的 `PROVIDER=auto`。
- 搜索缓存和网页引用按会话隔离，不写入业务数据库，也不能跨会话读取。

## 验证

- Server TypeScript 类型检查通过。
- 3 项 Web 专项测试通过，覆盖配置优先级、私网/保留地址拒绝和会话引用隔离。
- 修改文件 Oxlint 为 0 警告、0 错误，差异空白检查通过。
- 真实联网搜索通过匿名 Bing 返回 5 条结果，并通过 `refId` 抓取到 Node.js 官方页面标题及 3482 字符正文。
- 针对最新真实会话暴露的中日文冷门实体搜索偏移完成回归：同样输入“普雷纳帕斯特 / Phrenapates Blue Archive”由搜狗匿名降级返回 6 条相关结果，包括萌娘百科、Bilibili 与知乎来源；多查询结果改为轮询合并，避免首条劣质查询占满返回列表。
- 双宿主开发环境已重启；Local RPC 工具目录确认三个 Web 工具均已注册为 deferred，`web-research` 技能包含对应工具依赖。
