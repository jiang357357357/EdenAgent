# 69. 宿主提示词去限制化

日期：2026-09-12

## 目标

用户认为统一后的提示词限制过严，要求去掉这些限制，并由用户后续自行补充真实模型测试。此次调整降低模型层重复训话，不改变代码层权限、审批、持久化和数据隔离机制。

## 实施

- 普通会话和多人角色系统提示只保留身份、自然回应目标及附件工具入口，移除重复的授权与不可信内容声明。
- 多人回合、提醒、连接器事件、交接、技能目录、子智能体任务和插件钩子改为正向任务说明。
- 自醒提示删除重复审批、禁止外发、结果推断等密集限制，保留上下文工具、定时工具和结果 JSON 结构。
- 内置工具描述只说明能力、参数和关键状态，不再重复“经审批”“不能授权”“不得重试”等宿主执行约束。
- 子智能体角色和技能快照提示改为正向职责说明，移除“不修改”“不执行”“不授予权限”等残留训话。
- 压缩及历史交接提示改为简洁的中文上下文说明。
- 删除不再使用的 `safety-boundaries.ts`。
- 导演 JSON/节拍协议、记忆 JSON 格式和插件平台客观限制均改用正向能力、字段和上限描述。
- 历史分类器继续识别旧英文模板、较严的旧中文模板、当前精简中文模板及两代附件工具名，旧模板不会进入新请求。
- 合并工作区同期新增的 `send_external_email` 工具描述，避免覆盖用户已有改动。

## 验证

- 提示词、历史分类、导演、记忆、自醒、子智能体、插件指南与请求上下文专项：33/33 通过。
- 三个提示词所有者均加入禁止性措辞防回退断言。
- `npm run typecheck:server`：通过。
- `npm run check:architecture`：0 errors；仅保留仓库已有长度警告。
- `npm run build:server`：通过。
- 残留子智能体提示修正专项：4/4 通过，随后服务端类型检查再次通过。
