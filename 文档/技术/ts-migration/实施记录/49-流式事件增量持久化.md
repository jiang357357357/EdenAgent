# 流式事件增量持久化

2026-09-11，用户批准修复流式消息重复存储导致的数据库膨胀。

## 问题与范围

此前只读统计：89,910 条事件中，86,688 条是流式更新，占用 JSON 653.43 MB；其中 `message` 与 `assistantMessageEvent.partial` 两份累计消息合计约 635.6 MB。每片流式输出重复写入不断增长的全文。

本轮修改新增数据的持久化表示；保留实时广播、RPC 查询和旧记录的公共结构。没有删除历史事件、压缩真实数据库或启动真实模型。

## 实现与边界

- `sessions/message-delta.ts` 按字段生成精确差异：字符串追加、属性替换/删除、数组内容变化；无法追加的修改保存替换值。
- `sessions/stream-persistence.ts` 只精简 SDK partial 与 message 完全相等的更新事件。磁盘只存一份消息快照或差异，不保存重复 partial；特殊不相等的 SDK 事件原样保存。
- 以 session、turn、messageId 分别维护已提交基线；第一次更新、重启后的新写入、差异不划算或超过快照间隔时保存完整消息。每最多 128 次更新断开增量链，限制随机分页的重建工作量。
- `SessionEvents.insert` 先写紧凑表示；提交后的 `publish` 才推进内存基线并广播原始完整事件。事务失败不会以未持久化消息作为后续基线，也不广播伪成功。
- `event.list` 自动重建紧凑记录，校验基线序号、会话、轮次和 messageId；基线缺失明确报错，不返回截断内容。分页可以从增量链中间开始；旧全量记录保持可读。
- 完整 `message_end`、工具结果和 runtime checkpoint 保留原语义。Mon 投影读取消息结束事件，自醒列表原本排除流式更新，因此无需修改前端或这些业务消费者。
- 追加数据库格式标记迁移 `event_payload_format=eden.message.delta.v1`，提高 schema 版本，防止旧宿主把紧凑事件当成原格式读取。调整前一轮索引升级夹具，显式从索引迁移前的 schema 开始。

## 验证

- `node --import tsx --test Server/tests/stream-persistence.test.ts`：6 项通过，覆盖存储大小、实时事件不变、跨快照分页、替换/删除/工具字段、事务回滚与失败、旧格式、缺失基线、多角色交错及新写入器恢复。
- 人工生成 400 次逐渐增长的流式更新，JSON 大小从 4,907,200 字节降为 123,914 字节，减少 **97.47%**。这是合成夹具结果，不是生产库压缩结果；测试断言低于原始大小十分之一。
- `node --import tsx --test Server/tests/stream-persistence.test.ts Server/tests/stream-restart.test.ts Server/tests/startup-history.test.ts packages/store/tests/event-indexes.test.ts Server/tests/memory-extraction-service.test.ts`：初批 14 项通过，加上后续多角色测试，相关服务端测试共 15 项通过。
- 真实 pi 运行时接本地录制模型，通过实际宿主落盘、关闭重开和 RPC 历史回放，确认公共事件与实时原始事件一致，没有重复模型请求。
- 前端 `node --experimental-strip-types --test tests/tool-lifecycle.test.mjs tests/event-stream-recovery.test.mjs tests/message-event-id.test.mjs`：11 项通过。并行 Vite 夹具有 24678 端口占用提示，断言均通过；未执行真实 Electron 窗口验收。
- Server 类型检查、架构检查通过；665 个源文件、0 错误，既有规模提醒保留。主仓库及 Server diff 空白检查通过。

## 生效与未处理项

重启加载新代码后，新增流式事件使用紧凑持久化。事件条数、实时网络传输仍保持原协议，本轮优化的是重复落盘大小。既有约 791 MB 文件不会自动缩小，历史重写/空间回收不包含在本轮中。未提交、未发布，保留之前请求统计和启动超时修复的工作区修改。
