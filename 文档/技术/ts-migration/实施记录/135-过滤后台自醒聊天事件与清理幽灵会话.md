# 135 过滤后台自醒聊天事件与清理幽灵会话

2026-09-21，用户报告自动自醒回复出现在普通聊天，显示“新会话”、空角色/模型与持续忙碌控件。

定位：截图对应会话 1bbcd4ec-520a-4c57-9037-6c3e62dfa49d 的 environment.sessionPurpose 为 self_awake，服务端已持久化 turn.completed。session.list 原本排除了该后台会话，但全局事件仍经 ensureSession 创建默认“新会话”，缺少正常会话元数据。缓存清理函数仅检查 background_session 错误；session.read 实际返回正常记录，因而无法清理。截图中忙碌状态没有收敛的具体事件丢失路径尚未复现，不能声称服务端未结束。

修复：isBackgroundSession 读取真实 environment.sessionPurpose；聊天运行时增加按会话缓存的异步事件过滤，在创建聊天状态及聊天回调前过滤后台 session/message/companion/subagent 事件。普通会话的事件保持到达顺序；审批等非聊天通知继续传递。已有缓存由原刷新/重连清理逻辑移除。没有修改后台执行或模型绑定。

验证：新增两项回归测试验证延迟分类时不产生后台假会话、保留非聊天通知，以及普通 turn.started/turn.completed 经真实事件投影和 reducer 后恢复 idle；两项既有连接状态测试通过，共 4 项。前端类型与差异检查通过。只读核对真实问题会话分类。开发服务热更新加载，未执行桌面 UI 自动化，未额外触发自醒。
