# 模型瞬时故障自动重试

日期：2026-09-13

## 问题

模型接口已经返回 `200` 并开始输出思考内容后，响应流以 `terminated` 中断。原运行时把 pi 的请求重试和会话重试都显式设为 0，因此该次输入直接进入 `interrupted`，前端显示“智能体运行失败”。

只打开供应商 SDK 的通用重试不足以解决此问题：流中断发生在响应开始之后，而且通用 HTTP 状态重试无法区分临时限流与额度耗尽。直接重放整轮还可能再次执行已经发生的工具副作用。

## 修复

- 在 `runtime-pi` 的持久会话层统一接管模型重试，默认最多重试 2 次，退避时间为 500 ms、1500 ms。
- 对 `terminated`、网络断开、超时、408/409、普通 429 和 5xx 等瞬时故障重试；认证、权限、余额、额度耗尽和上下文超限不重试。
- 每次重试前把活动检查点恢复到本轮输入之前。失败分支仍保留在持久审计中，但不会进入下一次模型请求的上下文。
- 同一逻辑输入只投影一个用户消息；失败的半截助手消息会在实时界面和历史回放中移除。
- 任意工具一旦开始执行，本轮便不再整体重放，避免文件写入、命令、消息发送等副作用重复发生。
- 用户在退避期间停止生成会立即取消等待，不会发出下一次模型请求。
- 前端在退避和重新请求期间显示“模型连接中断，正在重试（当前次数/2）”；重试结束后清除状态。
- 最终仍失败时，将 `terminated`、流提前结束和常见网络错误转换为可读中文。

底层供应商请求仍保持 `maxRetries: 0`。这是有意设计：所有重试分类、检查点回滚、事件持久化和副作用边界都由 Eden 的持久运行时完成。

## 验证

- runtime-pi 专项 6/6 通过：默认退避时间、流中断后恢复、工具执行后禁止重放、额度错误不重试、503 重试、退避期间取消。
- 前端专项 1/1 通过：失败消息删除、重试状态持续和结束清理，同时覆盖历史回放。
- 服务端与前端 TypeScript 类型检查通过，相关差异格式检查通过；lint 为 0 个错误，报告的 1 个警告来自会话选择器中既有的数组展开写法。
- 开发环境已重启，伊甸园 `40092`、尘世 `40093` 和 Web `40091` 正常启动。
- 使用当前私有模型绑定只读取得配置，分别向 `deepseek/deepseek-flash` 与原故障模型 `opencode_go/deepseek-v4-flash` 发起真实请求；两次均以 `stop` 完成，各产生 1 次模型请求且无需重试。测试未创建或修改用户会话。

真实供应商连接无法在不干扰服务的情况下强制制造“输出一半后断线”，因此瞬时失败恢复由本机真实 HTTP/SSE 断流夹具验证；线上真实请求用于确认两种现有供应商配置与新运行时兼容。
