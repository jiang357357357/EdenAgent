# 启动端口后启动者接管

日期：2026-09-12

## 问题

安装版的 MonPM 后端、开发版双宿主和桌面自管宿主可能同时使用固定端口。旧开发入口只清理 Web 端口，并把 Mon 当作外部服务，导致界面连接到安装版后端及错误的数据根/能力令牌；直接杀死 MonPM 子进程还会触发自动重启。

## 规则

- 启动方在创建进程前接管自己声明的固定端口，最后启动的一方取得端口。
- 开发入口接管 `40091`、`40092`、`40093`；从仓库根目录或 `frontend` 执行 `npm run dev` 均进入同一启动器。
- 桌面自管宿主在启动每个 realm 前接管该 realm 的端口；标记为外部监管的 realm 仍由外部监管器负责。
- 若监听者由 MonPM 监管，开发启动器先通过对应 MonPM 配置执行应用停止，关闭自动重启意图，再释放监听进程。
- 当前启动器及其父进程链受保护，端口若由这条进程链监听则拒绝自杀式清理。
- 若当前默认 realm 目录仍是旧数据库、其保留的 `v2` 子目录才包含 TS realm 元数据，开发入口继续选择该 `v2` 数据根，避免端口接管成功后因误读旧库再次离线；显式环境变量始终优先。
- 启动 Electron 桌面壳前显式移除父终端遗留的 `ELECTRON_RUN_AS_NODE`，防止 Electron CLI 被错误降级成普通 Node 进程。

MonPM 已在应用启动/重启前按配置中的 `ports` 强制清理监听者。因此安装版后启动时会接管开发版端口；本次补齐开发版和桌面自管宿主后启动时的反向接管。

## 验证

- `node --test Script/Project/runtime_children.test.mjs`：6 项通过，覆盖真实子进程端口替换及旧目录/保留 `v2` 目录选择。
- `npm --prefix frontend/desktop test`：172 项通过，包含桌面宿主在 spawn 前按顺序接管两个 realm 端口。
- `oxlint` 检查 7 个相关启动器、桌面进程和测试文件：0 警告、0 错误。
- 真实交叉接管通过：开发版先接管安装版 PID `207759`，MonPM 状态变为 `stopped/stopped`；随后 MonPM 后启动并接管开发版，安装后端 PID `1285120` 在 `40092` 返回版本 `1.10.1`；最后开发版再次接管安装版，MonPM 恢复 `stopped/stopped`，`40092` 与 `40093` 均返回 `2.0.0-dev.0`，`40091` 返回 HTTP 200，Electron 桌面进程在运行。
