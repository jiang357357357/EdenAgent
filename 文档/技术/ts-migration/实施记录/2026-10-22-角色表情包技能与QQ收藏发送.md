# 角色表情包技能与 QQ 收藏发送

## 范围与结果

补齐新 TypeScript 宿主缺失的表情包能力。新增 `character-stickers` 内置技能及四个工具：`list_character_stickers`、`remember_character_sticker`、`send_character_sticker`、`delete_character_sticker`。伊甸园 App 与 QQ 共用当前行动角色的 Core 表情包库，无额外数据库迁移；尘世未连接 Core，不提供这些工具。子任务不能获得这些角色工具。

App 默认提供查询与发送，收藏/删除通过工具发现加载；技能说明与工具加载沿用独立生命周期。QQ 私聊直接提供四个工具，群聊提供查询、收藏和发送；群聊不提供删除。保存来源支持本轮图片附件 `blobId` 或 HTTP(S) 图片链接 `imageUrl`，二选一，模型不需要搬运 Base64。填写名称、描述、情绪、意图和检索别名；名称、情绪、意图与 Core 的 64 字符字段限制对齐。可按 ID、名称或唯一别名发送，重复别名要求明确选择 ID。

## 链路、状态和边界

- `packages/api/src/character-stickers.ts` 定义公共输入与业务结果；`Server/src/modules/stickers/` 分别负责目录选择、图片读取、工具用例和投递。模型提示集中在 `model-prompts`。
- `MonBindingService.characterContext` 使用宿主行动助手选择角色，并复用当前会话已验证的 Core 连接。多角色会话没有行动角色时拒绝猜测。审批后、读完图片后、QQ 能力查询后再次复核角色与连接；同一账号的正常服务令牌续期不会误判为换绑，浏览器重绑仍使旧操作失效。
- 收藏使用 Core 的 multipart 创建接口，发送 App 时持久化 `character.sticker.sent` 及结构化 `part`，复用现有前端图片投影；删除接受 Core 的 204 空响应。没有引入对归档运行时的依赖。
- 图片支持 PNG/JPEG/GIF/WebP，最多 10 MiB，校验 MIME 和文件签名。附件只允许当前运行输入已接受的图片；网络下载无 Core 凭证、不跟随重定向、有超时及流式大小限制。GIF 无重编码。
- QQ 的目标来自持久会话映射，私聊固定当前联系人，群聊固定本群。群收藏和发送必须已有 `allow_actions`；写入、读取与外发均走相应审批，不继承 App 授权。Core 继续校验群准入和目标权限。
- 原 QQ 图片消息只接受公网 URL，不能满足本地 Core 的图片地址。Core/BotCore 动作目录同步增加 `send_private_sticker`、`send_group_sticker`，Agent 下载已选图片并传输有界 Base64，BotCore 仅构造固定 OneBot 图片消息。复用同目标串行队列，要求有效消息回执，缺失回执保持未知且不自动重试。
- Core 签名读取只为 `/api/devices/qq_bot/actions/execute/` 放宽到有界的 16 MiB；其他路由保留原正文限制。BotCore 专用 Core WebSocket 的接收上限为 16 MiB，以容纳 10 MiB 图片编码和封装。
- 模型结果只含表情包业务字段与 `success/failed/unknown`，原 QQ 回执留在工具审计。通用结果目录同时登记恢复投影，下一轮和旧历史恢复不会把平台消息号、请求号或图片编码带入模型。成功只表示 App 事件落库或 QQ 接口确认，不代表已读；失败或未知不发布已发送事件。

## 使用与生效

更新并重启 Agent、Core、QQBot 后使用；本次未重启已有在线进程、提交推送或发布。QQ 可发图片并说“把这张图存成开心表情包”，再说“发个开心的表情包”。群图片沿用现有的引用图片/文件消息并 @智能体的附件入口，且收藏/发送需要开启群操作。图片按自定义图片消息发送，不写入 QQ 账号本身的收藏表情列表。
