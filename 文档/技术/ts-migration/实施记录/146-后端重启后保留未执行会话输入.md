# 146 后端重启后保留未执行会话输入

日期：2026-09-26

## 问题

实施记录 138 的停止生成修复只处理用户主动停止时的取消顺序与执行状态；实施记录 145 的真实复验确认：后端进程重启后，原本排队且尚未执行的普通会话输入仍会自动执行。运行中的输入则已被标为 `interrupted`，其后排队输入被标为 `held`。因此之前没有修复用户指出的“重启后会话继续执行”。

## 改动

- 启动恢复时，将尚未开始的普通会话输入从 `queued` 改为 `held`，保留原文、附件快照与事件；不再由 `resumePending()` 自动执行。
- `held` 输入可通过现有恢复列表查看、核对并明确处置。需要继续时，用户先确认停止原输入，再显式重投。原输入不会因为重启或新消息而自行释放。
- 带有效 `job` 元数据的已派发任务输入仍交给对应任务调度器恢复；运行中输入和同会话后续输入保留原有中断/待核对规则。

## 验证

- 临时目录中真实关闭并重启 Server：旧排队输入变为 `held`，模型请求数为 0；明确提交的新消息完成，旧输入仍为 `held`。
- 附件快照恢复测试：重启后不自动执行；经核对及显式重投后，模型收到原图片。
- 持久队列测试：普通输入变为 `held`，任务输入仍为 `queued`；重复恢复结果稳定。
- 相关服务端测试共 11 项通过，`npm run typecheck:server` 通过。未修改或使用真实用户数据库，尚未验证 Windows 已安装运行包。
