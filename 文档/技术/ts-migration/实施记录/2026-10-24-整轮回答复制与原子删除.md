# 整轮回答复制与原子删除

后续发现独立 character.sticker.sent 未纳入原历史页和整组删除选择，已在[表情历史恢复与独立消息](2026-10-25-表情历史恢复与独立消息.md)补齐，包含旧组 tombstone 的兼容隐藏。本文保留本轮原验收记录。

## 问题与结果

同一回答的思考、工具、文字和表情可能保存为多条 assistant 消息。旧界面合并了头像和姓名，每条消息却仍独立生成复制、删除按钮，操作范围与可见回答不一致。

现在按连续的同一回合、同一角色分组，只在末尾保留一组按钮。当前组仍在生成时隐藏阶段性按钮；其他已完成回答仍可复制，执行期间继续禁止删除。耗时取组内累计耗时最大值，不相加重复计算。不同用户输入、角色、回合、压缩卡和命令保留边界。

复制按顺序汇总整组正文，保留 Markdown 和缩进，不复制思考、工具参数及回执。表情可作为回答结尾，按钮仍属于整组；已知只有图片且无正文时复制禁用。点击复制由服务端读取完整分组，支持历史分页未加载的开头，不会静默复制局部文字。读取失败显示错误，账号／世界切换或组件卸载后不写剪贴板。

删除确认说明覆盖本组全部思考、工具过程和表情图片；条数注明是当前已显示消息数。聊天历史与模型上下文一起删除全部成员及配对工具结果。用户输入、其他回答和执行审计保留，已执行副作用不会撤销；沿用原有摘要失效及迟到消息保护，防止内容复活。

## 实现与协议

- 前端 reply-action-groups 汇总组末操作信息，MessageBubble 仅在 single/last 位置挂载 MessageFooter；原有思考、工具和图片组件继续显示。reducer 以服务端 turnID 回填缺省 runID，防止丢失真实回合边界；压缩记录单独分组。
- 新 RPC message.reply.read 接收 sessionId/messageId，返回完整持久分组的 messageIds 与正文，不依赖客户端页大小。
- message.delete 增加可选 scope=reply，省略时保留原单条语义。新前端明确请求整组，旧 Server 拒绝新参数时不会静默降级为局部删除。
- Server 历史查询按可见连续消息选择分组，保持回合／角色／用户／压缩边界，忽略隐藏交接与工具回执；兼容旧空 turn_id。
- 删除在既有空闲锁、账号和世界所有权检查内执行，一个事务写入全部 tombstone 并处理上下文，提交后才广播。任意阶段失败全部回滚；同组 tombstone 使用 replyGroupId 关联，重试任一已删成员返回原组 ID，不重复写入或扩散邻组。
- 前端使用回执完整 ID 列表更新，广播沿用逐消息 message.deleted，既有永久删除保护继续阻止迟到历史复活。协议来源在 packages/api，legacy-wire 类型及生成客户端已同步，没有数据库迁移。
