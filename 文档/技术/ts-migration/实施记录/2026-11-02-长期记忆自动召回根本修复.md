# 长期记忆自动召回根本修复

## 范围与行为

所属模块：Core Recall、Agent memories／logging、Windows/Linux 便携打包。输入为当前账号／行动角色可读取的本地记忆候选与本轮查询；输出仍为阈值以上的有限相关记忆。记忆持久化归 Agent repository，模型解析／推理归 Core，不新增会话状态或跨安装模型回退。

原自动召回依赖 Core `/api/agent/memories/retrieve/`，其默认 `Resources/Models` 路径与便携包 `Data/Os/Models` 不一致。已统一 Core 共享配置解析，保留显式覆盖与独立 Core 历史布局，并在缺件或配置错误时明确失败。Agent 主动文本检索不受这条推理链路影响。

自动召回补齐开始、完成、故障和取消诊断，记录角色、数量、耗时与受限错误类别；无关查询为空，故障仅影响本次调用，下一轮重新尝试。提示保留主动检索能力，不能把召回故障描述成所有记忆能力失效。查询、记忆正文、凭据和任意异常原文不进入新增诊断。

新 Core 提供先于密钥／Django／迁移的只读模型检查。Windows/Linux 组装必须从候选自身执行真实 CPU ONNX 推理，记录随包模型文件大小和 SHA-256；Windows 审计复核记录。旧 Core 缺少该入口时先拒绝，不调用可能按正常启动处理未知参数的旧二进制。

## 实际验证

在本机 Core 自身虚拟环境和 Node 下执行以下检查，全部使用临时夹具或公开模型，不读取真实用户数据库：

- Core 路径、只读模型检查、检索规则和冻结入口分派：23 项通过。命令为 `python -B -m unittest`，模块包括 `Recall.tests.test_model_resource`、`test_model_check`、`test_retrieval` 及 `Script.Build.windows.tests.test_portable_entry.MemoryModelDiagnosticDispatchTests`。
- Core `Application/Dependencies/ServiceProvider/Recall/tests/run_vector_contracts.py`：11 项通过，包含真实 DRF／内存 ORM／本地 ONNX、搬迁便携布局、权限、过期、配置错误和诊断隐私。
- Agent `node --import tsx --test --test-timeout=60000`：新增 `tests/regression/memories/recall-diagnostics.test.ts`、既有 `recall-policy.test.ts` 共 7 项；集成 `vector-retrieval.test.ts`、`memory-recall.test.ts`、`memory-tools.test.ts`、`unit/logging/format-record.test.ts` 共 12 项通过。实际 HTTP 结果与独立 Node 模型向量一致，录制会话请求中只加入相关记忆。
- 根 `Script/portable/test_memory_retrieval.py` 4 项、Windows 既有组装 8 项和候选审计 5 项通过。覆盖旧 Core 拒绝、候选环境隔离、证明缺失和模型被替换等情况。
- Agent 服务端类型检查通过；架构扫描 1401 个文件，0 错误、30 个现有警告。

自动用例去重共 70 项。Windows 冻结诊断完成实际入口、本地 ONNX 推理、中文／空格路径搬迁、缺件失败和无密钥／数据库创建检查，完整临时程序副本已清理。范围与结果见根 `.release/current/Agent/memory-frozen-verification.json`；它使用实际只读入口和记忆模块，不是完整客户 Core 发行构建。完整记录为 `memory-retrieval-verification.json`。Linux 平台命令与布局有契约覆盖，本轮不宣称实体 Linux 全包验收。

首次较广回归的临时 Python 子进程退出等待与 Windows 日志句柄清理问题已修正，并复验通过。冻结验证发现模型检查的父包提前加载服务商配置、要求密钥，已改为保留公开 API 的按需导出；新增冷启动导入检查禁止加载 Config／Django／服务商核心。临时脚本的路径编码、重复执行和异常输出解码问题也已修正，最终冻结检查通过。
