# 失效会话助手恢复与模型错误隔离

日期：2026-09-12

## 问题

Mon Core 更换或恢复数据库后，Eden Agent 的历史会话仍可能引用已不存在的助手 ID。模型目录读取原先只返回 `Mon request failed (404)`；启动恢复又在历史消息加载前刷新模型，导致单个旧会话的 404 被当成全局运行错误，页面看起来像空白会话。

新会话创建后的模型绑定失败也会被前端吞掉，随后仍发送首条消息，最终只显示 `No model configured for this session`，并留下没有输入和模型绑定的空会话。

## 修复

- 模型目录先独立读取会话助手。该资源返回 404 时，报告“会话助手已不在 Mon Core 中”，不再丢失资源身份。
- 历史消息加载不再依赖模型目录刷新成功；模型错误按会话保存，不污染 WebSocket 连接状态或其他会话。
- 聊天错误卡提供“重新选择助手”入口，使用现有参与者更新与模型绑定链路完成恢复。
- 会话指定的助手不在当前 Core 名册时，不再悄悄显示另一个默认助手；界面继续使用持久参与者快照展示原会话名称和头像。
- 单会话切换页以持久会话助手 ID 判断是否已经选中。多人选择会剔除已从 Core 删除的 ID，避免保存无效名册。
- 新会话必须先完成模型绑定才发送首条消息。绑定失败时删除尚无内容的会话空壳并返回原始错误。

## 验证

- 服务端类型检查通过。
- 前端类型检查通过。
- 服务端模型目录专项 3 项通过；前端助手身份、新会话绑定、模型可用性和语音恢复相关专项 14 项通过。
- 真实 Mon Core 联调：会话助手 21 已删除时返回可操作中文错误；助手 10 可成功建立会话模型绑定，`model.read.available=true`；临时验收会话随后删除。
- 清理一条由旧缺陷产生、没有输入且没有模型绑定的空会话；另一条已通过界面重新绑定为助手 10。

包含历史消息且已有模型快照的助手 21 会话继续保留原身份和内容，由用户打开后按需重新绑定，不批量改写为其他角色。
