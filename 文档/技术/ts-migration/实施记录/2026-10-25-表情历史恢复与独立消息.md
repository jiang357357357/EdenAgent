# 表情历史恢复与独立消息

## 现象和核对

用户报告以前发出的表情，重新打开会话后消失，但工具过程和文字仍在。

只读检查截图会话数据库：表情发送事件和图片地址仍存在；单独读取原图返回 HTTP 200、image/jpeg，JPEG 文件头完整。没有补写真实消息、重新发送表情或把用户数据库作为测试夹具。操作证据在本地忽略目录的 audit.json，不在本文记录会话标识或图片地址。

原因有两处：SessionEvents.messages 只读取 agent.message_end，漏掉独立持久化的 character.sticker.sent；实时投影则把表情附着到活动消息或临时 shell，重新加载不能稳定重建同一消息。之前前端已有“历史表情分支”，但实际历史接口没有返回该事件，因此未覆盖真实读取链路。

## 修复

- 历史分页同时读取普通消息和表情发送事件，表情事件 ID 可作游标，保留原始时序、页大小、所有权及删除过滤。旧数据无需迁移、重发或补写。
- 前端 sticker-message 将表情发送事件投影为独立、已完成的 assistant 消息。消息 ID 固定为原事件 ID，part ID 固定为该事件的 sticker 引用，实时与历史使用同一个投影。不再依赖其他角色的活动消息、临时 shell 或当前页是否包含前面的文字。
- 保留原持久图片 URL、名称、描述及角色身份，按原有图片组件显示。多角色交错、表情独占一页、重复事件、离开重开和分页补载均保持身份一致，不生成重复图片。
- 整组查询及删除纳入独立表情消息，支持从表情末尾锚定整组；单独删除也可使用表情事件 ID。删除后原始审计保留，历史页不再返回该记录，迟到更新继续受前端删除保护。
- 新发送事件带 presentation=standalone.v1。旧版整组删除曾只记录普通消息 tombstone，历史查询按同角色最近的原消息及 replyGroupId 隐藏相关旧表情侧事件，避免扩大历史查询后复活已删除的表情；不误伤另一角色或未来独立发送。
- 模型重试清理仅针对模型回答，不删除已经发送的独立表情；没有把图片二进制或真实图片内容重新灌入模型上下文。

涉及 Server 的 stickers/delivery、sessions/session-events、message-deletion、history/reply-group 与 message-visibility，以及 Web 的 sticker-message、rpc-transport 和 agent-client。没有数据库迁移、新 RPC 或协议生成变更。

## 生效与限制

源码和构建已更新，历史读取修复需要正常重载 Agent Server，并使用更新后的 Web 客户端重新打开会话。原图无需重发，本轮没有强停整组在线开发服务、修改真实聊天、修改图片文件或发布制品。原图原先已被外部删除的情况不属于本次恢复保证；截图对应原文件已实际确认可访问。
