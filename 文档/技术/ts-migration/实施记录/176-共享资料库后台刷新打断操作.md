# 共享资料库后台刷新打断操作

日期：2026-10-06。用户反馈：共享资料库页面隔几十秒像被强制刷新一次。

## 原因与复现

`useSharedWorkspace` 每五秒调用 `owner.refresh(true)`，与页面手动刷新共用路径。`SharedWorkspaceStateOwner.refresh` 在详细读取前设置 `loading: true`；页面绑定表单将 `loading` 合入 `busy`，因此自动读取也会禁用输入框、资料库下拉、目录按钮和确认勾选，并让头部显示“正在刷新”。网络响应慢时，影响更明显。

在隔离 React DOM 中模拟定时触发和延迟状态响应，修复前断言 `background polling must not disable a focused form` 失败，实际 `input.disabled === true`。这是已复现的定时读取交互问题；未将其认定为浏览器导航重载，也未观测真实桌面窗口的页面重载事件。

## 修复

- 状态所有者增加前台/后台读取模式。定时器使用后台模式，有旧快照时不进入全页加载或禁用表单；成功响应仍更新真实服务状态。
- 私有读取计数防止慢读取未完成时再次启动定时请求；主动操作、前台读取期间也跳过自动读取。
- 首次读取与用户手动点击刷新保留原加载反馈。手动刷新或用户操作仍会使更早的背景响应失效，账号、世界和目录改变后的迟到结果继续丢弃。
- 没有重建页面、改写输入、滚动到顶部或自动清除共享确认。未更改 RPC、DLC 启用状态、同步算法及服务权限。

执行工作区临时脚本 `node .run/shared-workspace-page-check.mjs`，通过已安装的 Vite/React 与 ConfigAppReact JSDOM 挂载实际入口和页面，模拟内存传输及定时器。延迟读取开始时输入框、下拉、确认勾选和绑定按钮保持可用；后续连续触发 12 次五秒定时回调，名称、资料库、确认、焦点、滚动位置和设备展开状态保持，未出现自动“正在刷新”。原页面导航、同步/暂停、目录切换和账号隔离交互也通过。
