# 76 工具暴露与技能阅读解耦

日期：2026-09-14。按用户要求修正实施记录 75 中的技能调用门槛。

## 行为与状态

- 工具注册、模型接口暴露、技能阅读记录独立。技能代码工具也可通过 `list_tools` / `load_tools` 获取，不要求先执行 `load_skill`。
- `load_skill` 返回操作说明，并把关联工具保存为独立工具选择，方便随后使用；同一工具不会因来源技能数量而重复暴露。
- `unload_skill` 只停用技能记录，不移除工具。`unload_tools` 撤销工具接口暴露，即使技能记录仍启用也不自动恢复。默认基础工具仍由场景决定。
- 角色预加载首次保存技能及独立工具选择；之后显式卸载工具或技能不会被每轮预加载重新打开。
- 工具更新可单独重新发现和加载，不要求更新技能阅读记录。技能阅读记录只根据自身内容、启用状态、工作区和场景判断有效性。
- 直接执行代码工具不要求其所属技能的其他工作流依赖全部可用；仍验证安装启用状态、场景、快照版本、最终目标权限、参数和执行审批。

状态归属仍为当前世界数据库中的会话与行动角色。扩展工具的模型接口按需暴露，不将完整注册表塞入每次模型请求。历史里的技能正文不会因停用记录而删除；持久加载标记也不证明压缩后上下文仍保留正文。

## 数据兼容与失败行为

schema 116 将 schema 115 中启用技能的工具绑定转为独立工具选择，保留原始版本和会话工作区。原先手动卸载但仍由技能提供的工具保留暴露；已有启用的独立选择不覆盖。共享依赖优先采用最近的技能记录。恢复后仍按当前注册表核对，旧版本不自动升级到新版本。

加载仍先验证全部请求和容量，再事务保存状态和事件。工具未暴露、被策略禁止或审批等待期间版本/暴露状态变化时拒绝执行。卸载技能说明本身不会撤销已申请的工具执行；撤销工具暴露或拒绝审批仍可阻止执行。
