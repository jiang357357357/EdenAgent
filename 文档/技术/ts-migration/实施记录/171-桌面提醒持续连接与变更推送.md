# 桌面提醒持续连接与变更推送

日期：2026-10-06。模块：桌面提醒投递、主进程 RPC 生命周期、WebSocket 提醒事件。

## 问题与修复

原桌面提醒每五秒读取两个世界的列表，`createRealmRpc` 在每次请求中新建 WebSocket、认证、执行请求后关闭。修复前的真实 WebSocket 回归中，三次连续/并发查询实际完成三次初始化，单连接复用断言失败。前一项可选共享资料库修复消除了不可用 DLC 的错误恢复；本次移除造成重复初始化的提醒轮询链路。

- `realm-rpc.cjs` 按世界保存连接及订阅，复用正在初始化的连接；Core 账号、能力令牌或服务地址变化时关闭旧连接。尘世不读取或发送 Core 凭据。
- `realm-rpc-connection.cjs` 持有单条连接、初始化承诺、独立请求 ID 和等待表。响应可乱序；取消只影响对应请求。连接失败/超时拒绝待处理请求并通知服务；显示/关闭等未确认操作不自动重发。
- `reminder-service.cjs` 为两个世界分别维护刷新状态。启动读列表，健康空闲期间没有定时列表读取；收到推送立即刷新，读取期间的推送合并为后续刷新。断线或读取失败按五秒重试，重连重新读取持久队列。关闭确认后立即推进下一条提醒；窗口加载失败延迟重试，避免连续打开。
- 账号切换递增投递版本、取消伊甸园请求、销毁旧窗口及连接；旧通知/回执无法操作新账号，尘世连接和窗口独立保留。退出时解除订阅、计时器、请求及连接。
- `packages/api` 定义 `eventMode: reminders` 和 `desktop.reminder.changed` 通知。模式只能用于无会话游标的控制连接；生成浏览器客户端后，其通道选项使用契约中的类型。
- Server 在提醒创建、显示、关闭的事务持久事件发布后发送已认证的列表失效通知，内容只有 `runtimeOrigin`。专用 notifier 不调用会话事件范围补发，避免两个提醒事件之间的对话流进入提醒连接。30 秒账号认证刷新与失败关闭保持生效。

状态归属：Electron 主进程持有连接、账号投递版本和窗口；Server 仓库持有提醒和持久事件；API 包持有协议定义。连接内的能力令牌/Core 凭据不进入提醒渲染进程或通知。

- 空闲时间超过配置的失败重试间隔后，两个世界仍各一次初始化和一次列表读取。
- 生成、显示、关闭提醒即时推送；显示后窗口保留，关闭后移除。
- 账号 B 的事件不通知账号 A；切换后读取 B 队列，旧账号回执拒绝，尘世不重连。
- 本地连接丢失期间持久化新提醒，重连补读并替换已经关闭的旧提醒。
- 原始 WebSocket 消息只有提醒变更元数据，对话流夹在提醒事件之间也不进入连接。
- 六次真实提醒列表读取复用一次连接/认证，不恢复不可用的共享资料库，也无原恢复警告。
