# QQ 能力工具与授权群智能体

日期：2026-10-03。所属模块：Mon、QQ channel、会话能力、权限、记忆作用域与 Core QQ Agent 适配。

## 已实现

- Agent 真实运行时登记 `list_qq_capabilities`、`list_qq_events`、`read_qq_action`、`execute_qq_action`。概览与指定动作的完整 JSON schema 均从 Core allowlist 获取，保留二选一约束、桥接字段和不可用原因；没有静态复制允许动作清单。说说发布和私聊／群历史查询使用相同发现和执行路径。
- 读写分工具，权限服务在网络操作之前记录和处理审批；Core 再次验证当前身份、动作、参数、读写分类与作用域。QQ 模型不能提供操作者身份或另选机器人；身份来自持久渠道映射。应用会话使用自己的 Core 连接及明确的机器人 ID。HTTP 超时为 130 秒，未知写入结果不自动重试。
- 私聊审批优先显示动作、机器人及来源／目标 ID，再截断长内容。内嵌图片只显示近似字节数，不把 Base64 正文作为审批内容。
- 群 Agent 默认关闭，机器人 owner 需显式启用目标群的 `group_agent` 规则。群内仍要求 @／关键词触发、真实发言人的本机器人个人超级管理员身份，以及当前个人和群准入。普通群聊天模式保留。群 Agent 当前仅接收文字与 @／回复引用，不接收文件或图片附件。
- `qq-group-turn.v1` 将机器人、群号、真实操作者和 `allow_actions` 通过已有签名 QQ 通道传递。持久 `qq_group_sessions` 按机器人、群、操作者隔离，绑定角色改变时创建新会话；不复用私聊会话。该表由公共数据库迁移建立，不依赖 QQ bridge 构造。
- 群模型只获得三个能力发现／读取／执行工具，不获得事件全集、宿主文件、终端或私聊工具。仅开放当前群的 `target=group` 动作，强制当前群号；修改另需 owner 明确启用 `allow_actions`。`PermissionService` 记录授权决策，群会话不继承应用或私聊接管许可，也不把待审批请求发到群内。
- 群会话不召回或写入 owner 的角色记忆，也不投影到 owner 的 Core 私聊记录。模型提示明确公开群环境。状态接口只提供最终文本，不返回工具、审批、文件或内部失败详情；跳过工具调用结束的空消息查找有效最终文本。Core 群进度为固定提示，最终文字／卡片带明确群目标；BotCore 群图片投递由对应项目实现。
- Core 角色绑定实际变化后通过 `transaction.on_commit` 调度显式 opt-in 的资料同步；同步执行、重新授权与串行控制由 Core 的 `napcat_profile` 负责。

## 状态与失败边界

会话输入、操作者映射、群动作许可快照归 Agent 数据库；群开关、超级管理员和准入事实归 Core，并在每次动作执行时重新验证。群输入接受前及最终结果返回前也重新核验权限。被撤销或越过作用域时拒绝执行，不借 owner 身份回退。群公开回复不包含工具审批和私有错误详情。

群能力按 `target=group` 筛选。因此群历史查询可使用，空间发布等账号动作、好友动作、全机器人事件、`target=none` 的卡片桥接等不从群 Agent 开放；可通过获准的私聊或应用渠道执行。群工具写入依靠 owner 的明确群规则授权，不提供群内互动审批。
