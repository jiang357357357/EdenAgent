# 定时投递与可恢复压缩

状态：源码实现及本地验证完成，未发布客户包。产品版本保持 1.11.8。

## 现场问题与范围

客户机报告指出：备忘到期只提交会话任务，任务的文本结果缺少 QQ 主动投递；超长历史的压缩超过 32 次模型请求后失败，已生成的中间摘要没有保存。

本次修改 Agent 共享运行时、Server、前端和 Core 的进度回传。QQBot 使用现有签名动作通道与 OneBot 文字消息能力。客户机的两份 `main.mjs` 由同一套源码构建，后续交付无需重新手工追加提示词。

## 定时提醒（根据用户确认的自主通信方案修订）

- 到期作业先保存收件箱及持久决策记录，再通过原角色会话提交持久输入。宿主不拼接固定提醒文案，不直接代发 QQ，不限制来源为 QQ 或 App 的角色只能使用原渠道。
- 角色根据当前上下文、工具目录、接收者信息和现有授权，自主选择 QQ、邮件、设备或 App 通知并组织表达。QQ 群聊与私聊均可使用这些内置通信工具，每个工具继续执行原审批、账号及目标校验。
- 新增可选的 `delivery.channel`：默认为 `auto`，只有用户明确指定时才保存 `qq/email/device/app`。创建、修改、模型工具与前端完整传递该字段；普通 metadata 不能覆盖它。前端新提醒关联当前聊天；没有关联角色时明确提示，不将无人负责的提醒伪装为已投递。
- `memo_channel_deliveries` 保存决策输入及原备忘快照，`memo_delivery_effects` 保存经过实际宿主工具调用的通信回执。仅在角色回合结束后根据回执结算，不按模型文字或 `input.completed` 推断已送达。
- QQ 需有效消息标识，邮件需 Core 接受；设备排队后继续查询原命令，直到设备确认执行成功；App 通知需实际显示确认。单纯会话文字、收件箱记录、桌面待显示和设备排队不推进日期。
- 明确拒绝后角色可选择其他已授权渠道；已有接受、执行中、排队或未知的通信时阻止重复通知。发送结果未知不会自动重发，重启继续等待原输入／原命令或要求人工核对。
- 关闭聊天不取消已安排的提醒；只有关联作业正在执行的提醒回合可以在关闭会话中调用对应工具，不重新打开聊天，不放宽其他会话调用。审批期间修改提醒会在发送前阻止旧内容；发送期间的修改不会被旧回执覆盖。
- 没有模型时保留队列及可见错误等待绑定恢复；模型未使用通信工具则记为未投递失败，不自动改用宿主固定渠道。
- 历史补发需要明确确认；已送达提醒补发不重复推进日期。人工确认与作业／提醒状态同事务提交。旧固定发送中断的记录仍为未知，不因改用角色决策而自动重发。

`accepted` 表示该渠道已确认接受／执行相应通知，不表示用户已经阅读。QQ 文件等没有有效最终回执的调用不冒充送达。

## 历史压缩

- 手动和自动压缩共用按模型输入预算分段的处理。每次成功摘要后保存 `eden.compaction_progress.v1` 检查点，包含摘要、已处理游标、来源前缀校验和累计用量。
- 32 次作为协作让出执行机会的批次边界，长历史可以跨批处理；仍遵守运行时原有总模型请求预算。预算耗尽、取消、断线后可以从最近成功段继续。
- 恢复校验模型、指令和原始前缀；前缀被编辑时重新处理相应历史。字段排序及分段时间戳保持稳定。
- 达到可用预算后才提交正式压缩条目。原始消息及其 ID 保留；中间记录仅保存摘要和游标，避免反复复制剩余完整历史。
- 用户删除历史时，同步失效可能包含相关内容的中间摘要。临时交接材料继续排除在持久摘要之外。
- 前端展示一张可更新的进度卡和暂停提示。QQ 进度限定原会话与回合，Core 校验计数并按 30 秒节流，授权撤销后停止回传。

## 数据与升级

Agent SQLite 保留上一阶段的投递迁移，并追加自主通信迁移：备忘增加正式渠道选择，投递记录关联角色输入，新增通信效果账本。已有排队／检查中的默认 QQ 目标改为自动选择；已接受、未知或旧发送中的记录不被重新发送。不修改既有迁移，不推进产品版本和 QQ 协议版本。

回滚包含新 schema 的升级时，应按完整包升级事务同时处理对应数据库；旧程序不会忽略新 schema 强行打开。开发与验收使用独立测试库，未以真实用户数据库作为夹具，未向真实 QQ 发送验收消息。

## 验证记录

自主通信修订使用 Node 22.23.1，真实调度器、隔离运行时和本机 SSE 模型协议服务，实际调用本机 HTTP Core 测试端点。覆盖 QQ 来源改用邮件、群聊与私聊、App 外发、指定渠道、关闭会话、审批拒绝／变更、明确失败后改选渠道、丢失回执、防重复、设备／桌面最终确认、明确补发及旧发送恢复。

最新证据见工作区 `.run/logs/reminder-choice-validation.json` 与同目录 `reminder-choice-*` 日志。此前固定 QQ 方案的验证记录 `reminder-compaction-validation.json` 作为前一阶段记录保留，不代表当前自主通信方案的验收。压缩算法与其原有测试证据继续有效。

以上为本地协议联调和构建验收，没有向真实 QQ／邮箱发测试消息。产品版本保持 1.11.8，客户机当前安装尚未更新。
