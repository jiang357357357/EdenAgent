# 云端目录新建文件夹

老师指出云端目录浏览器缺少新建入口。现已在目录工具栏增加「新建文件夹」，输入单个名称后在当前云端父目录创建，成功后进入新目录。取消输入、创建失败重试及同名提示均在浏览器内处理，不自动建立资料库或共享；后续仍需选择目录并确认共享。取消整个建库流程保留已经创建的文件夹。

## 调用与边界

- 新增 `sharedWorkspace.cloudDirectory.create` RPC，携带原账号/会话/目录范围、主机 ID、父路径与名称，经 Server 转为已认证的 `POST directories/create`。
- 仅云端固定公钥匹配的管理员可以创建；本机调用检查发布 DLC。云主机用 `directoryCreate` 声明能力，旧版浏览服务不会收到可能不支持的创建请求，已有浏览与选择继续可用。
- 创建端使用现有共享路径规则验证单级名称及 UTF-8 长度，检查绝对父路径、真实目录身份和读写权限。禁止路径穿越、链接、系统及私有状态目录；父目录是运行状态祖先时仍允许创建独立的共享兄弟目录。
- 使用单次 `mkdir`，已有目录或文件返回冲突，不覆盖、合并或自动取代。目标位于另一资料库已共享的范围内时先拒绝，避免创建不能独立绑定的源目录。
- 新建输入有独立错误与忙碌状态，失败保留名称；创建中禁用浏览器导航。Escape 先取消新建输入，账号/父路径/主机变化丢弃旧响应。文件夹创建后仍有明确的未共享提示。

实现位于 `packages/shared-workspace/lan/source-directories.ts`、`directory-sources.ts`、共享 API/Server 路由、客户端封装、`CloudFolderCreate.tsx` 和现有目录选择器。资料库 schema、既有身份与文件版本不变。

## 验证

99 项服务回归（21 个递归发现文件）、61 项前端回归、11 项真实浏览器交互与 1 项独立编译云进程用例通过。覆盖真实加密环回调用创建物理文件夹、无自动建库、同名文件及内容保留、非管理员拒绝、非法名称/链接/私有路径、共享重叠、取消、失败重试、进入新目录及旧服务提示。编译主机实际处理目录创建并保留后续同步与重启历史验证。

Server/Web 类型、主题（344 文件）、架构（0 错误）、Server 与 Web 生产构建通过。浏览器同时复核原建库、配对、姿态、授权、接收与小屏流程；实际云服务器未作为测试夹具。

证据及候选位于根 `.release/shared-workspace-mkdir-20261030/`，截图在 `ui/`，Web 在 `web/`，在线注册前后记录为 `live-before.json` 与 `live-after.json`，总结果为 `RESULT.json`。

## 本机应用与交付

自动审核拒绝了强制结束开发进程的重启命令，该命令未执行。随后使用应用原有的 `.artifacts/desktop-quit.flag` 入口，由 Electron 调用 `app.quit()` 正常退出，再启动现有开发入口；两个后端和 Web 恢复健康，工作区身份及数据目录保持，新增 RPC 从未注册变为已注册。没有使用替代强杀命令或绕过审核。

新增接口已加载到本机开发服务。真实云主机需部署本次配套共享服务后才支持新建；本轮没有部署云主机、更新客户包、提交推送或推进正式版本 `1.11.7`。
