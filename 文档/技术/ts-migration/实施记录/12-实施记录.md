## B5：MCP 客户端与 stdio 帧协议（已编写，未测试）

- 核对归档 MCP manager 与当前插件清单：旧实现通过插件运行时组件声明 mcp_stdio/mcp_http，新清单已保留两类；后续接线继续复用包版本和组件权限，不另外建立无关配置域。
- integrations 新增 MCP 客户端：initialize/initialized、工具目录、资源目录、资源模板、tools/call、resources/read。支持协商已有 2024-11-05、2025-03-26、2025-06-18 协议，不宣称支持尚未实现的新协议能力。
- stdio 使用逐行 JSON-RPC，与官方 native worker 长度帧分离。限制单帧/待写队列 8 MiB、32 个并发请求；校验响应 ID 和结果/错误互斥，响应不匹配或流中断关闭通道。仅响应远端 ping，未声明 sampling/elicitation/roots 能力，也不会执行这类远端请求。
- 分页目录限制 32 页、1024 项、8 MiB，拒绝重复 cursor。保留工具 isError/structuredContent 及资源文本/Blob，不将远端业务失败改成成功。

- 本轮仅阅读本地源码并编写模块/文档；没有安装依赖、启动 MCP、联网、构建、类型检查或运行测试。此记录不代表 MCP 已可从产品使用。

## B5：MCP 包描述与隔离 stdio 启动（已编写，未测试）

- runtime-descriptors 从已验签/验完整性的包读取最多 64 KiB 描述，解析 MCP stdio command/args/cwd 与 HTTP URL；限制包内相对工作目录，拒绝 URL 内嵌凭据及非 HTTPS/loopback HTTP。
- InstalledPackageRepository.runtimePlan 绑定包 revision、组件启停和现有权限记录；stdio 必须获对应 process.execute/execute 命令授权，HTTP 必须获精确 network.connect/connect URL 授权，不因仅有包级启用而默认放行。
- execution 增加 stdio MCP 进程启动器：将包文件复制到临时快照、只读挂载，Node 使用固定宿主运行时，包内和沙箱 /usr/bin 程序可执行。保留无网络命名空间、内存/文件/FD 限额、干净环境、stderr 限额与进程组取消；包限 4096 文件/128 MiB。
- 新 mcp/stdio-runtime 连接隔离进程与协议客户端，握手前后复查授权，记录工具/资源目录变化通知，失败时终止并清理快照。
- 生命周期监管、模型工具/资源审批与操作账本、HTTP 通道仍待实现，因此包启用入口继续明确阻断 MCP 运行时激活，不能把底层模块编写算作产品完成。已有内联测试未改变，本轮未启动子进程、构建、测试或联网。

## B5：MCP Streamable HTTP 请求通道（已编写，未测试）

- 新增 HTTP channel 与独立 JSON/SSE 响应读取器，发送 JSON-RPC POST，支持 JSON 及 POST 响应内 SSE；限制请求/事件 8 MiB、响应累计 16 MiB、并发 32，处理远端通知和 ping，拒绝未声明的客户端能力请求。
- initialize 保存 MCP session ID 并核对后续标识，后续请求发送协商的 protocol header；HTTP 仅接收 2025-03-26/2025-06-18，stdio 仍兼容旧版本。客户端等待 initialized 通知获确认后才完成握手。
- 每次发送与处理响应复查授权，禁重定向、隐式 Cookie 和 URL 内嵌凭据。远端 RPC 错误保留错误码；连接失败、协议错误、取消或超时关闭通道并返回副作用可能未知，不自动重试。
- http-runtime 组装插件组件、客户端、宿主取消与退出信号，与 stdio 运行时提供相同监管结构。
- 独立 GET 通知流、DELETE 终止会话、断线恢复与鉴权扩展尚未实现；不能据当前 POST 支持宣称完整 MCP HTTP 完成。插件生命周期、审批工具、操作账本仍待接入，包启用阻断暂保留。本轮未发送 HTTP、构建或运行测试。

## B5：MCP 生命周期、模型入口与持久操作（已编写，未测试）

- 包版本 runtimePlan 通过后，启用入口不再统一拒绝 MCP；native_worker 包仍要求官方连接器生命周期。宿主启动 MCP 监管器，按组件启停、版本完整性和权限重查连接，最多八个运行时，初始化失败后十五秒退避，退出时关闭 stdio/HTTP。
- 模型增加 list_mcp_servers、list_mcp_capabilities、call_mcp_tool、read_mcp_resource。远端发现、调用与读取均经过会话审批；批准后复查版本及运行时实例，审批过程中重启不能沿用旧实例。
- 增加 mcp_operations 持久记录，远端调用前落 running，确认后 completed/failed，非确定错误记 unknown；宿主重启把未确认 running 转为 unknown。重复 operation ID 被拒绝，不自动重发。业务 isError 保留为 failed。
- mcp.status 与按会话分页的 mcp.operations 管理 RPC 已接入，不返回输入、结果或凭据；状态包含初始化错误。SQL 由 MCP 业务模块持有。
- 独立 HTTP 通知流、DELETE、精细恢复、动态远端工具别名、多模态结果及前端展示仍待补；当前接线不代表完整 MCP 通过验收。本轮仅编写源码和文档，未启动宿主/MCP、联网、构建或测试。

## B5：MCP 独立通知流与会话终止（已编写，未测试）

- HTTP 握手后接入独立 GET SSE，处理目录变化通知及 ping；服务器不支持 GET（405）时继续保留 POST 能力。流重连使用退避，仅重开 GET，不重发任何工具 POST。
- GET 携带当前 session/protocol header，拒绝会话标识变化、非 SSE 响应及未声明的客户端请求。等待周期和响应体有限额，重复失败关闭运行时交给生命周期恢复；不提供 Last-Event-ID 重放保证。
- SSE 读取增加 LF/CRLF/CR 换行处理。标准远端通知继续使运行时目录变化标志失效，动态目录工具接线后使用该标志。
- dispose 中取消本地请求、等待在途请求结束，并对仍获授权的既有远端 session 发送最多五秒的 DELETE；404/405 可关闭，其他失败仅记录清理未确认，不重试。失效/撤销端点不再接收清理流量，可能依赖服务器回收会话。
- HTTP 运行时自然退出也纳入 dispose，避免仅从活动列表删除而遗留本地请求。宿主退出已撤销自身授权时只做本地清理，不宣称每次退出都能确认远端 DELETE。
- 本轮未启动 GET、DELETE、真实 MCP 或测试/构建。精细事件续传、动态工具、多模态及其余完整迁移计划仍待推进。

## B5：MCP 动态工具目录与图片结果（已编写，未测试）

- 握手后加载工具目录，工具变更通知触发刷新；停用、退出和加载失败清理缓存。远端工具获得独立 runtime tool，使用远端 inputSchema 与描述，调用仍复用审批和持久操作账本。
- 名称按旧 mcp__plugin__component__tool 规则归一化，超过 64 字符时采用前缀和稳定摘要；拒绝跨组件及归一化碰撞。目录与包 revision 共同生成工具摘要，审批前后检查定义及运行时实例，旧闭包不能调用更新后的接口。
- 通用 call_mcp_tool 同样要求工具存在于当前目录。新工具在下一次会话工具工厂刷新时可见；当前尚未增加正在进行的模型请求内即时热替换。
- MCP 图片内容与嵌入资源/资源 Blob 可转为 pi 图片结果，支持 PNG/JPEG/GIF/WebP，校验 MIME 签名与标准 base64，限制八张/8 MiB；JSON 原结果和错误状态继续保留。音频播放、超限资源外置 Blob 仍待产品接线。
- 本轮只编写代码与文档，未连接 MCP、运行构建、类型检查或测试；远端 JSON Schema 复杂约束、本地多模态展示和动态更新行为仍待后续验收。
