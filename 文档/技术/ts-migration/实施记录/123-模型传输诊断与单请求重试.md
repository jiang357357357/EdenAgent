# 123 模型传输诊断与单请求重试

2026-09-20，用户要求记录 Connection error 的底层原因、增加自动重试，再完成一次真实自醒。

## 定位与实现

原宿主已有最多两次整轮重试，但工具开始执行后会禁用，避免重放外部副作用；pi 的单请求重试则设为 0。上次第九次请求失败发生在工具执行后，因而没有恢复。

新增请求级流包装：在尚未向上层输出内容时，对网络/临时服务错误最多重试两次，等待 500ms 和 1500ms。只重发同一模型上下文，不回退会话、不重新执行已完成工具；每次尝试都经过请求预算和持久化。耗尽后标记阻止旧整轮机制叠加重试。用户取消、鉴权/额度等非临时错误不自动重试；已经有部分输出且已有工具副作用的场景仍保守中断。无工具副作用的原部分流恢复机制保留。

使用 Node 公共 diagnostics_channel 与 AsyncLocalStorage 关联 fetch/undici 底层错误、HTTP 状态和模型请求，未修改全局 fetch、依赖制品或 pi 私有接口。agent.model_transport 持久化 operationId、requestId、attempt、模型、端点 origin、耗时、状态、stopReason、错误原因链；agent.model_request_retry / finished 记录退避和结果。model.response 同时保留错误文本。端点去掉路径/凭据/查询，原因链限制深度与长度，过滤密钥和认证信息，不记录请求头或正文。
